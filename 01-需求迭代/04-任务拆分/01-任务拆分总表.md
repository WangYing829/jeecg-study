## 1 拆分原则

| 原则 | 说明 |
|---|---|
| **一张卡只做一件事** | 跨模块的工作要拆开，否则 AI 会顺手做超范围的事 |
| **落点唯一** | 每张卡明确到包路径 / 目录 / 接口路径，不写「实现 XX 功能」 |
| **判据可判定** | 验收标准不许写「正常显示」「运行正常」 |
| **红线显式化** | 涉及练习、判分、家长端的任务，红线条款写进卡片正文，不只靠链接 |
| **先底座后内容** | V1 之前不得上线任何「内容型」模块——底座没稳就堆内容等于制造积灰 |
| **缺口先判读** | 依赖台账 §5.1 未判读缺口的卡，状态是 ⛔ 阻塞，不是 ⬜ |
| **先有归属再有数据** | 多用户场景下，**没有 `child_id` 就没有数据归属**——隔离卡必须排在学习行为卡之前 |

## 4 需求 → 任务 反查

要查某条需求归哪个任务，查机读矩阵更准：

```powershell
python 05-公共资源\2026103015-追溯矩阵生成.py
```

打开 `06-AI协作/01-任务台账/02-追溯矩阵.csv`，按 `需求编号` 筛。
**若某条需求在矩阵里显示「未覆盖」，说明它还没被任何任务认领**——要么补任务卡，要么在台账 §5.2 登记豁免。
