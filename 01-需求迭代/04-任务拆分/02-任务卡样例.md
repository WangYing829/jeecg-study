## 任务卡 `T-V0-01` 基座接管与单模块落地

| 字段 | 值 |
|---|---|
| 任务号 | `T-V0-01` |
| 所属阶段 | V0 地基 · 批次 0 |
| 需求编号 | —（基础设施任务，支撑全部 F-*） |
| 优先级 | P0 |
| 状态 | 🔵 待验证（模块骨架与库名改造已落地，待跑通启动） |
| 产出物 | `jeecg-module-study` 单模块（**不拆 api 模块**）；父 pom 注册；`jeecg-system-start` 依赖；四份 `application-*.yml` 指向 `jeecg-study` |
| 依赖 | —（**无前置，最先做**） |
| 预估 | 1–2 天 |

### 1 目标

后端能编译启动，连得上 `jeecg-study` 单库（平台表 + 业务表同库），且**全程没有 `@DS` 数据源切换**。

### 2 范围

| 含 | 不含 |
|---|---|
| 建**一个** Maven 模块 `jeecg-module-study` 并在父 pom 注册 | 任何业务表与业务逻辑 |
| `jeecg-system-start` 依赖新模块 | 建 `jeecg-module-study-api`（ADR-016 已关闭两模块方案） |
| 四份 `application-*.yml` 库名统一为 `jeecg-study` | 引入 `@DS("study")` 动态数据源（ADR-015 已取消） |
| MyBatis-Plus 扫描包覆盖 `org.jeecg.modules.study` | 实现 F-BASE-01…08 任何一条需求 |
| 启动自检：无扫描告警、无连接池告警 | 建业务表（属 T-V0-02） |

### 3 落点

| 类型 | 位置 |
|---|---|
| 后端 | `02-代码开发/05-源码/01-JeecgBoot基座/jeecg-boot/jeecg-boot-module/jeecg-module-study/` |
| 配置 | `02-代码开发/05-源码/01-JeecgBoot基座/jeecg-boot/jeecg-module-system/jeecg-system-start/src/main/resources/application-{dev,test,prod,docker}.yml` |
| 数据库 | 单库 `jeecg-study`（本卡只连库，不建表；建表属 T-V0-02） |

### 4 输入契约

- **照抄对象**：`<Boot>/jeecg-boot/jeecg-boot-module/jeecg-module-monitor/pom.xml`（模块结构与依赖写法）
- **官方规范**：`<Boot>/jeecg-boot/CLAUDE.md`（包结构域优先、实体注解、`Result<T>`、`update-begin/update-end` 痕迹）
- **本项目速查**：`../../../06-AI协作/04-知识库/01-JeecgBoot底座速查.md`（每条带 file:line 证据）
- 数据源配置格式：`<Boot>/jeecg-module-system/jeecg-system-start/src/main/resources/application-dev.yml`

### 5 验收判据

| # | 判据 | 验证方式 |
|---|---|---|
| 1 | `mvn -pl jeecg-module-study -am package` 成功 | 命令退出码 0 |
| 2 | 应用启动日志无 MyBatis-Plus 扫描告警 | 启动日志 |
| 3 | 应用连上 `jeecg-study` 且**能读到平台表**（如 `sys_user`） | 集成测试：临时表写入 + 读回 |
| 4 | **全仓搜不到任何 `@DS(` 用法** | `grep -r "@DS(" jeecg-boot/`（单库不需要） |
| 5 | `application-dev.yml` 里的口令**未被提交**（gitignore 生效） | `git check-ignore` |

### 6 红线检查

## 任务卡 `T-V0-10` 反搜题顺序约束

| 字段 | 值 |
|---|---|
| 任务号 | `T-V0-10` |
| 所属阶段 | V0 地基 · 批次 2 |
| 需求编号 | **F-BASE-06**（PRD V1.1 §5.6 已正式定义）· 红线 R-01 |
| 优先级 | P0 |
| 状态 | ⬜ 未开始（阻塞已解除） |
| 产出物 | `GET /practice/{type}/next` 响应不含答案字段；`GET /practice/{id}/explanation` 未作答时返回 4003；练习页答案区不渲染到 DOM |
| 依赖 | T-V0-02（表）、T-V0-09（判定层）、**T-V0-17（`child_id` 隔离）** |
| 预估 | 1 天 |

### 1 目标

**孩子在作答之前，页面上和接口响应里都不存在答案。**

### 2 范围

| 含 | 不含 |
|---|---|
| 取题接口响应字段裁剪 | 解析内容的生成逻辑（属 T-V0-09） |
| 未作答取解析返回 4003 | 家长端的申诉通道（属 T-V0-11） |
| 练习页答案区改为**条件渲染**（初始态不进入 DOM） | 答案区的视觉设计（按《产品设计规范》） |
| 5 个练习页的一致性 | 新增练习页 |
| 取题按当前孩子过滤 | 数据范围隔离的实现（属 T-V0-17） |

### 3 落点

| 类型 | 位置 |
|---|---|
| 后端 | `org.jeecg.modules.study.error.controller` · `org.jeecg.modules.study.error.service` |
| 前端 | `src/views/study/kid/` 练习页组件 |
| 接口 | `GET /api/v1/study/practice/{type}/next` · `GET /api/v1/study/practice/{id}/explanation` |
| 测试 | `03-测试验证/04-自动化测试/02-测试脚本/`（R01-1…R01-5） |

### 4 输入契约

- **参照实现**：`<Boot>/jeecg-boot-module/jeecg-module-monitor/.../MonitorAlarmModelController.java:34-47`（Controller 骨架）
- **响应契约**：《接口设计说明书》§3.2
- **错误码**：4003 = 未作答不允许取解析
- **判定来源字段**：`judgeSource`（枚举 `rule` / `rule+model`）
- **数据范围**：见《多用户改造契约》§3（越权返 4010）

### 5 验收判据

| # | 判据 | 验证方式 |
|---|---|---|
| 1 | 取题响应 JSON 的 key 集合不含 `answer` / `analysis` / `correctAnswer` / `solution` | 接口断言（R01-1） |
| 2 | 未作答调 `/explanation` 返回 **4003** | 接口断言（R01-2） |
| 3 | 练习页初始态解析容器**元素个数 = 0** | DOM 断言（R01-3）——**数个数，不是查可见性** |
| 4 | 5 个练习页全部满足判据 3 | 遍历断言（R01-4） |
| 5 | 学习端组件源码无 `v-show` / `display:none` 式答案隐藏 | 静态扫描（R01-5） |
| 6 | 孩子 A 取题不会拿到孩子 B 的题 | 接口断言（F-FAM-07，返 4010） |

### 6 红线检查

| 红线 | 触及 | 落点 |
|---|---|---|
| R-01 反搜题 | **是** | 本卡全部内容即为 R-01 的落地；实现方式必须满足 ADR-009（不渲染到 DOM，不是 `display:none`） |
| R-02 AI 只做解释层 | 否 | — |
| R-03 护眼硬指标 | 否 | — |
| R-04 不做公开比较 | 否 | — |

### 7 自检

- [ ] 判据 1–6 全部通过且断言脚本已入 `03-测试验证/04-自动化测试/02-测试脚本/`
- [ ] 红线断言规格 §4 已回填本卡的 5 条断言登记
- [ ] 追溯矩阵已重跑，`F-BASE-06` 状态为「已覆盖」
- [ ] 未改需求编号体系

### 8 备注

✅ **原阻塞已解除**：PRD V1.1 §5.6 已补 `F-BASE-06` 正式定义（并标注「与 R-01 同源」），台账缺口 G-01 已闭合，可直接开工。
