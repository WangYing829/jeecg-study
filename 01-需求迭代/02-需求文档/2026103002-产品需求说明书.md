## 核心结论速览

本节结论先行。每条结论后标注证据来源模块，完整竞品论证见 `01-需求迭代/01-竞品分析/20261030 学习助手模块竞品研究.html`。

### 1.1 定位不是「一个 App」，而是「一个家庭的学习操作系统」

竞品分析的第一条结论：头部市场（作业帮、小猿搜题、学而思、猿辅导）卷的是题库规模与教研厚度，面向的是千万级陌生用户；对一个家庭（哪怕是好几个孩子）是过剩的。本项目唯一的结构性差异不是内容更多，而是**六个模块共享同一份学情数据**——竞品中每个模块都是独立产品线，无法做到这一点。

**补全**：该结论被翻译成一条可验收的需求——任意两道来自不同模块的题目，必须能通过统一知识点 ID 互相引用。落地形态即第五章的五个共享底座组件。

### 1.2 最大空位在错题「复盘」，不在错题「录入」

所有竞品把拍照擦笔迹、自动归类、导出 PDF 做到了极致，供给端已过剩且免费化。真实用户反馈是「整理错题不如手写更能加深记忆」「举一反三的出题质量偶尔差强人意」。错题本 90% 的价值在**什么时候复习**和**错的到底是什么原因**，而工具只做到分类和导出。

**补全**：竞品分析给出了方向，本 PRD 把它落成四条可测的功能需求（F-WRG-01…04）与一条贯穿性的复习排期规则（当日 / +1 / +3 / +7，连续三次做对才移出）。

### 1.3 「母题过关斩将」全场只有洪恩思维与需求同构

洪恩思维有 185 道小学应用题母题，每题配「剖析讲解 + 子题变式练习」，官方表述即「一通百通，学会举一反三」。其余大厂给的是「题」不是「一类题的结构」。大厂缺的三样东西被明确点出：**没有母题抽象层**、**过关单位错了**（刷了 200 道 ≠ 这类题我会了）、**判对标准单一**（蒙对、跳步、真懂不分）。

**补全**：竞品分析给了五段式母题结构与三层变式，本 PRD 补上了过关判据的量化口径（变式全对 + 能口述关键关系）、错因二分前置打标点，以及母题到考纲坐标树的溯源要求。

### 1.4 英语语法有一条没人走的中间地带

查错工具（Grammarly 系）只报错不教规则，课程工具（British Council 系）讲规则但不落地且与国内教材语法点顺序完全不对应。中间那一段——给国内学生、按考纲、用孩子自己的句子讲语法——是空的。

**补全**：竞品分析提出「句子变形器 + 错误即入口」，本 PRD 补上考纲锚定（语法点挂考点树并标注中考题型）、与模块③共用语境库的复用约定、以及错句自动进统一错题池的链路。

### 1.5 语文写作的「鉴赏」与「积累」是两件事

竞品（笔神作文、稿好语文、语文天天读）交付的是可抄的句子与素材金句，平台自己的 FAQ 都写明「范文不建议直接抄袭照搬」。「看出一篇好作文为什么好」至今没有产品系统地做。

**补全**：竞品分析提出「拆解库 + 对照式批改」，本 PRD 补上六层拆解结构、批改只给最该改的三条的量化约束、防代写三步训练流（提纲不过关不许写初稿），以及与模块②共享错因标签的约定。

### 1.6 真正的约束不是「功能」，是「别把孩子养成伸手搜答案的人」

行业观察反复指出搜题依赖风险；艾瑞点名作业帮与学而思、猿辅导功能严重同质化。对自有工具，约束应当反过来设计。国家卫健委监测数据显示我国儿童青少年总体近视率已突破 52.7%，超 75% 的家庭无法完全依靠自身完成孩子全流程学习辅导。

**补全**：竞品分析提出四条红线，本 PRD 将其升级为**不可破红线**（第 4.3 节），并逐条给出可自动检测的判据与对应的设计约束条款。

## 产品定位与边界

### 2.1 一句话定义

> 一个家庭私有、面向多个孩子的学习操作系统：以统一学情底座为轴，用六个共享数据的功能模块替代六个互不相通的独立小应用，把「每个孩子学过什么」「错在哪」「什么时候再练」三件事连成闭环；家长只看自己关联的孩子，孩子只看自己。

### 2.2 应该做成什么样

| 方向 | 落地含义 | 关联需求 |
|------|----------|----------|
| 共享学情底座 | 统一的知识点 ID 体系，六个模块的题目、单词、语法点、作文段全部挂到同一棵树上 | F-BASE-03 |
| 统一错题池 | 所有模块的「做错」进同一个池子，带模块、学科、知识点、错因、复习排期 | F-BASE-04 |
| 统一复习调度 | 一条间隔重复队列管全部模块，跨模块共享同一排期 | F-BASE-05 |
| 家庭与成员 | 一个家庭下多个孩子、多个家长；孩子 PIN 登录、家长标准账号；学习数据按孩子隔离 | F-FAM-01…08 |
| 家长端只读 | 看报告、看趋势、留一句话，可切换看哪个孩子；不做辅导、不做排名、不做横向比较 | F-PAR-01…03、F-FAM-07 |
| 护眼优先 | 用眼时长统计、蓝光过滤、休息提醒是硬指标，不是营销词 | F-EYE-01…04 |

### 2.3 不应该做成什么样

| 禁止项 | 为什么禁止 | 替代做法 |
|--------|------------|----------|
| 搜题机 | 一拍照给答案会直接毁掉前五个模块的价值 | 题目先给母题思路 → 孩子作答 → 才允许看解析（F-BASE-06） |
| 资源仓库 | 学科网式「1200 万套资料」只会让孩子逛而不做 | 只建结构不收内容：地区考纲 → 学科 → 单元 → 考点（F-REG-01） |
| 素材金句库 | 导致所有作文雷同，且违背「鉴赏」初衷 | 给情境不给金句，强制填自己的经历（F-WRT-03） |
| 通用大模型堆砌 | 竞品评测指出通用模型只是把矛盾的训练数据重新生成心理学话术 | AI 只做解释层，判对错走确定性逻辑（F-BASE-07） |
| 公开社区 / 排行榜 | 家庭私有工具不需要社交压力，反而需要降低焦虑 | 家长端只看客观趋势与状态（F-PAR-03）；多家长之间也不得互相比对（R-04） |

### 2.4 形态决策与待验证项

竞品分析倾向**微信小程序**：低频使用、跨设备只求同步；APP 仅在需要离线答题或护眼大屏时再考虑。

**补全（本 PRD 新增）**：本系统以 JeecgBoot 为后端底座，先以 **Web 家长端 + 学习端（孩子端）页面** 形态落地，接口层保持 REST 无状态，为后续小程序 / APP 客户端预留。落地节奏见第 16 章。

| 待验证项 | 验证方式 | 影响范围 |
|----------|----------|----------|
| 是否需要家长端独立身份 | **已定**（原为待验证）：家长用底座标准账号、孩子用 PIN 独立登录，家长端是独立布局而非学习端内的「家长视图」 | F-PAR 全部、F-FAM-05 |
| 是否需要离线答题 | 观察孩子实际使用场景是否频繁断网；**V0 不做**离线与缓存（F-BASE-08） | F-BASE-08 缓存策略 |
| 教材版本变更频率 | 坐标树需版本化与失效标记 | F-REG-05 |

## 用户与使用场景

### 3.1 角色

本系统服务**多个家庭、多个孩子、多个家长**：家长↔孩子是多对多，详见第 12 章。仍**不做多租户、不做通用权限体系、不做数据埋点看板**；角色仅用于区分数据归属与可见范围。

| 角色 | 身份 | 可见范围 | 可写范围 |
|------|------|----------|----------|
| 学生（KID） | 每个孩子一个独立账号，PIN 登录 | 自己的全部学习内容与练习（仅自己的 child_id） | 练习作答、错因标注、错题录入 |
| 家长（PARENT） | 监护人，可有多位（妈妈 / 爸爸 / 长辈） | 关联孩子的学习报告、趋势、知识点掌握度、错因分布 | 仅「一句话反馈」与「提醒推送偏好」 |
| 管理员（ADMIN） | 底座 admin | 全部 | — |

### 3.2 核心场景

| 编号 | 场景 | 触发 | 期望结果 |
|------|------|------|----------|
| S-01 | 错题录入 | 孩子做完一张卷子拍照 | 自动擦除手写笔迹、归类到科目/考点、**必须选错因**、进入重做队列 |
| S-02 | 复习调度 | 每天首次进入 | 弹出当日应复习队列（错题 + 到期单词 + 语法错句 + 写作病句），一条队列 |
| S-03 | 背单词闯关 | 孩子打开背单词 | 教材单元 1:1 映射，过关有可见奖励，连续天数累计 |
| S-04 | 母题闯关 | 孩子进入数学模块 | 按考纲优先级排序的母题关卡，变式三层，答错回放关键关系追问 |
| S-05 | 语法纠错 | 孩子写完一句英语 | 标出错处，点击弹出最小讲解 + 同类例句 + 反例，立即改一次 |
| S-06 | 写作训练 | 孩子写完一篇作文 | 三步训练流给结构反馈；批改只给「与同题材佳作的差异清单」前三条 |
| S-07 | 家长查看 | 家长打开报告 | 切换到目标孩子，看到用眼时长、知识点掌握度、错因分布、连续天数；留一句话 |
| S-08 | 护眼干预 | 连续用眼达阈值 | 强制远眺提醒 + 蓝光过滤 + 记录用眼时长 |
| S-09 | 孩子登录 | 孩子打开学习端 | 输入家庭码 → 选自己的头像 → 输入 PIN → 进入只属于自己的学习页 |

### 3.3 关键用户旅程（主链路）

一次完整的「学习—出错—复盘—巩固」闭环：

1. 孩子在背单词模块背到课内第 3 单元，答错 2 个词（错因：词义混淆）→ 词条自动进入统一错题池。
2. 同一晚做数学母题闯关，第 7 关变式题错误（错因：审题偏差）→ 题目进入统一错题池，挂到「应用题 · 行程问题」考点。
3. 次日系统按间隔重复排出当日复习队列：**先母题变式，后单词**（依据是各内容的遗忘衰减与优先级）。
4. 变式做对 → 但「口述关键关系」未通过 → 补一道苏格拉底式追问，仍未通过则保留在队列。
5. 家长端当天在对应孩子的视角下看到「行程问题类连续 2 日出错」，留下一句话反馈，不给辅导建议。
6. 周末复盘报告显示：该考点掌握度仍低 → 坐标树把「应用题 · 行程问题」标记为薄弱，母题关卡排序自动前移。

**这条旅程是本系统的验收主线**：它同时穿过模块②③④、底座的错题池与复习调度、家长端报告。

## 需求拆解与优先级

### 4.1 需求来源与补全说明

下表把原始需求描述逐条拆成可验证的子问题，左两列**提取自竞品分析**（证据结论列为其原文判断），右两列是**本 PRD 的补全**——补的是可验证的判定标准与优先级。

| 需求要素 | 字面要求 | 可验证的子问题 | 证据结论（竞品分析） | 本 PRD 补全 |
|----------|----------|----------------|----------------------|--------------|
| 形态 | 小程序或 APP | 微信生态还是独立 APP？家长端要不要？ | 倾向小程序；APP 仅在需要离线答题/护眼大屏时再考虑 | 本期以 Web 双视图落地，接口无状态化，为小程序预留（F-BASE-08） |
| 使用者 | 自家小娃子 | 单人使用还是未来扩到 sibling？ | 单用户设计，可放弃多租户、权限体系、埋点看板 | 已改为**多家庭多用户**：仍不预留租户字段，但必须按 child_id 做数据隔离（N-05 改写、F-FAM-01…08） |
| 增量策略 | 逐步增量追加各类小工具 | 模块之间要不要共享数据？ | 必须共享，否则退化成拼盘 | 共享底座提升为 P0，排在所有业务模块之前（F-BASE-01…05） |
| 模块 ① | 学生地区与考纲 | 是资源库还是坐标系？ | 做成坐标系，只做地区→考纲→考点定位表 | 补四层坐标树结构 + 考点四属性 + 版本化失效（F-REG-01…05） |
| 模块 ② | 错题集与复盘练习 | 错题怎么进来？什么时候复习？ | 最大机会，竞品普遍只做收录不做复盘 | 补四件套（错因强制标签、重做队列、一题多变、统一入口）+ 排期规则（F-WRG-01…04） |
| 模块 ③ | 趣味高效背单词 | 课内课外要不要分成两条线？ | 分两条线，算法诉求相反 | 补课内/课外分线算法与「课内错词自动升级为课外优先复习项」的闭环（F-WRD-01…05） |
| 模块 ④ | 数学母题过关斩将 | 母题怎么定义？过关标准是什么？ | 机制稀缺，全场仅洪恩做到「母题+变式」 | 补母题五段结构、三层变式、过关判据量化口径、错因二分前置（F-MTH-01…05） |

### 4.2 优先级定义

| 级别 | 含义 | 判定标准 |
|------|------|----------|
| P0 | 缺失则系统不成立 | 家庭与成员最小闭环（F-FAM-01…07）+ 底座五组件 + 错题复盘四件套 + 反搜题红线 |
| P1 | 影响主链路可用性 | 护眼指标、家长端只读报告、考纲坐标树 |
| P2 | 增强体验，可延后 | 趣味化渲染、多端同步、统计看板美化 |

### 4.3 不可破红线（每阶段都要守住）

这四条来自竞品分析，本 PRD 将其升级为**设计约束 + 验收断言**，任一条被破，版本不予发布。

| 编号 | 红线 | 设计约束 | 可自动检测的判据 |
|------|------|----------|--------------------|
| R-01 | 反搜题 | 任何练习的答案入口必须排在「孩子先作答」与「先看母题思路」之后 | 练习页 DOM 中答案区域的触发条件必须依赖一次作答事件；未作答时答案区域不可见 |
| R-02 | AI 只做解释层 | 判对错走确定性逻辑（题干比对、规则引擎、题型规则）；AI 只负责讲解与追问；涉及分数必须有家长兜底通道 | 判对错接口的响应必须包含「判定来源」字段，取值非 `ai`；存在家长复核入口 |
| R-03 | 护眼是硬指标 | 用眼时长统计、蓝光过滤、定时休息提醒、每 15 分钟强制远眺提醒 | 连续用眼超过阈值时必须出现阻断式提醒；蓝光过滤开关状态可查询 |
| R-04 | 不做公开比较 | 家长端只看客观趋势与状态，不做同龄排名；**多家长场景下额外禁止家庭内比较**（「谁的孩子更…」「家长评分对比」），**禁止家长之间对比数据** | 全库不得存在「排名」「排行」「超过 X% 的同学」等字段与文案；家长 A 的响应中不得出现家长 B 的任何标识；全站文案无家庭内比较措辞 |

## 底座：五个共享组件

> 六个模块单独看都不难，难的是让它们共用一套数据。这五个组件必须**先于**任何业务模块落地。
>
> F-BASE-01…05 是共享组件本体；**F-BASE-06…08 是随本轮多用户改造补齐的三条底座约束**（分别与红线 R-01、R-02 同源，以及离线 / 缓存策略），不计入上述五组件。

### 5.1 F-BASE-01 全局上下文

**需求**：一次配置（省 + 学段 + 年级 + 教材版本），之后全局生效。

| 项 | 内容 |
|----|------|
| 输入 | 省级行政区、学段（小学/初中/高中）、年级、教材版本（人教/苏教/北师大/浙教/沪教/京教/鲁教） |
| 规则 | 教材版本是事实上的最小集（7 个版本），必须全支持；地区不作为筛选项，而是全局上下文变量 |
| 生效 | 修改后所有模块的默认取数范围同步切换；历史学习记录**不随切换而失效**，但标记「来自旧坐标」 |
| 验收 | 配置一次后，进入任一模块无需再次选择地区/年级/教材 |

**补全**：多用户改造后，全局上下文**按孩子隔离**——不同孩子的年级与教材版本可以不同，配置在孩子维度生效（F-FAM-07）；坐标树、题库、词库等内容表仍全局共享，不按孩子拆分。

### 5.2 F-BASE-02 坐标树

**需求**：地区考纲 → 学科 → 单元/章节 → 考点，四层坐标树；每个考点携带四属性。

| 考点属性 | 说明 | 来源 |
|----------|------|------|
| 题型 | 该考点的出题形式（如行程问题 → 应用题/画图题/列表题） | 竞品分析 4.1 |
| 分值权重 | 该考点在中考/期末的分值占比 | 竞品分析 4.1 |
| 常见错误类型 | 从真实错题反推，不预设 | 竞品分析 5.2（借鉴 A+ 错题本自定义错因） |
| 对应母题 ID | 挂载到模块④的母题 | 竞品分析 7.2 建议⑤ |

**补全**：坐标树必须**版本化**。地区考纲与教材版本会周期性调整（竞品分析 10.3 风险清单），节点需带 `version`、`effective_from`、`invalid_at` 三个字段；旧节点置为失效而非删除，历史记录仍可解析。

### 5.3 F-BASE-03 统一 ID 体系

**需求**：题目 / 单词 / 语法点 / 作文段 / 考点各有 ID，跨模块可互引。

| 实体 | ID 规则 | 示例 |
|------|---------|------|
| 考点 | `KPT-{学科码}-{序号}` | `KPT-MA-0417` |
| 题目 | `QST-{来源}-{年份}-{序号}` | `QST-SELF-2026-0088` |
| 母题 | `MTH-{学科码}-{序号}` | `MTH-MA-0123` |
| 单词 | `WRD-{字母}-{序号}` | `WRD-A-04512` |
| 语法点 | `GRP-{序号}` | `GRP-0088` |
| 作文段/拆解层 | `WRT-{层级码}-{序号}` | `WRT-HOOK-0031` |

**补全**：ID 一经分配**永久不变**，即使内容被修订也不回收（否则历史错题会指向不存在的对象）。所有跨模块引用只允许指向 ID，不允许复制内容。

### 5.4 F-BASE-04 统一错题池

**需求**：所有模块的「做错」进同一池，带模块、学科、知识点、错因、复习排期。

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 错题 ID | `ERR-{序号}` | 必填 |
| 来源模块 | 错题 / 背单词 / 母题 / 语法 / 写作 | 必填 |
| 关联内容 ID | 指向具体题目或词条或句子 | 必填 |
| 知识点 | 指向坐标树考点 | 必填 |
| 错因 | 见 F-WRG-01 五维 | **必填**（答完题必须答的一个问题） |
| 复习排期 | 下次复习日期 | 系统生成 |
| 当前掌握度 | 连续做对次数 / 状态机 | 系统维护 |

**补全**：错题池是**唯一**的错题存放处。各模块内部不得再建「我的错题」表，只能按条件从统一池查询。这是竞品做不到、也是本项目唯一结构性优势的落点。

### 5.5 F-BASE-05 统一复习调度

**需求**：一条间隔重复队列管全部模块。

**排期规则（补全）**：

| 阶段 | 间隔 | 移出条件 |
|------|------|----------|
| 首次答错 | 当天 | — |
| 第 1 次做对 | +1 天 | — |
| 第 2 次做对 | +3 天 | — |
| 第 3 次做对 | +7 天 | **连续三次做对即移出** |

> **移出阈值必须大于排期阶梯的第 3 档**：阈值若为 2，则第 3 次做对时立即移出，**+7 天这一档在业务上永远走不到**。
> 因此阈值取 3 —— 第 1 / 2 / 3 次做对依次给出 +1 / +3 / +7 天，第 3 次做对后移出队列（TC-02-08 三档全部业务可达，TC-02-09 断言第 3 次移出）。
> `+14 天` 不再出现在业务阶梯里（连对 3 次即毕业，不会发生第 4 次），仅作为策略层 `nextIntervalDays(4)` 的保留档。

**补全的三条约束**：

1. **优先级排序**：同一天队列内，按「考点薄弱度 × 遗忘风险」排序，薄弱且久未复习的排前面。
2. **跨模块升级**：课内背错的单词自动升级为课外线的优先复习项（F-WRD-05），写作里的病句与数学错题共享同一排期（F-WRT-05）。
3. **口述类不过关不移出**：母题的「过关」还要求能口述关键关系（F-MTH-03），此时该母题在队列中保持 PENDING，不计入「做对」。

### 5.6 F-BASE-06 反搜题顺序约束

**需求**：答案入口必须排在「先看母题思路」与「孩子先作答」之后。**本条与红线 R-01 同源**——R-01 是红线表述，F-BASE-06 是它在底座层的可执行落点。

| 项 | 内容 |
|----|------|
| 顺序 | 题目先给母题思路 → 孩子作答 → 才允许看解析 |
| DOM | 答案 / 解析区域的渲染依赖一次作答事件；未作答时答案区**不进入 DOM**（不是 `display:none`） |
| 接口 | 取题接口不返回答案字段 |
| 验收 | 未作答时练习页 DOM 中不存在答案 / 解析节点；作答后才出现 |

### 5.7 F-BASE-07 AI 只做解释层

**需求**：判对错走确定性逻辑，AI 只负责讲解与追问。**本条与红线 R-02 同源**——R-02 是红线表述，F-BASE-07 是它在底座层的可执行落点。

| 项 | 内容 |
|----|------|
| 判定 | 对错判定由题干比对、规则引擎、题型规则等确定性逻辑产出；AI 只做讲解与追问 |
| 判定来源 | 判对错响应必须带「判定来源」字段，取值非 `ai`（只允许 `rule` / `rule+model`） |
| 兜底 | 涉及分数必须有家长复核与申诉通道（见 F-FAM-08） |
| 依赖 | `rule` / `engine.judge` 包不得依赖 AI 客户端 |
| 验收 | 接口响应的判定来源 ≠ `ai`；家长端存在申诉入口 |

### 5.8 F-BASE-08 离线 / 缓存策略（V0 不做）

**需求**：**V0 明确不做**离线答题、本地缓存与断网补交。

| 项 | 内容 |
|----|------|
| 范围 | V0 学习端全部在线请求；不做本地题库缓存、不做离线作答队列、不做断网补交 |
| 取舍 | 断网时给出可读提示并允许重试，不降级为本地判分（避免与 R-02 的确定性判定冲突） |
| 触发复评 | 待验证「孩子实际使用场景是否频繁断网」，V1 结束后再评估是否立项 |
| 验收 | 断网时提示明确、无静默失败；网络恢复后数据无丢失、无重复提交 |

## 模块① 地区与考纲

### 6.1 定位

> 这个模块最容易被做成「资源库」，也最不该。对一个家庭来说，几百万套试卷是负担而不是资产。真正有用的只有一件事：把孩子所在地区、年级、教材版本的考纲拆成结构化坐标，让后面五个模块的所有内容都能挂上去。

### 6.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-REG-01 | 一次配置生成四层坐标树 | P0 | 配置（省+学段+年级+教材版本）后自动生成该组合对应的坐标树骨架；至少覆盖该年级的全部学科 |
| F-REG-02 | 考点四属性维护 | P0 | 每个考点可维护题型、分值权重、常见错误类型、对应母题 ID；母题字段在模块④上线前可为空 |
| F-REG-03 | 教材版本全支持 | P0 | 人教/苏教/北师大/浙教/沪教/京教/鲁教 7 个版本均可选；选课内词表时按版本过滤超纲 |
| F-REG-04 | 知识点树状浏览 | P1 | 支持四层树展开/折叠；选中任一考点可查看其下挂的题目/单词/母题/语法点数量 |
| F-REG-05 | 坐标树版本化与失效标记 | P1 | 考纲或教材版本变更时，旧节点标记失效而非删除；历史学习记录仍可解析到旧坐标 |

### 6.3 借鉴与避坑

- **借鉴**：菁优中考的「每题固定四段结构（考点描述 → 分析 → 解答 → 点评）」——这是「考点坐标系」的最小可用模型。
- **借鉴**：学科网「教材设置」一次配置全局生效的交互。
- **避坑**：不收录任何试卷与资料链接；本模块的产出是一张地图，不是内容仓库。

## 模块② 错题集与复盘

> 这是全场竞品最多、也最容易做出差异化的一块。四件事必须**同时**具备，缺一件就退化成积灰本。

### 7.1 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-WRG-01 | 错因强制标签 | P0 | 答完题后必须选择错因才能提交，五个固定维度：概念不清 / 审题偏差 / 计算失误 / 方法不会 / 时间不够。**不是选菜单，是必答的一个问题** |
| F-WRG-02 | 重做队列而非文件夹 | P0 | 错题默认进入待重做队列，按 F-BASE-05 排期；连续三次做对才移出；可查看下次复习日期 |
| F-WRG-03 | 一题多变 | P1 | 一道错题至少配一道「换数字」变式与一道「换情境」变式；**变式做对才算真的掌握**；变式由母题机制生成（F-MTH-04） |
| F-WRG-04 | 统一入口 | P0 | 数学母题、背单词、语法、写作的每一次「做错」都进这一个池子；各模块内不得存在独立错题列表 |
| F-WRG-05 | 拍照录入与笔迹擦除 | P1 | 支持拍照框选、擦除手写笔迹保留印刷题干、按学科+知识点双维标签；图像增强提升手写识别率 |
| F-WRG-06 | 版权安全清单 | P0 | 录入的题目来源必须是自编或公开授权；教材同步只做「结构映射」不做「内容复制」；导入时需选择来源类型并留存出处 |

### 7.2 借鉴与避坑

- **借鉴**：A+ 错题本的用户自定义错因标签 —— 错因维度必须由真实错题反推，不能预设。本 PRD 接受「五维固定」是**首版**妥协，但要求系统记录每个错因的使用频次，为后续扩展留口（见 F-BASE-04 常见错误类型字段）。
- **借鉴**：作业帮/小猿 AI 的「归集错因 → 推送同类题」自动链路 —— 这是复盘引擎的骨架。
- **借鉴**：试卷错题宝的「定向复习引擎」—— 全场唯一被明确写出的复盘引擎机制。
- **借鉴**：豆包爱学「深度解题」的思路 —— 先给一条错误思路，再反思错在哪，才给正解。
- **避坑**：不做搜题机；不做「一键打印 PDF」作为终点；不做公开错题分享。

## 模块③ 趣味高效背单词

> 「高效」有两条技术路线（算法抗遗忘 vs 趣味激励），「课内 + 课外」是两条完全不同的需求线。一个入口，两套算法。

### 8.1 两条线的差异

| 维度 | 课内（教材同步词） | 课外（考纲扩展与真题） |
|------|--------------------|----------------------|
| 目标 | 跟得上进度、形成习惯、完成不掉队 | 提分、突破、应试得分 |
| 学习者状态 | 低年级、畏难、需要正反馈 | 高段、自律、要效率 |
| 算法诉求 | 完成度优先：进度条、连续天数、养成激励 | 抗遗忘优先：遗忘曲线、单次时长最大化 |
| 词汇来源 | 教材单元词表；高中课标 3,000 词（义务教育 1,500 + 必修增 500 + 选择性必修增 1,000，各地可再增约 200） | 各地真题高频词、熟词生义、一词多义（address / spring / yield）、高频词组搭配（account for / subscribe to） |

### 8.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-WRD-01 | 课内教材单元 1:1 映射 | P0 | 课内词表按「教材版本 + 单元」精确映射；自动过滤超纲词；每单元为一关 |
| F-WRD-02 | 闯关与养成激励 | P1 | 每单元过关有可见奖励；连续天数累计；可切换「纯净无游戏冲刺模式」 |
| F-WRD-03 | 课外熟词过滤 | P1 | 首次进入课外线先做词汇量测试，已掌握词直接剔除出队列；过滤量在报告中可见 |
| F-WRD-04 | 四档反馈 | P0 | 反馈档位为「认识 / 模糊 / 忘记 / 熟知」，**不是对/错**；四档映射到不同的遗忘衰减更新 |
| F-WRD-05 | 跨线升级 | P0 | 课内背错的词自动升级为课外线的优先复习项，进入统一复习队列 |
| F-WRD-06 | 词→句→篇三层 | P2 | 一词一义 → 造句 → 短文填词；短文填词可导出打印 |

### 8.3 四个已被验证的坑（写进设计约束）

| 坑 | 设计对策 |
|----|----------|
| 只记图不记词（看图认词的伪记忆） | 课内词条**必须包含无图回忆环节**；图形仅作辅助，不得作为唯一线索 |
| 只打卡不复习（贪新词，旧词堆积） | 每日新词上限受当日复习欠账约束；复习完成度优先于新学量 |

| 课内超纲污染 | 按教材版本过滤（F-REG-03），孩子不会背一堆本学期不考的词 |

## 模块④ 数学母题过关斩将

> 需求里的「母题」和「过关斩将」两个词，在竞品里几乎是空白的。这是本模块最值得押注的地方，也是 V2 阶段的主战场。

### 9.1 母题数据结构（五段固定）

| 段 | 名称 | 说明 | 用途 |
|----|------|------|------|
| 1 | 题型名 | 如「行程问题·相遇」 | 检索与关卡命名 |
| 2 | 已知条件类型 | 几个变体（人数、速度比、往返） | 生成变式 |
| 3 | 关键关系 | 解题的「眼」，如「路程和 = 速度和 × 时间」 | **过关口述对象** |
| 4 | 解题步骤链 | 3–5 步 | 生成讲解 |
| 5 | 易错点清单 | 常见跳步、错设未知数 | 生成追问与错因预判 |

这五段既能生成讲解，也能生成变式——这是「母题」区别于「题」的本质。

### 9.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-MTH-01 | 母题五段结构 | P0 | 母题实体强制五段齐全，缺任一段不允许保存 |
| F-MTH-02 | 三层变式生成 | P0 | 变式分三层：换数字（同结构）→ 换情境（同结构不同表层）→ 逆向提问（已知结果求条件）；第三层最能检验真懂 |
| F-MTH-03 | 过关判据 | P0 | 过关 = 该母题下 N 道变式全对（首版 N=3）**且**能口述关键关系；口述不过关补一道苏格拉底式追问，而不是直接给答案 |
| F-MTH-04 | 错因二分前置打标 | P1 | 解每一步时打标：公式记错 / 步骤跳步 / 审题偏差 / 方法不会；错因数据反过来决定「先补哪一关」 |
| F-MTH-05 | 溯源到坐标树 | P0 | 母题挂到「地区考纲 → 学科 → 单元 → 考点」树上；**闯关顺序 = 考纲优先级，不是随机推荐** |
| F-MTH-06 | 关卡进度单位 | P1 | 进度以「母题关卡」为单位统计（不是题量）；孩子看到的是「这类题我会了 N 类」 |

### 9.3 借鉴与避坑

- **借鉴**：洪恩思维「母题剖析 + 子题变式 + 阶段考试」—— 与需求字面同构的现成机制，但仅覆盖小学应用题 185 道、学科面窄，需自行扩展。
- **借鉴**：科大讯飞 T90 Pro 的三条机制 —— 错误类型二分、苏格拉底式追问、情境重构变式，三条都可脱离硬件实现。
- **借鉴**：学而思小猴思维「名师 AI 互动课 → 引导举一反三」的提问式教学。
- **避坑**：不做「题量累计」作为成就感来源；不把「蒙对」「过程对但步骤跳」「真懂」混为一谈。

## 模块⑤ 英语语法趣味解读

> 海外做语法产品的是「查错工具」和「ESL 课程」两条线，中间那块——用孩子自己的句子、按国内考纲讲语法——没有人做。

### 10.1 两条路线之间的空隙

| 路线 | 强 | 弱 |

- 不做语法键盘（对儿童学习场景体验负担大）。

## 家庭与成员：多孩子多家长

> 本节是系统从「单用户（一个孩子 + 一个家长）」改为「多家庭、多孩子、多家长」后，在 PRD 侧的唯一落点。唯一依据是《多用户改造契约》（`06-AI协作/01-任务台账/2026103019-多用户改造契约.md`），本文与该契约冲突时以契约为准。

### 12.1 为什么从单用户改成多用户

原 PRD 按「一个孩子 + 一个家长」设计，N-05 明确不做多租户、不做通用权限体系。真实使用里一个家庭常常不止一个孩子（哥弟俩各学各的），也常有爸爸、妈妈、爷爷奶奶共同参与看护，1:1 的家长↔孩子关系根本表达不了这种结构。于是本次改造定了四件事：

1. **家长 ↔ 孩子是多对多**：一个家长可关联多个孩子，一个孩子可被多个家长关联（妈妈 + 爸爸 + 爷爷）。孩子归属唯一家庭，家长可加入一个家庭。
2. **孩子也是 `sys_user`**，只是**登录方式不同**：孩子用 4–6 位数字 PIN 登录（`POST /api/v1/study/kid/login`），家长走**底座原生登录**（`POST /sys/login`，用户名 + 密码，**不新增接口**）。
3. **不新增第二套认证栈**：Shiro/JWT、Redis 会话、`@RequiresPermissions`、菜单权限全部复用底座现成能力；孩子 token 与家长 token 同构，只是额外携带 `childId` claim。
4. **数据归属随之改变**：所有学习行为数据按 `child_id` 隔离，家长只看得到自己关联的孩子。

**边界不变**：仍然**不做多租户**、**不做通用权限体系**、**不引入租户字段**。多家庭指的是「一家人的多个孩子」，不是「多个机构共享一个系统」——本系统仍是家庭私有工具。

### 12.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-FAM-01 | 家庭创建与基础信息 | P0 | 家长首次登录可创建家庭，首个家长自动成为 OWNER；家庭名称可修改（默认「我的家庭」）；同一家长重复创建不产生第二个家庭；家庭详情可查询且含成员列表 |
| F-FAM-02 | 家长成员管理 | P0 | OWNER 可按用户名添加家长成员并设置关系标签（妈妈 / 爸爸 / 爷爷 / 奶奶 / 其他）；可移除成员（置为已退出，不物理删除）；同一家庭内同一家长不可重复添加；成员操作非本家庭资源返回 4010 |
| F-FAM-03 | 孩子档案管理 | P0 | 可新增 / 编辑 / 停用孩子档案，字段含昵称、头像、性别、生日（可选）、年级；新增时同时创建孩子的 `sys_user` 账号与 PIN；停用后该孩子无法登录；每个孩子档案归属唯一家庭 |
| F-FAM-04 | 家长↔孩子多对多关联 | P0 | 一个家长可关联多个孩子，一个孩子可关联多个家长；关联须指定关系标签；重复关联同一对（家长 + 孩子）被拒绝；解除关联后家长立即看不到该孩子数据（返回 4010）；孩子的关联家长列表可查询 |
| F-FAM-05 | 孩子独立账号与 PIN 登录 | P0 | 孩子用 PIN（4–6 位数字）登录，签发的 token 与家长同构且携带 `childId`；PIN 连错 5 次锁定 10 分钟，锁定期内拒绝登录；PIN 不以明文存储（只存哈希 + 盐）；家长可重置 PIN，明文仅重置时返回一次；登出后 token 失效 |
| F-FAM-06 | 家庭码与孩子端候选列表 | P0 | 家长可生成 / 重置家庭码（6 位大写字母数字），明文仅生成时返回一次，库里只存哈希；孩子端凭家庭码换取该家庭的候选孩子列表，列表只含 id / 昵称 / 头像，不含账号与任何学习数据；家庭码错误返回 4009；候选列表不返回该家庭以外的孩子 |
| F-FAM-07 | 学习数据按孩子隔离 | P0 | 错题池、复习排期、练习记录、变式题、作文、用眼统计按 `child_id` 存取；家长请求任何学习数据时与关系表求交集，只返回自己关联孩子的数据；家长改 URL / 参数指定他人 childCode 返回 4010（不返回 404，避免探测）；孩子 A 访问孩子 B 返回 4010 |
| F-FAM-08 | 家长反馈与申诉入口 | P1 | 家长可对**指定孩子**的作文 / 练习留一句话反馈，反馈带 child 维度；反馈不进入孩子的练习数据流；涉及 AI 判对错的结论可由家长发起申诉（R-02 的家长兜底通道）；家长 A 看不到家长 B 的反馈、评价与申诉记录 |

**补全**：落地对应 4 张新表（`study_family` / `study_family_member` / `study_child` / `study_parent_child_rel`）、既有学习行为表加 `child_id`、以及 21 个新接口（家长端 17 + 孩子端 4）与既有接口的 child 维度改造；具体字段、索引与路径见《数据库设计说明书》与《接口设计说明书》。

### 12.3 数据范围

| 身份 | 可读范围 | 判定来源 |
|------|----------|----------|
| 管理员 | 全部 | — |
| 家长 | **仅与自己关联的 child_id** | 每次请求实时查关系表 |
| 孩子 | **仅自己的 child_id** | JWT 携带 `childId` |

- 家长请求：Service 层取出 `childIdsOf(currentUserId)` 并**强制**拼进 where 条件。
- **不以前端传来的 `childId` 作为唯一依据**——家长侧必须与关系表求交集，防止越权。
- 违反隔离一律返回 **4010 越权**，而不是 404（避免探测）。
- 孩子端接口只认 token 里的 `childId`，不接受参数覆盖。

### 12.4 家长之间互不可见

- 家长 A **看不到**家长 B 的反馈、评价、申诉记录，也看不到对方关联的孩子清单。
- 家长能看到的仍然只是**孩子的客观趋势与状态**，口径与单用户时期一致。
- **R-04 在多家长场景下进一步收紧**：禁止家庭内比较（「谁的孩子更…」「家长评分对比」等任何形式），禁止家长之间对比数据；数据模型与响应中同样不出现 rank / percentile 类字段。

## 家长端与护眼

### 13.1 家长端（F-PAR，只读）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-PAR-01 | 只读报告 | P1 | 家长可查看：知识点掌握度、错因分布、连续天数、用眼时长、周报；**不提供**任何「辅导建议」「辅导课程」「答案速查」入口 |
| F-PAR-02 | 一句话反馈 | P1 | 家长可对某篇作文/某次练习留**一句话**；评论长度上限受约束（建议 ≤ 100 字）；家长评论不进入孩子的练习数据流 |
| F-PAR-03 | 不做公开比较 | P0 | 家长端**不出现**任何同龄排名、分数排名、百分位、超过 X% 的同学等；仅呈现与自身历史趋势的对比 |
| F-PAR-04 | 提醒推送偏好 | P2 | 家长可设置复习提醒、护眼提醒的推送时间与渠道偏好 |

**补全**：多孩子家庭下家长端按孩子切换视角——切换的是**视角**不是身份，能看到的始终只有自己关联的孩子（F-FAM-07）；家长之间互不可见（R-04）。

### 13.2 护眼（F-EYE，硬指标）

| 编号 | 需求 | 优先级 | 验收标准 |
|------|------|--------|----------|
| F-EYE-01 | 用眼时长统计 | P1 | 记录每次连续学习时长、每日累计时长，在家长端可见 |
| F-EYE-02 | 蓝光过滤 | P1 | 可开关的蓝光过滤模式，作用于全站；状态可查询 |
| F-EYE-03 | 定时休息提醒 | P0 | 每 15 分钟强制远眺提醒；达到阈值时提醒为**阻断式**（须确认后才继续） |
| F-EYE-04 | 休息提醒可配置 | P2 | 提醒间隔可按阶段配置（低年级 10 分钟、高年级 20 分钟） |

**补全说明**：近视率 52.7% 是国家卫健委公开监测数据，超 75% 的家庭无法完全依靠自身完成孩子全流程学习辅导。护眼能力必须是**产品指标**而不是营销词，因此上述四项中 F-EYE-01/02/03 在 V0 即随学习端一同上线，而非延后。

| N-02 | 响应 | 列表/详情页首屏 ≤ 1.5s（本地环境）；判对错接口 ≤ 300ms（不含 AI 讲解） | 接口压测 |
| N-03 | 判对正确性 | 对错判定必须由确定性逻辑产出；AI 输出仅作解释层，**AI 判定不得直接落库为结论** | 代码走查 + 单元测试 |
| N-04 | 数据一致性 | 错题池、排期、掌握度三者的写入必须在同一事务内；排期写入失败则整笔回滚 | 事务测试 |
| N-05 | 多家庭多用户 | 系统不实现多租户、不做通用权限体系，数据模型不预留租户字段；但**必须实现按 child_id 的数据范围隔离**，家长↔孩子为多对多，孩子使用独立 PIN 登录 | 设计走查 + 越权用例（跨家庭 / 跨孩子访问一律返回 4010） |
| N-06 | 隐私 | 不采集任何用于画像的行为数据；不接入第三方统计 SDK；所有数据留在本地 | 依赖扫描 + 网络抓包 |
| N-07 | 未成年人合规 | 家长端与孩子端身份可区分；家长操作留痕；不设公开 UGC | 走查 |
| N-08 | 可用性 | 单手可完成全部核心操作（移动视口 390px 宽下无横向溢出） | 视口截图 + 溢出探针 |
| N-09 | 可维护性 | 遵循 JeecgBoot 既有分层与代码规范；新增页面遵循《产品设计规范》 | 代码走查 |

## 数据模型概要

> 完整字段、索引与建表语句见《数据库设计说明书》。此处只列实体与职责。

| 序号 | 实体 | 中文名 | 职责 | 关键关系 |
|------|------|--------|------|----------|
| 1 | `study_context` | 全局上下文 | 省/学段/年级/教材版本 | 坐标树根 |
| 2 | `study_knowledge_point` | 考点 | 四层树节点，含四属性 | 挂题目/单词/语法点/母题 |
| 3 | `study_question` | 题目 | 统一题目实体（含来源、版权类型） | 挂考点、进错题池 |
| 4 | `study_mother_question` | 母题 | 五段结构 + 变式定义 | 挂考点，生成变式题 |
| 5 | `study_word` | 单词 | 词条 + 课内/课外归属 + 遗忘参数 | 挂考点，进错题池 |
| 6 | `study_grammar_point` | 语法点 | 语法规则 + 例句 + 反例 | 挂考点，进错题池 |
| 7 | `study_writing` | 写作 | 作文 + 拆解层 + 批改差异清单 | 进错题池 |
| 8 | `study_error_pool` | 统一错题池 | 跨模块错题 + 错因 + 排期 | 关联各模块实体 |
| 9 | `study_review_schedule` | 复习排期 | 间隔重复队列 | 关联错题池 |
| 10 | `study_eye_usage` | 用眼记录 | 每次学习时长与休息确认 | 关联孩子 |
| 11 | `study_family` | 家庭 | 家庭码（哈希）+ 家庭名称 + 状态 | 挂成员与孩子 |
| 12 | `study_family_member` | 家庭成员（家长） | 家长与家庭的归属、成员角色、关系标签 | 关联家长账号 |
| 13 | `study_child` | 孩子档案 | 昵称 / 头像 / 年级 / PIN 哈希 / 状态 | 关联孩子账号、归属家庭 |
| 14 | `study_parent_child_rel` | 家长↔孩子关联 | 多对多关系 + 关系标签 + 是否主家长 | 关联家长与孩子 |

**补全**：竞品分析只描述了「五个共享组件」，本 PRD 把它落成 10 张实体表。其中 4–7 属各模块的**内容实体**（题/词/语法点/写作），1–3 与 8–10 属**底座实体**。模块实体与底座实体通过 `study_knowledge_point.id` 单一纽带相连——这是「六模块共享一份学情」在数据层的唯一实现点。多用户改造在此之上新增 4 张家庭与成员表（11–14），并为学习行为类的 7 张表加 `child_id` 实现按孩子隔离（F-FAM-07）；题库、词库、考点树等内容表保持全局共享，不按孩子拆分。

## 版本规划 V0–V4

> 增量追加的正确顺序，不是按开发难度，而是按「地基 → 闭环 → 增量」。

| 阶段 | 上线内容 | 要达成的目标 | 通过标准 |
|------|----------|--------------|----------|
| V0 地基 | **前置 F-FAM-01…07 最小闭环（家庭 → 孩子档案 → PIN 登录 → 数据隔离）** + 全局上下文配置 + 坐标树骨架 + 错题池（拍照录入 + 错因标签 + 重做队列）+ 护眼四项 | 先把「这是谁的数据」立住，再解决「一个娃学什么」和「他错在哪、什么时候再练」两个问题 | 能对任意一道错题回答：**这是哪个孩子的**、属于哪个考点、错因是什么、下次什么时候复习、变式题在哪 |
| V1 习惯 | 背单词模块（课内线优先：教材单元 1:1 映射 + 闯关 + 连续天数） | 先建立每天打开的习惯与最小成就感 | 连续 14 天完成率 ≥ 80%；课内单元词表覆盖到当前进度 |
| V2 主战场 | 数学母题过关斩将（母题五段结构 + 三层变式 + 过关判据 + 错因二分） | 做出竞品里几乎无人做的机制差异 | 每个母题至少 3 道变式；变式全对且能口述关键关系才算过关 |
| V3 拓展 | 英语语法（句子变形器 + 错误即入口）+ 课外词线（熟词过滤 + 四档反馈） | 补齐英语，并验证跨模块复盘是否跑得通 | 语法错句自动进错题池并排期；课外词复习完成率 ≥ 课内 |
| V4 沉淀 | 语文写作（名篇拆解库 + 对照式批改 + 三步训练）+ 全模块关联推荐 | 完成闭环，并做出与竞品最本质的差别 | 每篇作文能给出「与同题材佳作的差异清单」；跨模块推荐命中率达可用水平 |

**补全的阶段约束**：

1. 每个阶段**必须**同时满足 R-01…R-04 四条红线，缺一不发布。
2. V1 之前不得上线任何「内容型」模块——底座没稳就堆内容，等于制造积灰。
3. V2 之前，背单词的课内线必须先跑通「课内错词自动升级为课外优先项」（F-WRD-05），否则 V3 的课外线无升级来源。
4. **V0 必须先有身份**：F-FAM-01…07 的最小闭环（家庭 → 孩子档案 → PIN 登录 → 数据隔离）前置到 V0——没有孩子身份就没有学习数据的归属，护眼统计与错题池都无从落地。

## 验收标准

### 17.1 端到端验收场景（对应 3.3 主链路）

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| A-01 | 上下文生效 | 配置一次后，进入任一模块无需再次选择地区/年级/教材 |
| A-02 | 跨模块错题汇聚 | 分别在背单词、母题、语法、写作各制造一次错误，四个模块的「错题」总数等于统一错题池条数 |
| A-03 | 错因强制 | 未选错因时提交练习被拒绝，且给出可读原因 |
| A-04 | 排期正确 | 错题当天进入队列；答对一次后下次复习日期为 +1 天；连续两次答对后移出 |
| A-05 | 变式过关 | 母题变式未全对时不得标记过关；口述未通过时不得移出队列 |
| A-06 | 跨线升级 | 课内背错的词出现在课外线的优先复习项中 |
| A-07 | 写作防代写 | 未完成提纲步骤时无法提交初稿 |
| A-08 | 反搜题 | 未作答时练习页看不到解析/答案入口 |
| A-09 | 护眼阻断 | 连续用眼达阈值后出现阻断式提醒，需确认才能继续 |
| A-10 | 无排名 | 全库检索无「排名/排行/百分位/超过 X% 的同学」相关字段与文案 |
| A-11 | 家长端只读 | 家长端页面无任何答案查询、辅导建议入口 |
| A-12 | 教材版本隔离 | 切换教材版本后，课内词表与母题顺序随之改变，超纲词被过滤 |

### 17.2 非功能验收

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| A-13 | 移动端适配 | 390px 宽下无横向溢出；核心操作单手可达 |
| A-14 | 判对错来源 | 判对错接口返回含判定来源字段，取值不为 `ai` |
| A-15 | 数据留本地 | 网络抓包确认无第三方统计/广告请求 |
| A-16 | 事务一致性 | 排期写入失败时错题记录不落库 |

### 17.3 多用户验收（对应第 12 章）

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| A-17 | 家庭与成员闭环 | 家长创建家庭后自动成为 OWNER；可添加 / 移除家长成员；成员操作非本家庭资源返回 4010 |
| A-18 | 孩子 PIN 登录 | 家庭码 → 候选孩子列表 → PIN 登录成功；PIN 连错 5 次锁定 10 分钟；候选列表只含 id / 昵称 / 头像 |
| A-19 | 数据隔离 | 家长 A 访问孩子 B 的错题 / 记录返回 4010；家长改 URL 指定他人 childCode 返回 4010；孩子 A 访问孩子 B 返回 4010 |
| A-20 | 家长之间互不可见 | 家长 A 的接口响应中不含家长 B 的任何标识；全站文案无家庭内比较措辞 |
| A-21 | 反馈带孩子维度 | 家长反馈与申诉均绑定具体 child；反馈不进入孩子的练习数据流 |

## 风险与对策

| 级别 | 风险 | 说明 | 对策 |
|------|------|------|------|
| 高 | 内容版权 | 题库、范文、真题均不可直接搬运。学科网、菁优、笔神的题库与范文都是受版权保护的商业资产 | 题目用自编或公开授权（OpenStax、CC 授权教材、各地教育考试院公开发布的样题与考纲）；范文用公开发表的获奖作品并标注出处；教材同步只做「结构映射」不做「内容复制」（F-WRG-06） |
| 高 | 近视与用眼 | 儿童青少年总体近视率已突破 52.7%；超 75% 的家庭无法完全依靠自身完成全流程辅导 | 护眼四项进 V0（F-EYE-01…04），用眼时长是家长端一等指标，不是加分项 |
| 中 | 搜题依赖 | 行业公认的用户伤害：过度依赖搜题、缺乏独立思考 | 反搜题红线 R-01 落到 DOM 级约束；答案入口依赖作答事件；不做拍照搜题 |
| 中 | AI 幻觉与批改误判 | 竞品实测已出现（千问把正确题判为错） | 涉及分数、对错的判定一律走确定性逻辑，AI 只做解释层；每处 AI 结论须附依据并允许申诉；保留家长复核通道（R-02） |
| 中 | 教材版本与考纲变动 | 地区考纲、教材版本会周期性调整 | 坐标树版本化 + 失效标记（F-REG-05）；旧节点不删除 |
| 中 | 多用户改造后的数据隔离 | 家长↔孩子多对多之后，越权取数的面变大：家长看到别人的孩子、孩子看到别人的孩子 | 关系表实时求交集 + 越权统一返回 4010（不返回 404，避免探测）；隔离用例 10 条（F-FAM-04、F-FAM-07） |
| 中 | 内容供给不足 | 母题五段结构、拆解库六层结构都需要人工撰写，成本高 | 首版只覆盖一个年级一个学科，用「结构模板 + 人工填充」保证质量；不追求数量 |
| 低 | 家庭私有、规模有限 | 拿不到墨墨式 1200 亿级行为数据，也拿不到学而思式教研厚度 | 借 Anki 的间隔重复算法、扇贝的熟词过滤、洪恩的母题结构、菁优的考点四段式——**用别人的机制代替自己的数据规模** |

**补全的一条风险**：错因五维是首版固定值，而竞品证据（A+ 错题本的自定义错因）说明错因维度应由真实错题反推。对策是 F-BASE-04 记录每个错因标签的使用频次，V1 结束后评估是否需要扩展维度或允许自定义。

## 明确不做的事

> 这一节是对第一版范围最有效的约束。任何新增需求先对照本节。

| 编号 | 不做的事 | 理由 |
|------|----------|------|
| X-01 | 拍照搜题 / 拍题出答案 | 直接毁掉前五个模块的价值（R-01） |
| X-02 | 试卷/资料资源库与下载 | 资源规模对一个家庭是负担，1,294 万套资料等于选择困难 |
| X-03 | 作文素材金句库 | 导致作文雷同，违背「鉴赏」初衷 |
| X-04 | 文段美化 / 同义转化 / 一键成文 | 本质接近代写，与学习写作目标冲突 |
| X-05 | 公开社区、排行榜、点赞、投稿 | 家庭私有工具不需要社交压力，反而需要降低焦虑 |
| X-06 | 同龄分数排名 / 百分位 | 违反 R-04 |
| X-07 | 多租户、复杂权限体系、运营后台 | 多家庭≠多租户：不做机构化运营与通用权限体系，把复杂度省下来（N-05） |
| X-08 | 第三方数据埋点看板、广告 SDK | 未成年人数据合规 + N-06 |
| X-09 | 通用大模型直连生成答案 | 大模型只做解释层，结论必须确定性可溯源 |
| X-10 | 付费墙、会员、增长机制 | 家庭私有工具，不需要增长 |
