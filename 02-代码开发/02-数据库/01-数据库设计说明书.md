## 库与连接约定

### 1.1 单库策略（V1.1 变更：双库 → 单库）

| 库 | 内容 | 来源 |
|----|------|------|
| `jeecg-study` | **平台表**（JeecgBoot 自带 133 张：`sys_*` `qiankun_*` `onl_*` `airag_*` 等）**+ 业务表**（本文件定义的 24 张） | JeecgBoot v3.9.2 上游全量脚本（只改库名）+ 本项目业务表 |

**为什么改成单库**：

1. **独立基座**：jeecg-study 使用**自己拉取的 JeecgBoot v3.9.2**（`02-代码开发/05-源码/01-JeecgBoot基座/`），与 monitorV2 完全隔离，不共享 `jeecg-boot` 库——共享就谈不上「独立」。
2. **多用户需要平台表**：家长账号就是 JeecgBoot `sys_user`，孩子也是 `sys_user`（角色 `study_kid`）。平台表与业务表同库，关联查询与事务边界才简单。
3. **不需要双数据源**：`@DS("study")` 随之取消（ADR-015 取代 ADR-001）。

> ⚠️ **这改变了原 ADR-001（双数据源）**。若将来要拆分，只需在 `spring.datasource.dynamic.datasource` 下新增一个 `study` 键并给业务 Mapper 加 `@DS("study")`，**业务代码无需改动**——底座的 dynamic-datasource 已经就位。

**平台表来源**：上游 `jeecg-boot/db/jeecgboot-mysql-5.7.sql`（133 张表 + 7446 条种子数据），
由 `05-公共资源/2026103018-平台库脚本.py` **只改库名**生成 `03-脚本/01-平台库初始化.sql`。
上游原文件**保持不动**，便于日后对照 v3.9.2 升级。

### 1.2 连接参数

| 项 | 值 |
|----|-----|
| 主机 / 端口 | `127.0.0.1:3306` |
| 库名 | `jeecg-study`（平台表 + 业务表同库） |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 用户 | `root` |
| 密码 | 环境变量 `DB_PASSWORD` 注入（**不入库**；未设置时回落上游默认 `root`） |
| JDBC URL | `jdbc:mysql://127.0.0.1:3306/jeecg-study?characterEncoding=UTF-8&useUnicode=true&useSSL=false&tinyInt1isBit=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai` |

> 口令**一律**由环境变量 `${DB_PASSWORD}` 注入：`application-dev.yml` 与 `application-test.yml` 写 `${DB_PASSWORD:root}`，
> `application-prod.yml` 写 `${DB_PASSWORD}`（无缺省，生产必须显式注入）。**真实口令不写入任何入库文件。**

### 1.3 建库

```sql
CREATE DATABASE IF NOT EXISTS `jeecg-study`
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE `jeecg-study`;
```

> **库名是部署参数**：脚本里出现的库名一律是字面量，由部署脚本 `migrate.ps1` 按环境（dev / test / acc / prod）做替换后再执行。
> **每个脚本自带 `USE`**，因此不依赖调用方预先选库——直接 `mysql < 脚本.sql` 也能落到正确的库。

## 建表规约

| 项 | 约定 | 理由 |
|----|------|------|
| 表前缀 | `study_` | 与平台表隔离，便于识别 |
| 主键 | `id varchar(32)`，**不用自增** | 内容 ID 具备业务语义（`KPT-MA-0417`），且跨库可引用 |
| 业务 ID | 内容表用 `xxx_code varchar(32)` 存业务 ID（如 `KPT-MA-0417`），`id` 存 UUID | 业务 ID 对外暴露且稳定，`id` 对内关联 |
| 逻辑删除 | `del_flag tinyint default 0` | JeecgBoot 底座约定 |
| 审计字段 | `create_by / create_time / update_by / update_time` | JeecgBoot 底座约定，`create_time`/`update_time` 用 `datetime` |
| 时间 | 一律 `datetime`，**不用 `timestamp`** | 避免 2038 问题与隐式时区转换 |
| 金额/分数 | `decimal` | 浮点误差 |
| JSON 字段 | `json` 类型 | MySQL 8 原生支持；半结构化内容（母题五段、拆解六层） |
| 状态字段 | `tinyint` + 枚举注释 | 避免 MySQL `ENUM` 改值时的锁表与迁移痛苦 |
| 索引 | 每个外键列建索引；组合索引遵循最左前缀 | — |
| 注释 | **每张表、每个字段必须有 `COMMENT`** | 交接与排错的基础 |
| 命名 | 全小写下划线 | 与 JeecgBoot 底座一致 |

> **注意**：本库**不建** `tenant_id` 列。系统是**多家庭多用户但不做多租户**（PRD N-05 改写版）：隔离维度是 `child_id`（孩子），不是租户。预留租户字段是典型的过度设计。

## 底座实体表

### 4.1 study_context — 全局上下文

```sql
CREATE TABLE `study_context` (
  `id`               varchar(32)  NOT NULL COMMENT '主键',
  `context_code`     varchar(32)  NOT NULL COMMENT '上下文编码',
  `province_code`    varchar(16)  NOT NULL COMMENT '省级行政区编码',
  `province_name`    varchar(32)  NOT NULL COMMENT '省级行政区名称',
  `stage_code`       varchar(16)  NOT NULL COMMENT '学段编码 PRIMARY/JUNIOR/SENIOR',
  `grade_code`       varchar(16)  NOT NULL COMMENT '年级编码 G1..G12',
  `textbook_version_id` varchar(32) NOT NULL COMMENT '教材版本ID',
  `eye_interval_min` int          NOT NULL DEFAULT 15 COMMENT '护眼提醒间隔(分钟)',
  `is_current`       tinyint      NOT NULL DEFAULT 0 COMMENT '是否当前生效 1是 0否',
  `effective_from`   datetime     NOT NULL COMMENT '生效时间',
  `del_flag`         tinyint      NOT NULL DEFAULT 0 COMMENT '删除标记 0正常 1删除',
  `create_by`        varchar(50)  DEFAULT NULL COMMENT '创建人',
  `create_time`      datetime     DEFAULT NULL COMMENT '创建时间',
  `update_by`        varchar(50)  DEFAULT NULL COMMENT '更新人',
  `update_time`      datetime     DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_context_code` (`context_code`),
  KEY `idx_context_current` (`is_current`, `del_flag`),
  KEY `idx_context_scope` (`province_code`, `stage_code`, `grade_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='全局上下文(地区/学段/年级/教材版本)';
```

**设计说明**

| 点 | 说明 |
|----|------|
| `is_current` | 全表最多一行 `is_current=1`；切换上下文时旧行置 0，**不删除** |
| 历史隔离 | 练习记录、错题携带 `context_id`，切换上下文后历史记录仍属旧上下文（系统设计 5.1） |
| `eye_interval_min` | 护眼间隔按学段配置（F-EYE-04） |
| 单上下文约束 | 应用层保证「同时只有一行 is_current=1」，数据库层不加唯一约束（避免切换过程中的写冲突） |

### 4.3 study_knowledge_point — 坐标树

```sql
CREATE TABLE `study_knowledge_point` (
  `id`              varchar(32)  NOT NULL COMMENT '主键',
  `point_code`      varchar(32)  NOT NULL COMMENT '业务ID KPT-{学科码}-{序号}',
  `parent_id`       varchar(32)  DEFAULT NULL COMMENT '父节点ID',
  `level`           tinyint      NOT NULL COMMENT '层级 1考纲 2学科 3单元 4考点',
  `subject_code`    varchar(16)  NOT NULL COMMENT '学科编码 MA/CH/EN/CN',
  `name`            varchar(128) NOT NULL COMMENT '名称',
  `path`            varchar(512) DEFAULT NULL COMMENT '物化路径 /id/id/id/',
  `question_type`   varchar(64)  DEFAULT NULL COMMENT '考点:题型',
  `score_weight`    decimal(5,2) DEFAULT NULL COMMENT '考点:分值权重',
  `error_types`     varchar(256) DEFAULT NULL COMMENT '考点:常见错误类型(逗号分隔)',
  `mother_question_code` varchar(32) DEFAULT NULL COMMENT '考点:对应母题业务ID',
  `version`         varchar(16)  NOT NULL DEFAULT 'v1' COMMENT '节点版本',
  `effective_from`  date         NOT NULL COMMENT '生效日期',
  `invalid_at`      date         DEFAULT NULL COMMENT '失效日期(NULL=现行)',
  `status`          tinyint      NOT NULL DEFAULT 1 COMMENT '状态 1现行 0失效',
  `sort_no`         int          NOT NULL DEFAULT 0 COMMENT '排序号',
  `del_flag`        tinyint      NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`       varchar(50)  DEFAULT NULL COMMENT '创建人',
  `create_time`     datetime     DEFAULT NULL COMMENT '创建时间',
  `update_by`       varchar(50)  DEFAULT NULL COMMENT '更新人',
  `update_time`     datetime     DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_point_code` (`point_code`),
  KEY `idx_kp_parent` (`parent_id`, `status`),
  KEY `idx_kp_subject` (`subject_code`, `level`, `status`),
  KEY `idx_kp_context` (`effective_from`, `invalid_at`),
  KEY `idx_kp_mother` (`mother_question_code`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='坐标树节点(地区考纲/学科/单元/考点, 四层, 版本化)';
```

**设计说明**

| 点 | 说明 |
|----|------|
| 四层 | `level` 1=地区考纲，2=学科，3=单元/章节，4=考点。`parent_id` 为空表示根 |
| `path` 物化路径 | 用于一次查询取子树：`path LIKE '/rootId/%'` |
| **版本化** | 考纲调整时**插入新版本节点**，旧节点置 `invalid_at` 与 `status=0`，**不 UPDATE 不 DELETE**（PRD F-REG-05） |
| `point_code` 唯一 | 业务 ID 永久不变，即使节点失效也不复用（系统设计 5.3） |
| `error_types` | 考点级常见错因；由真实错题反推后回填 |
| 母题外键 | 用 `mother_question_code` 业务 ID 而非 `id`，便于跨库与人工核对 |

### 4.4 study_error_pool — 统一错题池（核心表）

```sql
CREATE TABLE `study_error_pool` (
  `id`              varchar(32)  NOT NULL COMMENT '主键',
  `error_code`      varchar(32)  NOT NULL COMMENT '业务ID ERR-{序号}',
  `context_id`      varchar(32)  NOT NULL COMMENT '所属全局上下文',
  `source_module`   varchar(16)  NOT NULL COMMENT '来源模块 ERROR/WORD/MATH/GRAMMAR/WRITING',
  `content_type`    varchar(24)  NOT NULL COMMENT '内容类型 QUESTION/WORD/SENTENCE/PARAGRAPH',
  `content_id`      varchar(32)  NOT NULL COMMENT '关联内容业务ID',
  `content_snapshot` json         DEFAULT NULL COMMENT '内容快照(题干/选项/答案)',
  `knowledge_point_code` varchar(32) DEFAULT NULL COMMENT '所属考点业务ID',
  `subject_code`    varchar(16)  DEFAULT NULL COMMENT '学科编码',
  `error_cause`     varchar(16)  NOT NULL COMMENT '错因 CONCEPT/READING/CALC/METHOD/TIME',
  `raw_answer`      varchar(1024) DEFAULT NULL COMMENT '孩子原始作答',
  `correct_answer`  varchar(1024) DEFAULT NULL COMMENT '正确答案',
  `judge_source`    varchar(16)  NOT NULL DEFAULT 'rule' COMMENT '判定来源 rule/rule+model',
  `mastery_state`   tinyint      NOT NULL DEFAULT 1 COMMENT '掌握度 1未知 2学习中 3熟悉 4掌握',
  `correct_streak`  int          NOT NULL DEFAULT 0 COMMENT '连续做对次数',
  `review_status`   tinyint      NOT NULL DEFAULT 1 COMMENT '复习状态 1待复习 2已移出',
  `next_review_at`  date         DEFAULT NULL COMMENT '下次复习日期',
  `last_review_at`  datetime     DEFAULT NULL COMMENT '上次复习时间',
  `archived_at`     datetime     DEFAULT NULL COMMENT '移出时间',
  `upgrade_flag`    tinyint      NOT NULL DEFAULT 0 COMMENT '跨线升级标记(课内→课外)',
  `source_ref`      varchar(256) DEFAULT NULL COMMENT '版权来源说明/出处',
  `copyright_type`  varchar(16)  NOT NULL DEFAULT 'SELF' COMMENT '版权类型 SELF/PUBLIC/LICENSE',
  `del_flag`        tinyint      NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`       varchar(50)  DEFAULT NULL COMMENT '创建人',
  `create_time`     datetime     DEFAULT NULL COMMENT '创建时间',
  `update_by`       varchar(50)  DEFAULT NULL COMMENT '更新人',
  `update_time`     datetime     DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_error_code` (`error_code`),
  KEY `idx_err_review` (`review_status`, `next_review_at`),
  KEY `idx_err_content` (`content_type`, `content_id`),
  KEY `idx_err_kp` (`knowledge_point_code`),
  KEY `idx_err_module` (`source_module`, `create_time`),
  KEY `idx_err_cause` (`error_cause`),
  KEY `idx_err_context` (`context_id`),
  KEY `idx_err_upgrade` (`upgrade_flag`, `review_status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='统一错题池(全模块错题唯一存放处)';
```

**设计说明**

| 点 | 说明 |
|----|------|
| **唯一错题池** | 全库唯一一张错题表。各模块**不得**另建错题表（PRD F-WRG-04） |
| `error_cause` NOT NULL | 缺失直接抛 4001 错误，**不允许**空错因入库（PRD F-WRG-01） |
| `judge_source` | 只有 `rule` / `rule+model` 两种取值，**不存在** `model`（红线 R-02 的数据层保险） |
| `content_snapshot` | 存快照，避免内容修订后错题失真；同时支撑「原始作答对照」 |
| `mastery_state` | 考点级掌握度在本表冗余一份便于队列查询；权威值在 `study_kp_mastery` |

| `copyright_type` | 自编 / 公开 / 授权。导入非自编题目时**必须**填 `source_ref`（PRD F-WRG-06） |

> **`judge_source` 强约束**：只有 `rule` / `rule+model` 两种取值，**不存在** `model`。可在数据库层加 `CHECK` 约束做第二道保险（MySQL 8.0.16+ 支持 CHECK）。

**设计说明**

| 点 | 说明 |
|----|------|
| 唯一键 | `(error_code, schedule_date)` —— 同一条错题同一天只排一次 |
| `sort_score` | 薄弱度 × 遗忘风险，降序排前（系统设计 6.2） |
| `queue_date` | 物化到某天后当天顺序不变；为 NULL 表示尚未进入某日队列 |

**排期状态机**（对应系统设计 6.1）：

| 当前 | 动作 | 下次复习 | 移出 |
|------|------|----------|------|
| 当天 | 答错 | 当天 | — |
| +1 天 | 答对 | +3 天 | — |

### 8.1 多对多的语义边界

| 规则 | 说明 |
|---|---|
| 一个家长可关联**多个**孩子 | `study_parent_child_rel` 多行 |
| 一个孩子可被**多个**家长关联 | `study_parent_child_rel` 多行，`relation_label` 区分关系 |
| 孩子归属**唯一家庭** | `study_child.family_id` 单值 |
| 家长可属于**一个**家庭 | `study_family_member` 唯一索引 `(family_id, user_id)`；需换家庭先退出 |
| 解除关联**立即生效** | `status=2` 后家长端列表与数据范围同时失效 |

## child_id 数据隔离

> **多用户的核心防线**：家长只能看到与自己关联的孩子的数据。
> **内容/知识库全局共享**（教材版本、考点树、题库、母题、词库、语法点 —— 内容供给成本高，家庭内共享合理）；
> **学习行为/数据按孩子隔离**（上下文、错题池、排期、变式、作文、作答记录、用眼统计）。

### 9.1 越权判定

| 场景 | 判定 | 返回 |
|---|---|---|
| 家长 A 请求孩子 B 的数据 | `child_id` 不在 `study_parent_child_rel` 交集内 | **4010 越权**（不是 404，避免探测） |
| 家长 A 传孩子 B 的 `childCode` | 同上 | **4010** |
| 孩子 A 请求孩子 B 的数据 | JWT 的 `childId` 与请求不符 | **4010** |
| 家长 A 不在目标家庭 | `study_family_member` 无记录 | **4010** |

> **实现约定**：家长侧 `child_id` 集合必须由 `ChildScopeHelper.childIdsOf(userId)` **实时查关系表**得到，
> 与前端传入的 `childId` **求交集**后才能进 where 条件。**不得**直接信任前端参数。

## 索引与性能

### 11.1 关键查询路径

| 查询 | SQL 要点 | 命中索引 |
|------|----------|----------|
| 今日复习队列 | `WHERE review_status=1 AND next_review_at <= today ORDER BY 薄弱度×遗忘风险` | `idx_err_review` |
| 队列物化 | `WHERE queue_date=? AND status=1 ORDER BY sort_score DESC` | `idx_sched_queue` |
| 某考点的错题 | `WHERE knowledge_point_code=?` | `idx_err_kp` |
| 错因分布统计 | `GROUP BY error_cause` | `idx_err_cause` |
| 课内单元词表 | `WHERE textbook_version_id=? AND unit_code=? ORDER BY unit_order` | `idx_word_unit` |
| 课外到期词 | `WHERE line_type='OUT' AND next_review_at<=? AND known_flag=0` | `idx_word_review` |
| 坐标树子树 | `WHERE path LIKE '/rootId/%' AND status=1` | `idx_kp_parent` + `path` |
| 母题及变式 | `WHERE mother_code=? ORDER BY layer` | `idx_var_mother` |
| 错题内容追溯 | `WHERE content_type=? AND content_id=?` | `idx_err_content` |
| 写作情境清单 | `WHERE theme_code=? AND status=1 ORDER BY order_weight, scenario_code` | `idx_scn_theme` |
| 按词查例句 | `JOIN study_word_context w + study_sentence_context c ON c.sentence_code=w.sentence_code WHERE w.word_code=?` | `idx_wc_word` |
| 按玩法取候选题 | `WHERE game_type=? AND status=1 ORDER BY difficulty, question_code, id` | `idx_gq_type` |
| 孩子闯关进度 | `WHERE child_id=? AND game_type=? ORDER BY question_code` | `idx_ggr_child` |

### 11.2 性能设计

| 措施 | 说明 |
|------|------|
| 坐标树全量缓存 | Redis `study:kp:tree:{contextId}`，节点 < 5000，命中 < 50ms；变更主动失效 |
| 队列物化 | 每日首次访问时物化，当天顺序不变，避免每次查都算排序分 |
| 作答记录分表 | 按月分表，避免单表膨胀（3 年约 36 张表） |
| 快照存 JSON | 错题快照直接存 JSON，避免每次 join 内容表 |
| 无分页深翻 | 错题池按 `next_review_at` 走索引，不做深度分页 |

### 11.3 容量估算

| 表 | 3 年预估 | 单行均值 | 预估大小 |
|----|----------|----------|----------|
| `study_error_pool` | ≤ 20,000 | ~1 KB | ~20 MB |
| `study_practice_record_*` | ≤ 500,000 | ~0.5 KB | ~250 MB（分表后单表 ~7 MB） |
| `study_question` | ≤ 10,000 | ~2 KB | ~20 MB |
| `study_word` | ≤ 30,000 | ~1 KB | ~30 MB |
| `study_knowledge_point` | ≤ 5,000 × 3 版本 | ~0.3 KB | ~5 MB |
| `study_review_schedule` | ≤ 100,000 | ~0.2 KB | ~20 MB |
| **合计** | — | — | **< 400 MB** |

家庭私有部署场景下无需分库分表，`practice_record` 的按月分表是唯一必要的分区手段。

### 12.1 脚本规范

| 项 | 约定 |
|----|------|
| 目录 | `02-代码开发/02-数据库/03-脚本/`（**SQL 真源唯一一处**） |
| 文件 | `01-平台库初始化.sql` · `02-schema.sql` · `03-init.sql` · `04-fix.sql` · `05-partition.sql` · `06-cleanup.sql` · `12-writing-scenario.sql` · `13-writing-scenario-cleanup.sql` · `14-grammar-context-game.sql` · `15-grammar-context-game-cleanup.sql` |
| 幂等 | 建表一律 `CREATE TABLE IF NOT EXISTS`；插数据一律 `INSERT ... ON DUPLICATE KEY UPDATE`；**改结构用 `information_schema` 判定后再执行**（见下方说明） |
| 禁止 | **不修改已发布的脚本**，只追加新脚本 |
| 注释 | 每个脚本头部写明：作用、前置版本、是否可回滚、回滚方法 |

> **约束**：SQL 真源只在 `02-代码开发/02-数据库/03-脚本/` 一处。部署包里的 SQL 由打包脚本镜像同步，**不要**在部署包里手工改。

> **改结构的幂等写法**：MySQL 的 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 需要 **8.0.29+**，本项目目标环境下限是 8.0，因此统一用
> `information_schema` 判定 + `PREPARE` 动态执行。**这条规则由 `05-公共资源/2026103017-DDL提取.py` 在生成时强制落地**——
> 源稿里写普通 `ALTER TABLE` 即可，提取器会自动改写成幂等形态。

### 12.2 初始化顺序

```
01-平台库初始化.sql       平台表 133 张 + 种子 7446 条（单库，先建平台表）
02-schema.sql              建表（17 张业务表 + 2 张基础设施表，含 4 张家庭与成员表）
03-init.sql                业务种子（教材版本 / 首个上下文 / 枚举字典 / 坐标树骨架）
04-fix.sql                 增量：7 张行为表加 child_id
05-partition.sql           创建当月 practice_record 分表
06-cleanup.sql             种子数据清理
12-writing-scenario.sql    增量：写作情境库建表 + 种子（F-WRT-03，独立增量脚本）
13-writing-scenario-cleanup.sql  增量：写作情境库种子清理（F-WRT-03）
14-grammar-context-game.sql     增量：语境库 + 玩法题库建表与种子（F-GRM-05 / F-GRM-04）
15-grammar-context-game-cleanup.sql  增量：语境库与玩法题库种子清理（F-GRM-05 / F-GRM-04）
```

> **为什么 12 / 13、14 / 15 是独立增量脚本**：铁律 2「变更走增量脚本，不改历史脚本」。
> `02-schema.sql` / `06-cleanup.sql` 已在新环境执行过，回改会导致环境间 schema 不一致；
> 因此新表走独立增量脚本，清理语句也不塞回 `06-cleanup.sql`，而是配套一个单独的清理脚本。

> **业务表口径（三口径，别混用）**：全库业务表 **24 张**（物理 27 张 / 归一 26 张）。
> 拆解：`02-schema.sql` 17 张 + `12-writing-scenario.sql` 1 张 + `14-grammar-context-game.sql` 4 张
> + `23-seed-notification-preference-and-ai-feedback.sql` 2 张；另有 2 张基础设施表
> （`study_id_sequence` / `study_schema_migration`）与按月分区表（`study_practice_record_202610` / `_202611`）。
> 该口径由 `05-公共资源/2026110407-表数口径检查.py` 钉死（改表后三处一起改）。
>
> **14 号脚本建 4 张表**：`study_sentence_context` / `study_word_context` /
> `study_grammar_game_question`（内容表，无 `child_id`）+ `study_grammar_game_record`（行为表，必带 `child_id`）。
> 它依赖 `study_word` 的既有种子（主例句直接取 `study_word.context_sentence`），
> 因此**必须排在 `09-seed-content.sql` 之后执行**。

### 12.4 迁移记录表

每次执行脚本后登记一条（脚本名 + 内容 SHA-256 + 执行时间）。**登记后禁止再改该脚本**——要改就追加新脚本。

```sql

  `duration_ms`  int DEFAULT NULL COMMENT '耗时毫秒',

) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='迁移执行记录';
```

### 13.2 种子数据原则

| 原则 | 说明 |
|------|------|
| 版权安全 | 题目与范文只用自编或公开授权（OpenStax、CC 授权教材、教育考试院公开样题）；范文用公开发表的获奖作品并标注出处 |

| 可重置 | 种子数据带独立前缀（如 `SEED_`），一键清理脚本可全部清除 |
