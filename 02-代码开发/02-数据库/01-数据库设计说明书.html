库与连接约定

1.1 单库策略（V1.1 变更：双库 → 单库）

库 内容 来源
jeecg-study 平台表（JeecgBoot 自带 133 张：sys_* qiankun_* onl_* airag_* 等）+ 业务表（本文件定义的 17 张） JeecgBoot v3.9.2 上游全量脚本（只改库名）+ 本项目业务表

为什么改成单库：

  1. 独立基座：jeecg-study 使用自己拉取的 JeecgBoot v3.9.2（02-代码开发/05-源码/01-JeecgBoot基座/），与 monitorV2 完全隔离，不共享 jeecg-boot 库——共享就谈不上「独立」。
  2. 多用户需要平台表：家长账号就是 JeecgBoot sys_user，孩子也是 sys_user（角色 study_kid）。平台表与业务表同库，关联查询与事务边界才简单。
  3. 不需要双数据源：@DS("study") 随之取消（ADR-015 取代 ADR-001）。

⚠️ 这改变了原 ADR-001（双数据源）。若将来要拆分，只需在 spring.datasource.dynamic.datasource 下新增一个 study 键并给业务 Mapper 加 @DS("study")，业务代码无需改动——底座的 dynamic-datasource 已经就位。

平台表来源：上游 jeecg-boot/db/jeecgboot-mysql-5.7.sql（133 张表 + 7446 条种子数据）， 由 05-公共资源/2026103018-平台库脚本.py 只改库名生成 03-脚本/01-平台库初始化.sql。 上游原文件保持不动，便于日后对照 v3.9.2 升级。

建表规约

项 约定 理由
表前缀 study_ 与平台表隔离，便于识别
主键 id varchar(32)，不用自增 内容 ID 具备业务语义（KPT-MA-0417），且跨库可引用
业务 ID 内容表用 xxx_code varchar(32) 存业务 ID（如 KPT-MA-0417），id 存 UUID 业务 ID 对外暴露且稳定，id 对内关联
逻辑删除 del_flag tinyint default 0 JeecgBoot 底座约定
审计字段 create_by / create_time / update_by / update_time JeecgBoot 底座约定，create_time/update_time 用 datetime
时间 一律 datetime，不用 timestamp 避免 2038 问题与隐式时区转换
金额/分数 decimal 浮点误差
JSON 字段 json 类型 MySQL 8 原生支持；半结构化内容（母题五段、拆解六层）
状态字段 tinyint + 枚举注释 避免 MySQL ENUM 改值时的锁表与迁移痛苦
索引 每个外键列建索引；组合索引遵循最左前缀 —
注释 每张表、每个字段必须有 COMMENT 交接与排错的基础
命名 全小写下划线 与 JeecgBoot 底座一致

注意：本库不建 tenant_id 列。系统是多家庭多用户但不做多租户（PRD N-05 改写版）：隔离维度是 child_id（孩子），不是租户。预留租户字段是典型的过度设计。

  `effective_from`   datetime     NOT NULL COMMENT '生效时间',

设计说明

点 说明
is_current 全表最多一行 is_current=1；切换上下文时旧行置 0，不删除
历史隔离 练习记录、错题携带 context_id，切换上下文后历史记录仍属旧上下文（系统设计 5.1）

单上下文约束 应用层保证「同时只有一行 is_current=1」，数据库层不加唯一约束（避免切换过程中的写冲突）

设计说明

点 说明
唯一错题池 全库唯一一张错题表。各模块不得另建错题表（PRD F-WRG-04）
error_cause NOT NULL 缺失直接抛 4001 错误，不允许空错因入库（PRD F-WRG-01）

next_review_at 排期写入与错题写入同事务（N-04）
upgrade_flag 课内背错的词置 1，课外线查询时加权（F-WRD-05）
copyright_type 自编 / 公开 / 授权。导入非自编题目时必须填 source_ref（PRD F-WRG-06）

judge_source 强约束：只有 rule / rule+model 两种取值，不存在 model。可在数据库层加 CHECK 约束做第二道保险（MySQL 8.0.16+ 支持 CHECK）。

CREATE TABLE `study_review_schedule` (

  `context_id`     varchar(32) NOT NULL COMMENT '全局上下文',
  `source_module`  varchar(16) NOT NULL COMMENT '来源模块',
  `schedule_date`  date        NOT NULL COMMENT '计划复习日期',
  `sort_score`     decimal(10,4) NOT NULL DEFAULT 0 COMMENT '排序分(薄弱度×遗忘风险)',
  `queue_date`     date        DEFAULT NULL COMMENT '物化队列日期(NULL=未物化)',
  `seq_no`         int         NOT NULL DEFAULT 0 COMMENT '队列内序号',
  `status`         tinyint     NOT NULL DEFAULT 1 COMMENT '状态 1待复习 2已完成 3已顺延',
  `completed_at`   datetime    DEFAULT NULL COMMENT '完成时间',
  `del_flag`       tinyint     NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`      varchar(50) DEFAULT NULL COMMENT '创建人',
  `create_time`    datetime    DEFAULT NULL COMMENT '创建时间',
  `update_by`      varchar(50) DEFAULT NULL COMMENT '更新人',
  `update_time`    datetime    DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_schedule_error_date` (`error_code`, `schedule_date`),

  KEY `idx_sched_date` (`schedule_date`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='统一复习排期(一条队列管全部模块)';

设计说明

点 说明
唯一键 (error_code, schedule_date) —— 同一条错题同一天只排一次
sort_score 薄弱度 × 遗忘风险，降序排前（系统设计 6.2）
queue_date 物化到某天后当天顺序不变；为 NULL 表示尚未进入某日队列
单日上限 50 超出的顺延到次日，由应用层控制（PRD 未定义上限，此处定为 50）

排期状态机（对应系统设计 6.1）：

当前 动作 下次复习 移出
当天 答错 当天 —
+1 天 答对 +3 天 —
+3 天 答对 +7 天 —
+7 天 答对 — 连续三次做对即移出
