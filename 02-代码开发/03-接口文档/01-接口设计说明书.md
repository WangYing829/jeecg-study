## 通用约定

### 1.1 路径与命名

| 项 | 约定 | 示例 |
|----|------|------|
| 根路径 | `/api/v1/study` | — |
| 资源命名 | 小写复数，短横线分隔 | `/error-pool` |
| 动作 | 仅在 REST 无法表达时用子资源动作 | `/error-pool/{id}/review` |
| 版本 | 路径段 `v1`；**不兼容变更升 v2**，兼容变更直接加字段 | — |
| 路径参数 | 业务 ID（`error_code` 等）而非自增 ID | `/error-pool/ERR-00000123` |
| 前缀 | 前端请求带 `/api/v1/study` 由 axios baseURL 统一拼接 | — |

### 1.2 统一响应体

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "result": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `success` | boolean | 是否成功 |
| `code` | number | 0 = 成功；非 0 见错误码表 |
| `message` | string | 面向人的提示文案 |
| `result` | object \| array \| null | 业务数据，失败时为 null |

> 与 JeecgBoot 底座的 `ApiResult` 保持一致，不另造格式。

### 1.3 分页约定

**请求参数**：

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `pageNo` | number | 1 | 页码，从 1 开始 |
| `pageSize` | number | 10 | 每页条数，可选 10/20/50/100 |
| `order` | string | — | 排序，格式 `column,asc\|desc` |

**响应结构**：

```json
{
  "records": [],
  "total": 128,
  "pageNo": 1,
  "pageSize": 10,
  "pages": 13
}
```

> 字段名与 JeecgBoot 的 `IPage` 对齐（`records` / `total` / `current` / `size`），前端表格组件可直接消费。

### 1.4 鉴权

| 项 | 约定 |
|----|------|
| 机制 | JeecgBoot 底座的 Shiro + JWT，Header `X-Access-Token` |
| 身份 | 孩子（角色 `study_kid`）/ 家长（角色 `study_parent`）/ 管理员（`admin`） |
| 角色隔离 | 家长角色**不得**调用练习作答接口；孩子角色**不得**调用家长端接口。服务端按角色校验，不依赖前端 |
| 多用户 | **多家庭 / 多孩子 / 多家长**：按 `child_id` 做强制数据隔离；不做多租户、不预留租户字段。详见「认证与多用户」 |
| 家长登录 | 底座原生 `POST /sys/login`，**不新增**接口 |
| 孩子登录 | `POST /api/v1/study/kid/login`（PIN），两步流程见「认证与多用户」 |

### 1.5 请求约定

| 项 | 约定 |
|----|------|
| Content-Type | `application/json;charset=UTF-8`（文件上传用 `multipart/form-data`） |
| 字段命名 | 驼峰 `camelCase`（与数据库下划线通过 MyBatis-Plus 映射） |
| 日期时间 | `yyyy-MM-dd HH:mm:ss`；纯日期 `yyyy-MM-dd` |
| 枚举 | 传字符串码（如 `CONCEPT`），不传数字 |
| 布尔 | 传 `true` / `false` |
| 空值 | 不传该字段 = 不修改；传 `null` = 置空（仅 PATCH 语义接口） |

## 错误码表

### 2.1 业务错误码

| 码 | 含义 | HTTP | 触发场景 |
|----|------|------|----------|
| 4001 | 缺少错因 | 400 | 提交练习未选错因 |
| 4002 | 前置步骤未完成 | 400 | 写作未过提纲提交初稿 |
| 4003 | 违反练习顺序 | 400 | 未作答就请求解析 |
| 4004 | 上下文未配置 | 400 | 首次使用未配置地区/教材 |
| 4005 | 判定策略缺失 | 500 | 该题型未注册 `JudgeStrategy` |
| 4006 | 版权信息不完整 | 400 | 导入非自编题目未填 `source_ref` |
| 4007 | 母题结构不完整 | 400 | 母题五段缺任一段 |
| 4008 | 变式不足 | 400 | 过关要求 N 道变式但不足 |
| 4009 | 家庭码不正确 | 400 | 孩子端 `POST /kid/lookup` 家庭码校验失败 |
| 4010 | 越权 | 403 | 家长访问非关联孩子的数据 / 孩子访问他人数据 |

> **4010 为什么不是 404**：若越权访问返回 404，攻击者可借「404 vs 200」区分**资源是否存在**（资源探测 / 枚举 childCode）。返回统一的 **4010** 表示「你无权访问」，无论该资源是否存在，响应形态完全一致，无法反推资源存在性。
>
> 触发场景：家长请求的 `childCode` 不在 `study_parent_child_rel` 关联集合内；孩子 token 的 `childId` 与目标资源归属不一致。
>
> 业务错误码一律返回 **HTTP 200 + `code != 0`**（见 2.2 约定），表中 HTTP 列仅标注语义状态。

### 2.2 通用 HTTP 码

| 码 | 含义 |
|----|------|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / token 失效 |
| 403 | 无权限（角色不符或缺权限码） |
| 404 | 资源不存在 |
| 405 | 方法不允许 |
| 500 | 服务端异常 |

> **约定**：业务错误一律返回 **HTTP 200 + `code != 0`**，由前端按 `success` 判断；仅鉴权与路由错误使用 4xx/5xx。这与 JeecgBoot 的 `Result` 处理一致。

> `generatedBy` 显式暴露生成方式：`RULE` 表示结构与答案全由规则产出；`RULE+MODEL` 表示结构与答案仍由规则产出，仅自然语言表述经模型润色。**任何情况下 `generatedBy` 都不可能是 `MODEL`**（红线 R-02）。

## 认证与多用户

> 本章依据《多用户改造契约》§1、§3、§5。系统已从「单用户」改为**多家庭 / 多孩子 / 多家长**，本章是接口层唯一依据。

### 10.1 三类身份与凭据

| 身份 | 载体 | 凭据 | 登录端点 | 权限码前缀 |
|---|---|---|---|---|
| 家长 | `sys_user` + 角色 `study_parent` | 用户名 + 密码 | `POST /sys/login`（底座原生） | `study:parent:*` |
| 孩子 | `sys_user` + 角色 `study_kid` + `study_child` 档案 | **PIN**（4–6 位数字） | `POST /api/v1/study/kid/login` | `study:kid:*` |
| 管理员 | `sys_user` + 底座 `admin` 角色 | 用户名 + 密码 | `POST /sys/login` | `study:*`（全部） |

> **关键设计：孩子也是 `sys_user`。** Shiro/JWT、Redis 会话、`@RequiresPermissions`、菜单权限**全部复用底座现成能力**，不新增第二套认证栈。孩子只是**登录方式**不同（PIN 代替密码），登录成功后签发的 token 与家长**完全同构**。

### 10.2 家长登录：不新增接口

家长直接用 JeecgBoot 原生登录 `POST /sys/login`，**本项目不新增任何家长登录接口**。理由：

| # | 理由 |
|---|---|
| 1 | 复用底座现成的 Shiro + JWT + Redis 会话、密码策略、登录审计、验证码，不重复造轮子 |
| 2 | 家长就是 `sys_user` + 角色 `study_parent`，底座 `/sys/login` 签发的 token 与孩子 token 同构，前端拦截器统一 |
| 3 | 不新增接口 = **不引入第二套认证栈**，避免两套令牌语义、过期策略、踢下线逻辑不一致 |
| 4 | 底座 `/sys/login` 的请求/响应体**保持原样**，study 模块不包裹、不改字段 |

登录后家长进入**家长端**（独立布局，与学习端一样不吃管理端顶栏），首页展示「我关联的孩子」卡片列表。家长切换查看哪个孩子是**切换视角**，不是切换身份。

### 10.3 孩子登录：两步流程

```
孩子端打开
  ↓
① POST /api/v1/study/kid/lookup   { familyCode }
  → 校验家庭码 → 返回该家庭孩子的候选列表（仅 id / nickname / avatar）
  → 失败 4009「家庭码不正确」
  ↓
② POST /api/v1/study/kid/login    { childId, pin }
  → 校验孩子状态 + PIN（连续失败 5 次锁 10 分钟）
  → 复用底座 JwtUtil.sign(username, password, CLIENT_TYPE_APP) + Redis 存 token
  → 返回 token + 孩子信息 + 绑定的家长昵称列表（仅昵称）
```

> **为什么要有「家庭码」这一步**：孩子端不能公开列出所有孩子（信息泄露），也不能暴露底座登录页。家庭码由家长在家长端生成/重置，**明文只在生成时返回一次**。

**POST /kid/lookup — 家庭码 → 候选孩子**

```json
{ "familyCode": "K7M2QP" }
```

```json
{
  "success": true, "code": 0, "message": "ok",
  "result": {
    "children": [

    ]
  }
}
```

> **只返回 id / nickname / avatar**——不返回性别、年级、生日、账号名、PIN、家庭成员数量。家庭码泄露时，攻击者能拿到的信息严格受限。

**POST /kid/login — PIN 登录**

```json
{ "childId": "c-7b31d9", "pin": "2468" }
```

```json
{
  "success": true, "code": 0, "message": "ok",
  "result": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "childId": "c-7b31d9",
    "childCode": "CHD-000001",
    "nickname": "小满",
```

### 10.4 PIN 与家庭码的存储

| 项 | 孩子 PIN | 家庭码 |
|---|---|---|
| 形态 | 4–6 位数字 | 6 位大写字母数字 |
| 哈希 | `PasswordUtil.encrypt(childCode, pin, pinSalt)` | `PasswordUtil.encrypt(familyCode, code, salt)` |
| 盐列 | `study_child.pin_salt` | `study_family.family_code_salt` |
| 明文 | 仅创建 / 重置时返回一次 | 仅生成 / 重置时返回一次 |
| 强度要求 | 不要求复杂度（低龄孩子），靠失败锁定兜底 | 同款哈希实现 |

> **两者都不存明文**，哈希与底座密码同款（用户名 + 密码 + 盐），可复用底座的加盐哈希与校验逻辑。
> 校验用「按库中盐重算哈希并比对」，不做明文比对。

### 10.5 免认证路径与 Shiro 排除

| 路径 | 认证 | 登记位置 |
|---|---|---|
| `/api/v1/study/kid/lookup` | **免认证** | 底座 `shiro.excludeUrls` + 方法 `@IgnoreAuth` |
| `/api/v1/study/kid/login` | **免认证** | 同上 |

> 免认证**仅限这两个路径**；其余 study 接口一律需要 token，底座 `/sys/login` 也照常走 Shiro 过滤链。
> 两个免认证接口**自身仍做校验**：家庭码哈希比对、PIN 哈希比对、失败次数与锁定。

### 10.6 PIN 失败锁定

| 项 | 约定 |
|---|---|
| 计数 | `study_child.pin_fail_count`，**连续**失败计数 |
| 锁定阈值 | 连续 **5** 次失败 |
| 锁定时长 | **10** 分钟（写入 `pin_lock_until`） |
| 锁定期间 | 直接拒绝（不再比对 PIN），提示「请稍后再试」 |
| 成功登录 | `pin_fail_count` 归零、`pin_lock_until` 清空 |
| 家长重置 PIN | 同时清零失败计数与锁定 |

> 计数与锁定按 `child_id` 维度，不按 IP——锁定的是**这个孩子的 PIN**，不影响同家庭其他孩子。

### 10.7 身份 → 可见数据范围

| 身份 | 可读范围 | 判定来源 | 实现 |
|---|---|---|---|
| 管理员 | **全部** | — | 不加过滤条件 |
| 家长 | **仅 `study_parent_child_rel` 中与自己关联的 `child_id`** | 每次请求实时查关系表 | `ChildScopeHelper.childIdsOf(currentUserId)` 强制拼进 where |
| 孩子 | **仅自己的 `child_id`** | JWT 携带 `childId` | 令牌附加 claim 直接作为过滤条件 |

> **Controller 不接受前端传来的 `childId` 作为唯一依据**——家长侧必须与关系表**求交集**，防止越权。
> 违反隔离 → **4010**（不是 404，避免资源探测）。
> **家长之间的隔离**：家长 A 看不到家长 B 的反馈、评价、申诉记录；**禁止家庭内比较**（R-04 强化）。

**令牌载荷**

| 身份 | 附加 claim |
|---|---|
| 孩子 | `childId`、`childCode`、`role=study_kid` |
| 家长 | `role=study_parent` |
| 会话 | Redis，TTL 与底座一致；孩子端用 `CLIENT_TYPE_APP` 更长的过期时间 |

## 判对错响应契约

> 这是前后端之间最关键的一份契约，直接决定红线 R-01、R-02 能否成立。

### 11.1 字段契约

| 字段 | 类型 | 必返 | 取值 | 前端用途 |
|------|------|------|------|----------|
| `contentId` | string | 是 | — | 定位内容 |
| `correct` | boolean | 是 | — | 对错反馈 |
| `source` | string | 是 | `rule` / `rule+model` | 决定是否显示「AI 辅助讲解，判定以规则为准」角标 |
| `basis` | string | 是 | 人可读判定依据 | 「依据」折叠区内容；申诉时回传 |
| `detail` | object | 否 | 判定明细（期望/实际/容差/命中规则） | 「依据」折叠区明细 |
| `explain` | object | 否 | `{type, text}` 或 `{type, sections[]}` | 解析区内容 |
| `explainStatus` | string | 是 | `OK` / `TIMEOUT` / `UNAVAILABLE` / `SKIPPED` | 解析区降级提示 |
| `errorId` | string | 答错时 | 错题业务 ID | 错题池引用 |
| `nextReviewAt` | string | 答错时 | `yyyy-MM-dd` | 「明天再见」提示 |
| `masteryState` | number | 是 | 1–4 | 掌握度可视化 |

### 11.2 三条不可违反的规则

| # | 规则 | 校验方式 |
|---|------|----------|
| 1 | `source` **不可能**等于 `model` | 服务端枚举约束 + 数据库 CHECK + 单元测试断言 |
| 2 | `correct` 与 `basis` 必须同源 | `correct` 由 `JudgeStrategy` 产出，`basis` 由同一策略产出 |
| 3 | 解析内容**只能**在作答后出现 | `/practice/{type}/next` 不返回答案与解析；`/explanation` 未作答返回 4003 |

### 11.3 前端消费规则

| 场景 | 前端行为 |
|------|----------|
| 答对 | 显示成功反馈；**不**自动展开解析（让孩子自己点「看解析」） |
| 答错 | 先显示「错在哪一步」（来自 `basis` + `detail`），再提供「看完整解析」入口 |
| `source == "rule+model"` | 解析区顶部显示「AI 辅助讲解，判定以规则为准」 |
| `explainStatus != "OK"` | 显示降级文案「讲解暂时不可用，先看看思路」；**不显示错误弹窗** |
| 申诉 | 任何判定都提供「我不同意」入口，提交后返回 `basis` 全文 |

## 幂等与并发

### 12.1 幂等约定

| 接口 | 幂等方式 |
|------|----------|
| `POST /practice/answer` | 携带 `sessionId` + `contentId`；服务端对同一会话的同一内容**只判一次**，重复提交返回首次结果 |
| `POST /review/queue/{code}/complete` | 同一 `errorCode` + 同一 `scheduleDate` 重复提交，**不重复推进排期** |
| `POST /word/feedback` | 同一词 10 秒内的重复反馈只生效一次 |
| `POST /context` | 重复提交相同上下文不产生新记录 |
| `POST /eye/session/{id}/heartbeat` | 按 `sessionId` 累加，天然幂等 |

### 12.2 并发约定

| 场景 | 策略 |
|------|------|
| 同一错题被多端同时复习 | 排期推进用 `SELECT ... FOR UPDATE` 锁定该错题行，保证 `correct_streak` 不重复累加 |
| 队列物化并发 | 以 `queue_date` 为键做唯一索引，插入冲突则跳过（`INSERT IGNORE`） |
| 错因更新与掌握度更新 | **同一事务**（N-04） |
| 上下文切换 | 切换时对 `study_context` 加行锁，保证只有一行 `is_current=1` |
| 坐标树版本切换 | 插入新版本节点与失效旧节点在同一事务 |

### 12.3 事务边界

```
事务开始
  ├─ 判定（纯计算，无 IO）
  ├─ 写 study_practice_record
  ├─ 答错时：写 study_error_pool + 写 study_review_schedule + 更新掌握度
  └─ 事务提交
  ↓
事务外（可失败，不影响上面）
  └─ AI 讲解生成 → 异步补写 explain 字段
```

> **重要**：AI 调用**不在事务内**。解析内容先返回「生成中」占位，或由前端在 `explainStatus=SKIPPED` 时重试一次 `GET /explanation`。

### 12.4 既有接口的数据范围改造

系统改为多家庭多用户后，**既有接口路径一律不改**（避免大面积破坏），只加过滤维度。三条硬规则：

| # | 规则 | 说明 |
|---|------|------|
| 1 | **学习端接口强制按 `child_id` 过滤** | 练习、错题、排期、背单词、母题、语法、写作、护眼等**全部学习端接口**，在 **Service 层强制**拼 `child_id` 条件，不依赖前端传参 |
| 2 | **家长端只读接口接受 `childCode`，但必须与关系表求交集** | 前端传的 `childCode` 只作为**候选**，必须与 `study_parent_child_rel` 的关联集合**求交集**后才能进 where，**不得直接信任前端参数** |
| 3 | **越权统一返回 4010** | 不返回 404，避免资源探测（见 2.1） |

**改造清单**（下列均为**既有接口**，接口本身已在第 3 章总表登记，此处不重复计数）：

| 方法 | 路径 | 改造 | 需求 |

| GET | `/mastery/weak-points` | 接受 `childCode`，与关系表求交集 | F-PAR-01、F-FAM-07 |
| GET | `/practice/records` | 接受 `childCode`，与关系表求交集 | F-PAR-01、F-FAM-07 |
| GET | `/practice/stats/today` | 接受 `childCode`，与关系表求交集 | F-PAR-01、F-FAM-07 |

> **过滤维度落在 Service 层**：Controller 不接受前端传来的 `childId` 作为唯一依据（见 10.7）。孩子的 `child_id` 取自 JWT 附加 claim，家长的 `child_id` 集合取自 `ChildScopeHelper.childIdsOf(currentUserId)`。

### 13.1 家长侧 `study:parent:*` 与孩子侧 `study:kid:*` 的划分

| 维度 | 家长侧 `study:parent:*` | 孩子侧 `study:kid:*` |
|---|---|---|
| 承载角色 | `study_parent`（家长账号，密码登录） | `study_kid`（孩子账号，PIN 登录） |
| 能做什么 | 家庭与成员管理、孩子档案管理与 PIN 重置、家长↔孩子关联、只读查看关联孩子的数据、提交反馈与申诉 | 查看自己的信息、退出登录 |
| 不能做什么 | **不得**作答、不得改错因、不得查看未关联孩子的数据 | **不得**查看其他孩子的数据、不得管理家庭成员 |
| 数据范围 | 仅 `study_parent_child_rel` 中关联的 `child_id` | 仅 JWT 携带的**自己的** `child_id` |
| 免认证接口 | 无 | `POST /kid/lookup`、`POST /kid/login`（不持权限码） |

> **权限码 ≠ 数据范围**：权限码回答「能不能调这个接口」，数据范围回答「能看到哪些行」。两者**都要过**——持有 `study:parent:child:query` 但请求非关联孩子的 `childCode`，仍然返回 **4010**。
> **家长端权限码不代表「能看所有孩子」**：家长 A 持有完整的 `study:parent:*`，也只能看到自己关联的孩子。

## AI 降级契约

### 14.1 降级矩阵

| 接口 | AI 不可用时 | 返回 |
|------|--------------|------|
| `POST /practice/answer` | 判定照常，解析降级 | `explain: null`, `explainStatus: "UNAVAILABLE"` |
| `GET /practice/{id}/explanation` | 返回静态讲解（题干→思路→步骤→答案的模板） | `explainStatus: "SKIPPED"` |
| `POST /grammar/transform` | 语料库命中则正常；未命中返回提示 | `source: "library"` 或 `variants: []` + 提示文案 |
| `POST /grammar/detect` | 规则命中则正常；未命中返回「暂未识别」 | `errors: []` + `explainStatus: "UNAVAILABLE"` |
| `POST /writing/train/draft` | 返回可规则化的差异维度（字数、句长、连接词覆盖） | `source: "rule"`, `diffList` 最多 3 条 |
| `POST /math/mother/{code}/variants` | 结构与答案照常生成，仅表述用模板文案 | `generatedBy: "RULE"` |

### 14.2 约定

| 项 | 约定 |
|----|------|
| 超时 | 3 秒 |
| 重试 | 服务端不重试；前端对 `explainStatus != OK` 最多重试 1 次 |
| 熔断 | 连续 10 次调用失败后熔断 60 秒，期间直接走降级路径 |
| 观测 | 记录调用耗时、成功率、降级次数；降级率 > 20% 告警 |
| 用户可见 | 降级**不弹错误**。用中性文案「讲解暂时不可用，先看看思路」代替技术错误 |
| 隐私 | 不发送真实姓名、学校、年级等身份信息到模型；只发题干、选项、知识点 ID |

> **隐私补充**：本项目全部数据留在本地（N-06）。若后续接入外部模型 API，须在《部署方案》中同步更新数据边界说明，并取得明确同意。
