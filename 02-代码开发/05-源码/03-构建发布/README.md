### 数据库初始化顺序（单库，两段脚本）

```
1. 01-平台库初始化.sql   ← 平台表 133 张 + 7446 条种子（由 2026103018 生成）
2. 02-schema.sql         ← 业务表 17 张（含 4 张家庭与成员表）
3. 03-init.sql           ← 业务种子（当前只有规格占位）
4. 04-fix.sql            ← 增量：13 张表加 child_id
5. 05-partition.sql      ← 分表
```

> **顺序不能换**：平台表必须先建（业务表与 `sys_user` 有外键语义依赖）。

## 3 构建注意事项

| 项 | 说明 |
|---|---|
| **SQL 真源** | `../../02-数据库/03-脚本/`；DDL 由 `2026103017-DDL提取.py` 从设计源稿生成，平台库脚本由 `2026103018-平台库脚本.py` 生成 |
| **迁移幂等** | 每次部署执行 `04-fix.sql` + `05-partition.sql`，并写 `study_schema_migration` 记录 |
| **脚本校验和** | 脚本内容 SHA-256 登记入库，防止事后改脚本 |
| **后端常驻** | 用 Windows 服务（nssm）跑，**不要**用 WMI/`Start-Process` 直接起 java——它不脱离调用方控制台，任务结束就被杀掉 |
| **换 jar 前** | 先停服务再覆盖，运行中的 java 独占 jar 句柄 |
| **前端产物** | `dist/` 不入库；构建后由 nginx 指向 |
| **含中文的 `.ps1`** | 必须带 UTF-8 BOM，否则 PS 5.1 按 GBK 解码会吞换行符，报出无关的 `ParserError` |
| **基座构建** | 后端 `mvn -pl jeecg-module-study -am package`；前端在 `jeecgboot-vue3/` 内 `pnpm build` |
| **Windows 长路径** | 基座路径深，clone/checkout 前先 `git config --global core.longpaths true` |

## 4 产物边界

> 判据：**这个文件丢了能不能从别处重建？** 能重建 → 产物（不入库）；不能重建 → 自研资产（必须入库）。

| 类别 | 例子 | 入库 |
|---|---|---|
| 源码 | Java / Vue / SQL 脚本 | ✅ |
| **基座上游源码** | `01-JeecgBoot基座/` | ⚠️ 见下方说明 |
| 设计文档 | `.md` 源稿 + 生成的 `.html` | ✅ |
| 构建产物 | `target/`、`dist/`、`node_modules/` | ❌ |
| 报告生成器与校验脚本 | `05-公共资源/*.py` | ✅ |
| 校验台 | `03-测试验证/04-自动化测试/2026103014-校验台.html` | ✅ |
| 临时输出 | `_shots/`、`*.log`、`*.bak` | ❌ |

> **基座入库策略**：上游代码自带 `.git`，是独立 Git 仓库。**不要**把它连同上游 `.git` 一起提交进本仓库历史；
> 本仓库**只跟踪本项目的改动**（相对上游 v3.9.2 的**修改 / 新增 / 删除**），上游历史留在基座自己的 `.git` 里。
> 改动清单与导出 / 还原命令见 [`../README.md` §4](../README.md)，工具是 `05-公共资源/2026103019-基座同步.py`。
