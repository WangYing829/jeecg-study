1.3 布局差异

端 布局 说明

孩子端登录页是唯一的静态路由（ADR-039）：孩子没有账号密码，只有家庭码 + PIN， 登录页必须在无登录态下可达；而动态菜单（sys_permission → queryByUser）要先有 token 才下发， 挂在菜单里的页面孩子根本进不去。因此它走 jeecgboot-vue3/src/router/routes/index.ts 的 StudyKidLoginRoute（meta.ignoreAuth = true，进 basicRoutes）， 不在 sys_permission 里再建一行 —— 同一个 path 注册两次会让 vue-router 行为不可预期。 断言 StudyInterfacePageTest#kidLoginMustBeStaticRoute 同时守这两头（有静态路由 + 不在 DB 里）。

带 :code 的三级路由一律 hidden=1：DB 菜单的 url 原样就是 vue-router 的 path （SysPermissionController:794），侧边栏渲染出来会是一个字面量 :code 的死链。 这些页面从上级页面按钮进入。

家长端为什么不用 layouts/parent：上游动态菜单永远无法用自定义布局（见 routeHelper.ts:139-162）， 因此家长端改用 StudyParentShell 全屏固定层（position: fixed; inset: 0; z-index: 1100）压住管理端外壳， 并自带页面导航与登出（ADR-033）。上文 §6.4 关于 layouts/parent/index.vue 的规划已被此决策取代。 导航项已从 3 个扩到 5 个（新增「家庭成员」「孩子档案」；「关联管理」是档案页的下一级，不进 nav）。 用户操作说明见《用户手册 · 系统功能使用说明》，开发规范见《技术手册 · 系统开发使用说明》。

管理端页面详规

全部遵循《产品设计规范》第 9.1 节列表页骨架：PageWrapper（内容区 margin:16px）→ useListPage + BasicTable（查询区 / 工具栏 / 分页 / 表格设置均由组件内置）→（可选）统计区 → 操作列插槽 StudyActionColumn → 弹窗。 禁止手写 a-table、禁止另做分页组件、禁止把查询表单与表格混排（规范 9.1 / 8.2 / 8.9）。

⚠ 实现口径（ADR-041）：9 个内容维护页的读接口返回的是裸数组 / {items,total}， 不是 useListPage 期望的 {records,total} 服务端分页体 ⇒ 统一走 ManageContentPage.vue 内核的 BasicTable 本地数据模式（dataSource + 组件内置分页）， 不硬套 useListPage（硬套会让分页看起来对、实际取不到数）。 表格列由薄配置页提供，操作列由内核统一补齐并走 StudyActionColumn；管理端表单沿用基座默认 horizontal。

家长 A ↔ 家长 B 互不可见（反馈、评价、申诉一律隔离），且不做任何家庭内比较 study_parent_child_rel 4010

步骤 界面 接口 正常结果 异常处理

项 规则

9.2 实现要点

要点 实现
计时基准 服务端心跳。客户端每 30 秒上报一次 active；服务端按心跳累加（接口设计 8.2）
阈值 context.eyeIntervalMin（默认 15 分钟；低年级 10、高年级 20）
阻断 遮罩 z-index 高于所有内容；不可自动消失，必须点击确认
引导文案 「看向 6 米外的地方，保持 20 秒」——具体动作，不只写「休息一下」
蓝光过滤 容器 filter: sepia(...) 类滤镜；状态存 localStorage + 服务端
切后台 visibilitychange 隐藏时暂停心跳，恢复时重置计时（离开屏幕不算用眼）
页面卸载 beforeunload 上报会话结束，避免时长漏记
