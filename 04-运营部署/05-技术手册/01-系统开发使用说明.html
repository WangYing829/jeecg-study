后端开发规范

新增域

后端开发规范

后端开发规范：新增一个域或一个端点的完整步骤。

5.1 分层职责与红线

层 允许 禁止
controller 只依赖 Service 接口；返回 Result<T> ❌ 注入 Mapper；❌ 接受前端传来的 childId 作为唯一依据
service 业务编排；拼 child_id 过滤；事务边界 ❌ 跨域直接访问别的域的 Mapper（跨域只读点要有显式白名单）
mapper 继承 BaseMapper 或写注解式 @Select ❌ 在 Mapper 里做业务判断
entity 继承 JeecgEntity；表名加 study_ 前缀 ❌ 业务表混入平台表命名
vo 面向前端出参；字段口径统一用 items ❌ 直接返回 Entity

5.2 新增一个域的八步

  1. 建包：org.jeecg.modules.study.<域>.{controller,entity,mapper,service,vo}。
  2. 写实体：继承 JeecgEntity，@TableName("study_xxx")。
  3. 写 Mapper：继承 BaseMapper；注解式 SQL 必须满足排序确定性（见 §7.5）。
  4. 写 Service：业务逻辑 + child_id 强制过滤（用 ChildScopeHelper / scope 包）。
  5. 写 Controller：返回 Result<T>；权限码 study:<资源>:<动作>；不接收前端 childId 作为唯一依据。
  6. 建表：在 03-脚本/ 下新增增量脚本（不改历史脚本），并在《数据库设计说明书》登记字段表。
  7. 灌种子：同样走新增量脚本，幂等。
  8. 补菜单与权限：在菜单种子脚本里加 sys_permission 行（路由 + 组件 + 权限码）。

5.3 数据范围隔离：不可省的强制过滤

身份 可读范围 实现落点
管理员 全部 —
家长 仅 study_parent_child_rel 中与自己关联的 child_id Service 层强制拼 where
孩子 仅自己的 child_id 由服务端按 sys_user 实时反查
  • 家长侧必须与关系表求交集，不能直接用前端传的 childCode。
  • 越权一律返回 4010（不用 404，避免资源探测）。
  • 内容表不加 child_id（7 张内容表全局共享），行为表必须加（按孩子隔离）—— 改表时别把内容表也加了。

5.4 错误码与统一异常出口

码 含义 触发场景
4001 缺少错因 提交练习未选错因
4002 前置步骤未完成 写作未过提纲提交初稿
4003 违反练习顺序 未作答就请求解析
4004 上下文未配置 首次使用未配置地区 / 教材
4007 母题结构不完整 母题五段缺任一段
4009 家庭码不正确 孩子端家庭码校验失败
4010 越权 家长访问非关联孩子的数据 / 孩子访问他人数据

业务错误码一律 HTTP 200 + code != 0。 study 域的错误码出口由 @RestControllerAdvice（StudyExceptionAdvice）统一承接：HIGHEST_PRECEDENCE + basePackages 限定到 study 域，抢回 4001 / 4009 / 4010 —— 否则会被上游全局异常处理器改写掉。

5.5 类简单名必须全局唯一

MyBatis-Spring 用「类名去首字母小写」当 bean 名 → 同名直接 ConflictingBeanDefinitionException，整个 Spring 上下文起不来。

  • 规范：同域内 StudyXxxService / StudyXxxServiceImpl；跨域重复的 Mapper 按域加前缀（如 StudyErrorQuestionMapper）。
  • 闸门：python 05-公共资源\2026103020-类名唯一性检查.py（退出码 2 = 有启动级冲突）。

5.6 测试里的一个硬约定

一个类实现多个 Service 契约时，测试的 @MockBean 必须指向具体实现类，不能指向其中任一接口 —— 否则 @MockBean 按类型替换会把唯一的 Bean 整体顶掉，另一个契约无人实现，整个 Spring 上下文起不来。见 ADR-029。

6.3 护眼状态的跨组件传递：只准用共享单例

components/study/StudyEyeState.ts：

// 工厂：只造状态，❌ 不得注册任何 onMounted / onBeforeUnmount
export function useStudyEyeState(): StudyEyeState { … }

// 单例入口：模块级缓存，首调创建，之后复用同一实例
export function useSharedEyeState(): StudyEyeState { … }
规则 原因
状态工厂不得注册生命周期钩子 onMounted 绑定的是「当前正在 setup 的组件实例」→ 钩子会归第一个调用者，路由切换后静默停摆
会话生命周期归学习端布局 布局 onMounted(() => eye.start()) / onBeforeUnmount(() => eye.stop())
禁用 provide/inject 方向是「父 provide → 子 inject」，而布局是页面的子组件 → 页面永远 inject 不到
禁用 defineExpose + 模板 ref 模板 ref 拿到深层 reactive 代理，会自动解包嵌套 ref → .value 恒 undefined
模板里的 ref 必须挂在 setup 返回值顶层 Vue 只解包顶层 ref；嵌套普通对象属性拿到的是 Ref 实例本身 → 恒为真

固化断言：StudyEyeSharedStateTest（4 条）。

6.4 答案区不渲染到 DOM（红线 R-01）

练习页的解析/答案区在初始态不进入 DOM（不是 display:none、不是 v-show），使 R-01 可以用 DOM 查询直接验收。

<!-- ✅ 初始态不在 DOM -->
<p v-if="explainText" class="study-practice__explain-text">{{ explainText }}</p>

这条是发布否决项，由 RedLineAssertionTest 的 R01-3 静态扫描 + 浏览器实测双重把关。

6.5 断网提示与重试（F-BASE-08）
