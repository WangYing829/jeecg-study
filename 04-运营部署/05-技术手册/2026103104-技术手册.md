```powershell
# 把脚本写成 UTF-8 无 BOM 临时文件再 source（PS 5.1 管道会吞中文）
[IO.File]::WriteAllText("$env:TEMP\seed.sql", (Get-Content -Raw -Encoding UTF8 $src), (New-Object Text.UTF8Encoding($false)))
& mysql -uroot '-p<pwd>' --default-character-set=utf8mb4 -D 'jeecg-study' -e "source C:/Users/<user>/AppData/Local/Temp/seed.sql"
```

## 后端开发规范

后端开发规范：新增一个域或一个端点的完整步骤。

### 5.1 分层职责与红线

| 层 | 允许 | 禁止 |
|---|---|---|
| `controller` | 只依赖 **Service 接口**；返回 `Result<T>` | ❌ 注入 Mapper；❌ 接受前端传来的 `childId` 作为唯一依据 |
| `service` | 业务编排；**拼 `child_id` 过滤**；事务边界 | ❌ 跨域直接访问别的域的 Mapper（跨域只读点要有显式白名单） |
| `mapper` | 继承 `BaseMapper` 或写注解式 `@Select` | ❌ 在 Mapper 里做业务判断 |
| `entity` | 继承 `JeecgEntity`；表名加 `study_` 前缀 | ❌ 业务表混入平台表命名 |
| `vo` | 面向前端出参；**字段口径统一用 `items`** | ❌ 直接返回 Entity |

### 5.2 新增一个域的八步

1. **建包**：`org.jeecg.modules.study.<域>.{controller,entity,mapper,service,vo}`。
2. **写实体**：继承 `JeecgEntity`，`@TableName("study_xxx")`。
3. **写 Mapper**：继承 `BaseMapper`；注解式 SQL 必须满足**排序确定性**（见 §7.5）。
4. **写 Service**：业务逻辑 + **`child_id` 强制过滤**（用 `ChildScopeHelper` / `scope` 包）。
5. **写 Controller**：返回 `Result<T>`；权限码 `study:<资源>:<动作>`；**不接收前端 `childId` 作为唯一依据**。
6. **建表**：在 `03-脚本/` 下**新增增量脚本**（不改历史脚本），并在《数据库设计说明书》登记字段表。
7. **灌种子**：同样走新增量脚本，**幂等**。
8. **补菜单与权限**：在菜单种子脚本里加 `sys_permission` 行（路由 + 组件 + 权限码）。

### 5.3 数据范围隔离：不可省的强制过滤

| 身份 | 可读范围 | 实现落点 |
|---|---|---|
| 管理员 | 全部 | — |
| 家长 | 仅 `study_parent_child_rel` 中与自己关联的 `child_id` | Service 层强制拼 where |
| 孩子 | 仅自己的 `child_id` | 由服务端按 `sys_user` 实时反查 |

- 家长侧**必须与关系表求交集**，不能直接用前端传的 `childCode`。
- 越权一律返回 **4010**（**不用 404**，避免资源探测）。
- **内容表不加 `child_id`**（7 张内容表全局共享），**行为表必须加**（按孩子隔离）—— 改表时别把内容表也加了。

### 5.4 错误码与统一异常出口

| 码 | 含义 | 触发场景 |
|---|---|---|
| 4001 | 缺少错因 | 提交练习未选错因 |
| 4002 | 前置步骤未完成 | 写作未过提纲提交初稿 |
| 4003 | 违反练习顺序 | 未作答就请求解析 |
| 4004 | 上下文未配置 | 首次使用未配置地区 / 教材 |
| 4007 | 母题结构不完整 | 母题五段缺任一段 |
| 4009 | 家庭码不正确 | 孩子端家庭码校验失败 |
| **4010** | **越权** | 家长访问非关联孩子的数据 / 孩子访问他人数据 |

> 业务错误码一律 **HTTP 200 + `code != 0`**。
> study 域的错误码出口由 `@RestControllerAdvice`（`StudyExceptionAdvice`）统一承接：`HIGHEST_PRECEDENCE` + `basePackages` 限定到 study 域，**抢回** 4001 / 4009 / 4010 —— 否则会被上游全局异常处理器改写掉。

### 5.5 类简单名必须全局唯一

MyBatis-Spring 用「类名去首字母小写」当 bean 名 → **同名直接 `ConflictingBeanDefinitionException`，整个 Spring 上下文起不来**。

- 规范：同域内 `StudyXxxService` / `StudyXxxServiceImpl`；跨域重复的 Mapper 按域加前缀（如 `StudyErrorQuestionMapper`）。
- 闸门：`python 05-公共资源\2026103020-类名唯一性检查.py`（退出码 2 = 有启动级冲突）。

### 5.6 测试里的一个硬约定

一个类实现**多个** Service 契约时，测试的 `@MockBean` **必须指向具体实现类**，不能指向其中任一接口 —— 否则 `@MockBean` 按类型替换会把唯一的 Bean 整体顶掉，另一个契约无人实现，**整个 Spring 上下文起不来**。见 ADR-029。

### 6.3 护眼状态的跨组件传递：只准用共享单例

`components/study/StudyEyeState.ts`：

```ts
// 工厂：只造状态，❌ 不得注册任何 onMounted / onBeforeUnmount
export function useStudyEyeState(): StudyEyeState { … }

// 单例入口：模块级缓存，首调创建，之后复用同一实例
export function useSharedEyeState(): StudyEyeState { … }
```

| 规则 | 原因 |
|---|---|
| 状态工厂**不得注册生命周期钩子** | `onMounted` 绑定的是「当前正在 setup 的组件实例」→ 钩子会归**第一个调用者**，路由切换后静默停摆 |
| 会话生命周期归**学习端布局** | 布局 `onMounted(() => eye.start())` / `onBeforeUnmount(() => eye.stop())` |
| **禁用 `provide/inject`** | 方向是「父 provide → 子 inject」，而布局是页面的**子**组件 → 页面永远 inject 不到 |
| **禁用 `defineExpose` + 模板 ref** | 模板 ref 拿到深层 reactive 代理，会**自动解包嵌套 ref** → `.value` 恒 `undefined` |
| 模板里的 ref 必须挂在 setup 返回值**顶层** | Vue 只解包顶层 ref；嵌套普通对象属性拿到的是 `Ref` 实例本身 → 恒为真 |

> 固化断言：`StudyEyeSharedStateTest`（4 条）。

数据库变更规范：真源唯一、增量幂等、索引与排序都要可判定。

### 7.1 铁律

### 7.2 内容表与行为表的边界

| 类别 | 表数 | `child_id` | 例子 |
|---|---|---|---|
| **内容 / 知识库** | 7 张内容表 + 坐标树等 | ❌ **不加** | `study_question`、`study_word`、`study_grammar_point`、`study_writing_scenario`、`study_sentence_context` |

### 7.3 唯一索引清单要跟真实库对齐

```sql
SELECT TABLE_NAME, INDEX_NAME, GROUP_CONCAT(COLUMN_NAME ORDER BY SEQ_IN_INDEX)
FROM information_schema.STATISTICS
WHERE TABLE_SCHEMA='jeecg-study' AND NON_UNIQUE=0
GROUP BY TABLE_NAME, INDEX_NAME;
```

- 闸门：`python 05-公共资源\2026103021-唯一索引清单生成.py --check` → 期望「OK 唯一索引清单与真实库一致（24 张表）」。
- 新表上线时**必须**同步补进清单，否则清单与库结构不同步会被断言显式标注。
- 注意**组合唯一索引**（`uk_family_user(family_id,user_id)`、`uk_word_spelling_line(spelling,line_type)`）与**分区表**前缀匹配。

### 7.4 排序必须可判定（ADR-031）

| 规则 | 说明 |
|---|---|
| **对外可见顺序的查询必须显式 `ORDER BY`** | 家长端日序列聚合原先**完全无 ORDER BY** → 趋势图横轴顺序随执行计划漂移 |
| **排序键末位必须是唯一列** | `ORDER BY MIN(unit_order), unit_code`；`ORDER BY cnt DESC, knowledge_point_code` |
| **「最近一条」用主键兜底** | `ORDER BY create_time DESC, id DESC`（同一秒多行不可判定） |
| **截断查询必须有序** | `LIMIT n` 不排序 = 随机丢数据 |

> 落成断言：`StudySqlOrderDeterminismTest`（SQL-A：`GROUP BY` 必须有序 / SQL-B：截断必须有序 / SQL-C：`LIMIT 1` 末位键必须唯一）。
> **判断口诀**：用例偶发红绿翻转，**先怀疑排序并列**，别去改测试迁就。

## 排障速查

排障速查：2026-10-31 全量落地过程中沉淀的 15 条高频坑。

### 11.1 构建与编译

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 1 | `MalformedInputException` / 「找不到源文件」 | javac 的 `@argfile` 编码跟随 `file.encoding` | argfile 写 **UTF-8 无 BOM**，`-J-Dfile.encoding=UTF-8` 放**命令行**（不放 argfile 内部）；PowerShell 侧 `[Console]::OutputEncoding = [Text.Encoding]::UTF8` |
| 2 | javac 真实报错看不到 | PS 5.1 下 `$ErrorActionPreference='Stop'` 把 native stderr 升格成终止性错误 | 调用 native 命令前临时降级为 `'Continue'` |
| 3 | 源文件列表变空 → 「无源文件」 | 函数参数声明成 `[string[]]`，FileInfo 被降级后 `.FullName` 为 null | 参数声明成 `[object[]]` |
| 4 | 编译产物被 Spring 扫到半成品 | 私有编译目录复用，旧 class 残留 | 每次用**独立时间戳目录**，不复用 |

### 11.2 测试与断言

| # | 现象 | 根因 | 解法 |
|---|---|---|---|
| 5 | 整个 Spring 上下文起不来（`No qualifying bean`） | `@MockBean` 顶掉了「唯一实现某接口」的 Bean | `@MockBean` 指向**具体实现类**（ADR-029） |
| 6 | 源码扫描断言大批失败或**全部空通过** | 依赖 `Paths.get("")` 推导路径，运行器工作目录不对 | 运行器 `Push-Location` 到模块目录；扫描类断言必须断言「集合非空」 |

| 8 | 用例偶发红绿翻转 | 排序并列，缺唯一兜底键 | 改**生产侧**排序（§5.15），不要改测试 |

### 12.4 浏览器验证的注意事项
