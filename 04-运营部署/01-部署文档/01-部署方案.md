## 环境矩阵与端口

### 1.1 四套环境

| 环境 | 用途 | 后端端口 | 前端端口 | 业务库 | Redis 库索引 | 触发时机 |
|------|------|----------|----------|--------|--------------|----------|
| **DEV** | 本地开发自测 | 8590 | 8589 | `jeecg-study` | 3 | 每次开发 |
| **TEST** | 集成与接口测试 | 8091 | 3301 | `jeecg-study-test` | 4 | 每次提测 |
| **ACC** | 验收与 UI 走查 | 8092 | 3302 | `jeecg-study-acc` | 5 | 每个版本验收 |
| **PROD** | 生产（本机私有部署） | 8093 | 3303 | `jeecg-study-prod` | 6 | 正式发布 |

> **命名约定**：数据库与 Redis 索引一律带环境后缀，**只有 DEV 使用不带后缀的 `jeecg-study`**（因为它就是本机开发库）。

> ⚠ **端口以配置文件为准（2026-11-05 实测校正）**：本表是**规划口径**，实际端口由
> `application-<profile>.yml` 的 `server.port` 决定。实测：**DEV = 8590**（`application-dev.yml`）、
> **PROD = 8080**（`application-prod.yml`，**不是本表写的 8093**）；TEST / ACC 的 profile
> 尚未建立，对应端口也未落地。差异已登记在任务台账 §3.17。

### 1.2 与 monitorV2 的隔离

本机已有 monitorV2 在运行，本项目必须**完全并行**、互不干扰。

| 资源 | monitorV2 | jeecg-study | 冲突风险 |
|------|-----------|-------------|----------|
| 后端端口 | 8088 | **8590** | 无 |
| 前端端口 | 3100 / 3200 | **8589** | 无 |
| MySQL 实例 | 同一实例 | 同一实例 | 靠**库名**隔离 |
| MySQL 库 | `jeecg-boot` | `jeecg-study*` | 无 |
| Redis | 库索引 2 | 库索引 3–6 | 无 |
| 服务名 | `monitor-backend` | `study-backend` | 无 |
| 前端 dist | `latest/frontend/dist` | `study-latest/frontend/dist` | 无 |
| 目录 | `16-output/builds/latest` | `02-代码开发/05-源码/builds/latest` | 无 |

### 1.3 端口占用预检

# 部署前必查
$ports = 8590, 8091, 8092, 8093, 8589, 3301, 3302, 3303

本项目面向孩子，**平板端体验比手机重要**。若需要孩子用平板访问：

| 项 | 建议 |
|----|------|
| nginx 监听 | 增加 `192.168.x.x:3303` 监听，仅内网可达 |
| 访问控制 | 通过防火墙规则限制来源 IP 为家庭网段 |

> **不做公网暴露**。本项目无多用户、无账号体系，公网暴露等于把孩子的学习数据挂在互联网上。

## 配置与密钥

### 3.1 配置文件分层

| 文件 | 用途 | 是否入库 |
|------|------|----------|
| `application.yml` | 公共配置、profile 激活 | ✅ |
| `application-dev.yml` | 本地开发（含数据库口令） | ❌ gitignore |
| `application-test.yml` | 测试环境 | ❌ gitignore |
| `application-study.yml` | **study 模块专属配置**（新增） | ✅ |
| `.env.local` | 环境变量注入（生产口令） | ❌ gitignore |

### 3.2 study 模块配置项

```yaml
# application-study.yml
jeecg:
  study:
    # 护眼
    eye:
      default-interval-min: 15        # 默认护眼提醒间隔
      heartbeat-seconds: 30            # 客户端心跳间隔
      block-timeout-seconds: 60        # 阻断遮罩最短展示
    # 复习调度
    review:
      daily-limit: 50                  # 单日队列上限
      max-schedule-days: 14            # 最大排期天数
    # 判定
    judge:
      default-tolerance: 0.001         # 默认数值容差
    # AI 解释层（不启用时全部走降级路径）
    ai:
      enabled: false
      timeout-ms: 3000
      circuit-breaker-threshold: 10
      circuit-breaker-seconds: 60
```

> **`jeecg.study.ai.enabled` 默认 `false`**：本项目默认**不接任何外部模型**，全部走静态讲解与规则降级。这是 N-06「数据留本地」的默认姿态。启用需在《部署方案》中同步更新数据边界说明。

### 3.3 环境变量（生产）

| 变量 | 说明 |
|------|------|
| `JEECG_DB_URL` | **唯一** JDBC URL（单库 `jeecg-study`，平台表 + 业务表同库） |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号与口令（**生产必须显式注入 `DB_PASSWORD`**；dev/test 缺省回落 `root`。真实口令一律不入库） |
| `JEECG_DB_URL` / `JEECG_DB_USER` / `JEECG_DB_PASSWORD` | 部署期覆盖数据源用，等价于 Spring 松散绑定 `SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_URL` / `_USERNAME` / `_PASSWORD` |
| `REDIS_DB_INDEX` | Redis 库索引 |
| `STUDY_PROFILE` | Spring profile |

### 3.4 单库配置

> **V1.1 变更**：ADR-015 决定平台表与业务表**同在 `jeecg-study` 库**，双数据源方案作废（ADR-001 被取代）。
> 因此**只保留默认数据源 `master`**，业务代码**不需要任何 `@DS` 标注**。

```yaml
# 基座 application-prod.yml 的真实形态（口令走环境变量，无缺省）
spring:
  datasource:
    dynamic:
      primary: master
      datasource:
        master:                          # 唯一数据源：jeecg-study（平台表 + 业务表同库）
          url: jdbc:mysql://127.0.0.1:3306/jeecg-study?characterEncoding=UTF-8&useUnicode=true&useSSL=false&tinyInt1isBit=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
          username: ${DB_USERNAME:root}
          password: ${DB_PASSWORD}
          driver-class-name: com.mysql.cj.jdbc.Driver
```

> dev / test profile 写的是 `${DB_PASSWORD:root}`（缺省回落上游默认 `root`），
> prod **没有缺省**——不注入 `DB_PASSWORD` 就直接启动失败，这是有意的。
> 入库前请跑 `python -X utf8 .\05-公共资源\2026103023-凭据扫描.py`，确保没有明文口令漏进仓库。

全仓不应出现 `@DS(`。若将来要拆库，只需在 `spring.datasource.dynamic.datasource` 下新增一个键并给业务 Mapper 加 `@DS(...)`，**加在 Service 实现类的方法上，不是 Mapper 上**。

## 数据库初始化与迁移

### 4.1 脚本位置

| 类别 | 路径 | 入库 |
|------|------|------|
| **SQL 真源** | `02-代码开发/02-数据库/03-脚本/` | ✅ |
| 生成物（部署包镜像） | `04-运营部署/03-发布记录/` | ❌ gitignore |

> **SQL 真源只有 `02-代码开发/02-数据库/03-脚本/` 一处**。部署包里的 SQL 由打包脚本镜像同步，不要在部署包里手工改——下次打包会覆盖。
> 平台表初始化脚本 `01-平台库初始化.sql` 由 `05-公共资源/2026103018-平台库脚本.py` 从上游生成（只改库名，上游原文件不动）。

### 4.2 执行顺序

```
1. 01-平台库初始化.sql       平台表 133 张 + 种子 7446 条（单库，先建平台表）
2. 02-schema.sql              建 17 张业务表（含 4 张家庭与成员表）
3. 03-init.sql                业务种子（当前只有规格占位）
4. 04-fix.sql                 增量：7 张行为表加 child_id
5. 05-partition.sql           创建当月分表
```

> **顺序不能换**：平台表必须先建（业务表与 `sys_user` 有外键语义依赖）。

### 4.3 幂等要求

| 要求 | 做法 |
|------|------|
| 建表 | `CREATE TABLE IF NOT EXISTS` |
| 插数据 | `INSERT ... ON DUPLICATE KEY UPDATE` |
| 改结构 | `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`（MySQL 8 不支持 → 用存储过程判存在） |
| 索引 | 先查 `information_schema.statistics` 再建 |
| 迁移记录 | 每次执行在 `study_schema_migration` 表登记（脚本名 + 校验和） |

```sql
CREATE TABLE IF NOT EXISTS `study_schema_migration` (
  `id`           varchar(32) NOT NULL COMMENT '主键',
  `script_name`  varchar(128) NOT NULL COMMENT '脚本文件名',
  `checksum`     char(64) NOT NULL COMMENT '脚本内容 SHA-256，防止事后改脚本',
  `applied_at`   datetime NOT NULL COMMENT '执行时间',
  `duration_ms`  int DEFAULT NULL COMMENT '耗时毫秒',
  `del_flag`     tinyint NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`    varchar(50) DEFAULT NULL COMMENT '创建人',
  `create_time`  datetime DEFAULT NULL COMMENT '创建时间',
  `update_by`    varchar(50) DEFAULT NULL COMMENT '更新人',
  `update_time`  datetime DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_script_name` (`script_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='迁移执行记录';
```

> **脚本冻结**：`script_name` 与 `checksum` 登记后，**禁止修改已执行的脚本**（哪怕只是改注释）。要改就追加新的迁移脚本。

### 4.4 执行脚本

```powershell
# 02-代码开发/05-源码/04-建库迁移/migrate.ps1
param(
  [string]$Env = 'dev',
  [switch]$DryRun
)
$ErrorActionPreference = 'Stop'

$sqlDir = Join-Path $PSScriptRoot '..\..\02-代码开发\02-数据库\sql'
$mysql = 'mysql'
$db = switch ($Env) {
  'dev' { 'jeecg-study' }
  'test' { 'jeecg-study-test' }
  'acc' { 'jeecg-study-acc' }
  'prod' { 'jeecg-study-prod' }
}

# 1) 初始化脚本（按文件名排序）
Get-ChildItem (Join-Path $sqlDir '01-initialization') -Filter *.sql | Sort-Object Name | ForEach-Object {
  Write-Output "执行 $($_.Name)"
  if (-not $DryRun) {
    Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
    if ($LASTEXITCODE -ne 0) { throw "脚本失败：$($_.Name)" }
  }
}

# 2) 增量脚本（按文件名排序，已执行的跳过）
Get-ChildItem (Join-Path $sqlDir '02-migrations') -Filter *.sql | Sort-Object Name | ForEach-Object {
  $name = $_.BaseName
  $applied = & $mysql -u root -p$env:MYSQL_PWD $db -N -B -e "SELECT COUNT(*) FROM study_schema_migration WHERE script_name='$name'"
  if ($applied -eq '0') {
    Write-Output "执行 $name"
    if (-not $DryRun) {
      Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
      if ($LASTEXITCODE -ne 0) { throw "迁移失败：$name" }
    }
  } else {
    Write-Output "跳过 $name（已执行）"
  }
}
```

> **注意**：`.ps1` 脚本含中文时必须存为 **UTF-8 带 BOM**，否则 PowerShell 5.1 按 GBK 解码会吞掉换行符，把后续行并进注释，报出与真实原因无关的错误。

### 5.2 构建流程

> 脚本已落成真文件：**`02-代码开发/05-源码/04-建库迁移/build-and-sync.ps1`**（UTF-8 带 BOM）。
> 本节只讲**怎么用**；脚本内容以文件为准，不在这里内联副本。

```powershell
# 构建后端 + 前端，同步到 05-源码\builds\latest
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1'

# 只构建后端（前端产物已在 latest 里）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipFrontend

# 不同步版本目录（只更新 latest）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipVersion
```

| 步骤 | 脚本内部做什么 | 产物 |
|---|---|---|
| 1 | 后端 `mvn -pl jeecg-module-system/jeecg-system-start -am clean package -DskipTests=true` —— **`-pl` 必须指向启动模块**（见坑 ④） | `jeecg-module-study-3.9.2.jar` + `jeecg-system-start-3.9.2.jar`（**309 MB 的 fat jar**，含 342 个 `BOOT-INF/lib`） |
| 2 | 前端 `pnpm build` | `dist/` |
| 3 | 镜像 SQL 真源 | `builds\latest\sql\*.sql` |
| 4 | 同步到 `latest`（`robocopy /MIR` 增量镜像，不整拷） | `builds\latest\{backend,frontend,sql}` |
| 5 | 写版本目录 + `manifest.json` | `builds\versions\<stamp>\` |

> **四个必须遵守的坑**（来自既有工程与本轮实测的教训）：
> ① 构建输出**不要**经 `| Out-Host` 管道转发——1MB+ 资源清单会把管道压垮并让构建**静默中断**。用 `Tee-Object -FilePath $log | Out-Null`，失败时打印日志尾部。
> ② `Start-Process -ArgumentList` 传数组不安全，会用空格拼成一条命令行且不加引号。调用原生命令优先用 `&`。
> ③ **替换 jar 前必须先停服务**：运行中的 java 独占 jar 的文件句柄，覆盖写入会报「正由另一进程使用」。
> ④ **`-pl` 必须指向启动模块 `jeecg-system-start`**：指向业务模块 `jeecg-module-study` 时，
>    启动模块**根本不会进 reactor**（业务模块不依赖它）⇒ 产物里那枚 jar 是上一轮的**薄 jar**
>    （54 个 entry、无 `BOOT-INF/lib`、MANIFEST 无 `Main-Class`）⇒ `java -jar` 报「jar 中没有主清单属性」。
>    **判据**：产物里的 `jeecg-system-start-*.jar` 必须是 **fat jar**（含 `BOOT-INF/lib/`、MANIFEST 带
>    `Main-Class: org.springframework.boot.loader.launch.JarLauncher`），且 `build-and-sync.ps1`
>    跑完后能真的起起来。

### 5.3 发布流程

| 步骤 | 动作 | 校验 |
|------|------|------|
| 1 | 执行数据库迁移 | `study_schema_migration` 全部登记 |
| 2 | 停止后端服务 | `Stop-Service study-backend` |
| 3 | 替换 jar 与前端 dist | 先比对 SHA256，再替换 |
| 4 | **改写前端运行期配置** | `dist/_app.config.js` 的 `VITE_GLOB_DOMAIN_URL` 指向**本环境**后端（见下方说明） |
| 5 | 启动后端服务 | `Start-Service study-backend`，健康检查通过 |
| 6 | 重载 nginx | `nginx -s reload` |
| 7 | 部署后验证 | 见第 7 章 |
| 8 | 写发布记录 | `CHANGELOG.md` + `04-运营部署/03-发布记录/` |

> **替换 jar 前必须先停服务**：运行中的 java 独占 `latest/backend/*.jar` 的文件句柄，`Remove-Item` / 覆盖写入会报「正由另一进程使用」。

#### 步骤 4：前端运行期配置（**不做这一步，部署出来的东西是坏的**）

`dist/_app.config.js` 是上游**刻意**生成的**运行期覆盖文件**
（基座 `build/script/buildConf.ts` 注释原文：「生成外部配置文件，用于生产发布后配置，无需重新打包」）。

但**构建期写进去的是 `.env.production` 的默认值**：

```
VITE_GLOB_DOMAIN_URL=http://127.0.0.1:8080/jeecg-boot
```

前端的消息通知 WebSocket 地址由它派生
（`src/layouts/default/header/components/notify/index.vue`：`glob.domainUrl` 把 `http://` 换成 `ws://` 再拼 `/websocket/<userId>`）
⇒ **部署到别的后端端口时，WebSocket 会去连 `127.0.0.1:8080` ⇒ 连不上**。

**实测（2026-11-05 首次发布演练，E-52）**：对着发布候选取证，
**95 / 102 个页面**带 `WebSocket connection ... ERR_CONNECTION_REFUSED` 控制台错误；
每页一条，通知功能不可用。**对着 dev server 取证永远看不到** —— dev 走 `.env.development`（`http://localhost:8590/jeecg-boot`）。

**改法（构建时传参，脚本会自动改 + 校验）**：

```powershell
# 构建 + 同步 + 改写运行期配置（一步到位）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' `
    -RuntimeDomainUrl 'http://127.0.0.1:8590/jeecg-boot'
```

脚本会：改写**源 dist** 的 `_app.config.js` → 同步到 `latest` → **断言** `latest` 里的值确实生效（没生效就 `throw`，禁止发布）。

**已经部署完、只想改配置**（不用重新构建）：

```powershell
# 直接改 latest 里的运行期配置
$p = '.\02-代码开发\05-源码\builds\latest\frontend\dist\_app.config.js'
$t = [System.IO.File]::ReadAllText($p)
$t = [regex]::Replace($t, '"VITE_GLOB_DOMAIN_URL":"[^"]*"', '"VITE_GLOB_DOMAIN_URL":"http://127.0.0.1:8590/jeecg-boot"')
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))
```

> ⚠ **不要**把 `VITE_GLOB_DOMAIN_URL` 写死成某个部署环境的地址后再提交 —— 它是**环境相关**的，
> 正确做法是**部署时改**，不改源码。上游把它设计成运行期文件就是为了这件事。

### 5.4 Windows 服务注册

> ✅ **本节命令已实跑验证（2026-11-05）**：服务注册成功、`StartType = Automatic`、
> 端口 8590 起得来、健康检查 HTTP 200、`/api/v1/study/` 返回 401（鉴权正常生效）。
> 下面是**实测可复制**的版本 —— 原先那版有三处对不上，照抄必然起不来：
> ① jar 名写的是 `jeecg-system-start.jar`，实际产物**带版本号**（`jeecg-system-start-3.9.2.jar`）；
> ② Java 路径写死 `C:\Program Files\Java\jdk-17\bin\java.exe`，本机实际在 `D:\DevTools\Java\jdk-17.0.2`；
> ③ 日志路径用 `...` 占位，`nssm set` 会把它当真路径。

**为什么用包装脚本，而不是 nssm 直接起 java**：nssm 的 `AppEnvironmentExtra` 会把口令
**明文写进注册表**（`HKLM\SYSTEM\CurrentControlSet\Services\<服务名>\Parameters`）
⇒ 违反 ADR-046「口令不落文件、不进命令行、不进注册表」。
`start-backend.ps1` 改为：**启动时点号调用 `load-db-credential.ps1`**，从 DPAPI 加密凭据真源
解密到**本进程环境变量**（进程退出即消失）；同时它负责**按通配找最新 jar**、**不写死 Java 路径**。

```powershell
$root    = 'D:\DevProject\2-JavaPrj\20261030-jeecg-study'
$nssm    = 'C:\Users\Administrator\AppData\Local\Microsoft\WinGet\Links\nssm.exe'
$svc     = 'study-backend'
$backend = "$root\02-代码开发\05-源码\builds\latest\backend"

# ① 注册（powershell 包装器负责：加载凭据 → 选 jar → 选 java → 前台跑）
& $nssm install $svc powershell.exe "-NoProfile -ExecutionPolicy Bypass -File `"$root\02-代码开发\05-源码\04-建库迁移\start-backend.ps1`""
& $nssm set $svc AppDirectory $backend
& $nssm set $svc AppEnvironmentExtra "JAVA_HOME=D:\DevTools\Java\jdk-17.0.2"   # 仅 JDK 路径，非敏感信息
& $nssm set $svc AppStdout "$backend\logs\stdout.log"
& $nssm set $svc AppStderr "$backend\logs\stderr.log"
& $nssm set $svc Start SERVICE_AUTO_START
& $nssm set $svc AppExit Default Restart
& $nssm set $svc AppRestartDelay 5000
& $nssm set $svc AppRotateFiles 1
& $nssm set $svc AppRotateBytes 10485760
& $nssm start $svc
```

**验证**（2026-11-05 实测输出）：

```powershell
Get-Service study-backend                                     # Running / Automatic
Get-NetTCPConnection -LocalPort 8590 -State Listen             # 有监听
Invoke-WebRequest http://127.0.0.1:8590/jeecg-boot/ -UseBasicParsing   # HTTP 200
Get-Content "$backend\logs\stdout.log" -Tail 5
# 期望看到：Tomcat started on port 8590 (http) with context path '/jeecg-boot'
#           Started JeecgSystemApplication in xx seconds
```

> ⚠ **替换 jar 前必须先停服务**：运行中的 java 独占 jar 的文件句柄，覆盖写入会报「正由另一进程使用」。
> `Stop-Service study-backend` → 换 jar → `Start-Service study-backend`。

> ⚠ **端口口径以配置文件为准**：`application-dev.yml` = **8590**（DEV，本节走这个 profile）；
> `application-prod.yml` = **8080**（不是 §1.1 表里写的 8093 —— 该差异已登记在任务台账 §3.17）。

> **为什么用 Windows 服务而不是 WMI 启动**：既有工程实测，WMI 启动的子进程仍与调用方控制台关联，Agent 任务/终端结束时的 Ctrl+C 会波及后端，表现为 `java exit=-1`（Windows 强杀特征，非应用异常）。由 SCM 托管可避免。

> **路径口径**：本节假定 compose 文件放在**仓库根** `D:\DevProject\2-JavaPrj\20261030-jeecg-study\` 下，故所有路径以 `./` 开头。

```yaml
version: '3.8'
services:
  study-mysql:
    image: mysql:8.0
    container_name: study-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${STUDY_DB_PASSWORD}

    volumes:
      - study-mysql-data:/var/lib/mysql
      - ./02-代码开发/02-数据库/03-脚本/01-平台库初始化.sql:/docker-entrypoint-initdb.d/01-platform-init.sql:ro
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 10

  study-backend:
    build: ./02-代码开发/05-源码/01-JeecgBoot基座/jeecg-boot
    container_name: study-backend

      study-mysql: { condition: service_healthy }
    environment:

      STUDY_DB_URL: jdbc:mysql://study-mysql:3306/jeecg-study?...
      STUDY_DB_USER: root
      STUDY_DB_PASSWORD: ${STUDY_DB_PASSWORD}
    ports: ["8590:8590"]
    restart: unless-stopped

  study-frontend:
    image: nginx:alpine
    container_name: study-frontend
    depends_on: [study-backend]
    ports: ["3304:80"]

    restart: unless-stopped

volumes:
  study-mysql-data:
```

### 6.2 nginx.conf

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://study-backend:8590;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 60s;
    }

    location /study/ {
        alias /var/www/study-upload/;
        expires 7d;
    }
}
```

> **静态资源用 hash 文件名 + 长缓存**（`/assets/xxx.a1b2c3.js`），`index.html` 不缓存。

## 回滚方案

### 8.1 回滚触发条件

| 情况 | 处置 |
|------|------|
| 后端启动失败 | 回滚到上一版本 jar，重启 |
| 冒烟关键路径失败 | 回滚代码 + 回滚数据库 |
| 红线检查失败 | **立即回滚**，不现场修 |
| 性能指标不达标 | 评估后决定 |

### 8.2 代码回滚

```
1. Stop-Service study-backend
2. 从 builds\<上一时间戳>\backend\ 复制 jar 回 latest
3. 从 builds\<上一时间戳>\frontend\ 增量镜像 dist 回 latest
4. Start-Service study-backend
5. 重跑冒烟检查
```

> **保留历史**：每次构建产出独立时间戳目录 `builds/<yyyyMMdd.HHmmss>/`，保留最近 5 个。jar 与前端产物用 **NTFS 硬链接**发布到 `latest`（同卷零额外占用），指纹一致的组件跳过。

### 8.3 数据库回滚

| 变更类型 | 处置 |
|----------|------|
| 新增表/列 | 不回滚（向后兼容，旧代码不读新字段即可） |
| 新增索引 | 不回滚（仅影响性能） |
| 字段含义变更 | **必须写补偿脚本**，在 `02-migrations/` 追加 `V<新版本>__revert-<原版本>.sql` |
| 数据订正 | 写补偿脚本订正，**不修改已执行脚本** |

> **铁律**：已执行的迁移脚本**永不修改**。回滚靠**追加**补偿脚本，不靠改历史。
