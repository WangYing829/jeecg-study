## 环境矩阵与端口

### 1.1 四套环境

| 环境 | 用途 | 后端端口 | 前端端口 | 业务库 | Redis 库索引 | 触发时机 |
|------|------|----------|----------|--------|--------------|----------|
| **DEV** | 本地开发自测 | 8590 | 8589 | `jeecg-study` | 3 | 每次开发 |
| **TEST** | 集成与接口测试 | 8091 | 3301 | `jeecg-study-test` | 4 | 每次提测 |
| **ACC** | 验收与 UI 走查 | 8092 | 3302 | `jeecg-study-acc` | 5 | 每个版本验收 |

> **命名约定**：数据库与 Redis 索引一律带环境后缀，**只有 DEV 使用不带后缀的 `jeecg-study`**（因为它就是本机开发库）。

### 1.2 与 monitorV2 的隔离

本机已有 monitorV2 在运行，本项目必须**完全并行**、互不干扰。

| 资源 | monitorV2 | jeecg-study | 冲突风险 |
|------|-----------|-------------|----------|
| 后端端口 | 8088 | **8590** | 无 |
| 前端端口 | 3100 / 3200 | **8589** | 无 |
| MySQL 实例 | 同一实例 | 同一实例 | 靠**库名**隔离 |
| MySQL 库 | `jeecg-boot` | `jeecg-study*` | 无 |
| Redis | 库索引 2 | 库索引 3–6 | 无 |
| 服务名 | `monitor-backend` | `study-backend` | 无 |
| 前端 dist | `latest/frontend/dist` | `study-latest/frontend/dist` | 无 |
| 目录 | `16-output/builds/latest` | `02-代码开发/05-源码/builds/latest` | 无 |

> **服务名**必须包含 `study`，否则注册 Windows 服务时会与 monitorV2 撞名。

### 3.2 study 模块配置项

```yaml
# application-study.yml
jeecg:
  study:
    # 护眼
    eye:
      default-interval-min: 15        # 默认护眼提醒间隔
      heartbeat-seconds: 30            # 客户端心跳间隔
      block-timeout-seconds: 60        # 阻断遮罩最短展示
    # 复习调度
    review:
      daily-limit: 50                  # 单日队列上限
      max-schedule-days: 14            # 最大排期天数
    # 判定
    judge:
      default-tolerance: 0.001         # 默认数值容差
    # AI 解释层（不启用时全部走降级路径）
    ai:
      enabled: false
      timeout-ms: 3000
      circuit-breaker-threshold: 10
      circuit-breaker-seconds: 60
```

> **`jeecg.study.ai.enabled` 默认 `false`**：本项目默认**不接任何外部模型**，全部走静态讲解与规则降级。这是 N-06「数据留本地」的默认姿态。启用需在《部署方案》中同步更新数据边界说明。

### 3.3 环境变量（生产）

| 变量 | 说明 |
|------|------|
| `JEECG_DB_URL` | **唯一** JDBC URL（单库 `jeecg-study`，平台表 + 业务表同库） |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号与口令（**生产必须显式注入 `DB_PASSWORD`**；dev/test 缺省回落 `root`。真实口令一律不入库） |
| `JEECG_DB_URL` / `JEECG_DB_USER` / `JEECG_DB_PASSWORD` | 部署期覆盖数据源用，等价于 Spring 松散绑定 `SPRING_DATASOURCE_DYNAMIC_DATASOURCE_MASTER_URL` / `_USERNAME` / `_PASSWORD` |
| `REDIS_DB_INDEX` | Redis 库索引 |
| `STUDY_PROFILE` | Spring profile |

### 3.4 单库配置

> **V1.1 变更**：ADR-015 决定平台表与业务表**同在 `jeecg-study` 库**，双数据源方案作废（ADR-001 被取代）。
> 因此**只保留默认数据源 `master`**，业务代码**不需要任何 `@DS` 标注**。

```yaml
# 基座 application-prod.yml 的真实形态（口令走环境变量，无缺省）
spring:
  datasource:
    dynamic:
      primary: master
      datasource:
        master:                          # 唯一数据源：jeecg-study（平台表 + 业务表同库）
          url: jdbc:mysql://127.0.0.1:3306/jeecg-study?characterEncoding=UTF-8&useUnicode=true&useSSL=false&tinyInt1isBit=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
          username: ${DB_USERNAME:root}
          password: ${DB_PASSWORD}
          driver-class-name: com.mysql.cj.jdbc.Driver
```

> dev / test profile 写的是 `${DB_PASSWORD:root}`（缺省回落上游默认 `root`），
> prod **没有缺省**——不注入 `DB_PASSWORD` 就直接启动失败，这是有意的。
> 入库前请跑 `python -X utf8 .\05-公共资源\2026103023-凭据扫描.py`，确保没有明文口令漏进仓库。

全仓不应出现 `@DS(`。若将来要拆库，只需在 `spring.datasource.dynamic.datasource` 下新增一个键并给业务 Mapper 加 `@DS(...)`，**加在 Service 实现类的方法上，不是 Mapper 上**。

## 数据库初始化与迁移

### 4.1 脚本位置

| 类别 | 路径 | 入库 |
|------|------|------|
| **SQL 真源** | `02-代码开发/02-数据库/03-脚本/` | ✅ |
| 生成物（部署包镜像） | `04-运营部署/03-发布记录/` | ❌ gitignore |

> **SQL 真源只有 `02-代码开发/02-数据库/03-脚本/` 一处**。部署包里的 SQL 由打包脚本镜像同步，不要在部署包里手工改——下次打包会覆盖。
> 平台表初始化脚本 `01-平台库初始化.sql` 由 `05-公共资源/2026103018-平台库脚本.py` 从上游生成（只改库名，上游原文件不动）。

### 4.2 执行顺序

```
1. 01-平台库初始化.sql       平台表 133 张 + 种子 7446 条（单库，先建平台表）
2. 02-schema.sql              建 17 张业务表（含 4 张家庭与成员表）
3. 03-init.sql                业务种子（当前只有规格占位）
4. 04-fix.sql                 增量：7 张行为表加 child_id
5. 05-partition.sql           创建当月分表
```

> **顺序不能换**：平台表必须先建（业务表与 `sys_user` 有外键语义依赖）。

### 4.3 幂等要求

| 要求 | 做法 |
|------|------|
| 建表 | `CREATE TABLE IF NOT EXISTS` |
| 插数据 | `INSERT ... ON DUPLICATE KEY UPDATE` |
| 改结构 | `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`（MySQL 8 不支持 → 用存储过程判存在） |
| 索引 | 先查 `information_schema.statistics` 再建 |
| 迁移记录 | 每次执行在 `study_schema_migration` 表登记（脚本名 + 校验和） |

```sql
CREATE TABLE IF NOT EXISTS `study_schema_migration` (
  `id`           varchar(32) NOT NULL COMMENT '主键',
  `script_name`  varchar(128) NOT NULL COMMENT '脚本文件名',
  `checksum`     char(64) NOT NULL COMMENT '脚本内容 SHA-256，防止事后改脚本',
  `applied_at`   datetime NOT NULL COMMENT '执行时间',
  `duration_ms`  int DEFAULT NULL COMMENT '耗时毫秒',
  `del_flag`     tinyint NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`    varchar(50) DEFAULT NULL COMMENT '创建人',
  `create_time`  datetime DEFAULT NULL COMMENT '创建时间',
  `update_by`    varchar(50) DEFAULT NULL COMMENT '更新人',
  `update_time`  datetime DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_script_name` (`script_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='迁移执行记录';
```

> **脚本冻结**：`script_name` 与 `checksum` 登记后，**禁止修改已执行的脚本**（哪怕只是改注释）。要改就追加新的迁移脚本。

### 4.4 执行脚本

```powershell
# 02-代码开发/05-源码/04-建库迁移/migrate.ps1
param(
  [string]$Env = 'dev',
  [switch]$DryRun
)
$ErrorActionPreference = 'Stop'

$sqlDir = Join-Path $PSScriptRoot '..\..\02-代码开发\02-数据库\sql'
$mysql = 'mysql'
$db = switch ($Env) {
  'dev' { 'jeecg-study' }
  'test' { 'jeecg-study-test' }
  'acc' { 'jeecg-study-acc' }
  'prod' { 'jeecg-study-prod' }
}

# 1) 初始化脚本（按文件名排序）
Get-ChildItem (Join-Path $sqlDir '01-initialization') -Filter *.sql | Sort-Object Name | ForEach-Object {
  Write-Output "执行 $($_.Name)"
  if (-not $DryRun) {
    Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
    if ($LASTEXITCODE -ne 0) { throw "脚本失败：$($_.Name)" }
  }
}

# 2) 增量脚本（按文件名排序，已执行的跳过）
Get-ChildItem (Join-Path $sqlDir '02-migrations') -Filter *.sql | Sort-Object Name | ForEach-Object {
  $name = $_.BaseName
  $applied = & $mysql -u root -p$env:MYSQL_PWD $db -N -B -e "SELECT COUNT(*) FROM study_schema_migration WHERE script_name='$name'"
  if ($applied -eq '0') {
    Write-Output "执行 $name"
    if (-not $DryRun) {
      Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
      if ($LASTEXITCODE -ne 0) { throw "迁移失败：$name" }
    }
  } else {
    Write-Output "跳过 $name（已执行）"
  }
}
```

> **注意**：`.ps1` 脚本含中文时必须存为 **UTF-8 带 BOM**，否则 PowerShell 5.1 按 GBK 解码会吞掉换行符，把后续行并进注释，报出与真实原因无关的错误。

### 5.2 构建流程

> 脚本已落成真文件：**`02-代码开发/05-源码/04-建库迁移/build-and-sync.ps1`**（UTF-8 带 BOM）。
> 本节只讲**怎么用**；脚本内容以文件为准，不在这里内联副本。

```powershell
# 构建后端 + 前端，同步到 05-源码\builds\latest
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1'

& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipFrontend

# 不同步版本目录（只更新 latest）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipVersion
```

| 步骤 | 脚本内部做什么 | 产物 |
|---|---|---|
| 1 | 后端 `mvn -pl jeecg-module-study -am clean package -DskipTests` | `jeecg-module-study-3.9.2.jar` + `jeecg-system-start-3.9.2.jar` |
| 2 | 前端 `pnpm build` | `dist/` |
| 3 | 镜像 SQL 真源 | `builds\latest\sql\*.sql` |
| 4 | 同步到 `latest`（`robocopy /MIR` 增量镜像，不整拷） | `builds\latest\{backend,frontend,sql}` |
| 5 | 写版本目录 + `manifest.json` | `builds\versions\<stamp>\` |

> **三个必须遵守的坑**（来自既有工程的教训）：
> ① 构建输出**不要**经 `| Out-Host` 管道转发——1MB+ 资源清单会把管道压垮并让构建**静默中断**。用 `Tee-Object -FilePath $log | Out-Null`，失败时打印日志尾部。
> ② `Start-Process -ArgumentList` 传数组不安全，会用空格拼成一条命令行且不加引号。调用原生命令优先用 `&`。
> ③ **替换 jar 前必须先停服务**：运行中的 java 独占 jar 的文件句柄，覆盖写入会报「正由另一进程使用」。

| 步骤 | 动作 | 校验 |
|------|------|------|
| 1 | 执行数据库迁移 | `study_schema_migration` 全部登记 |
| 2 | 停止后端服务 | `Stop-Service study-backend` |
| 3 | 替换 jar 与前端 dist | 先比对 SHA256，再替换 |
| 4 | 启动后端服务 | `Start-Service study-backend`，健康检查通过 |
| 5 | 重载 nginx | `nginx -s reload` |
| 6 | 部署后验证 | 见第 7 章 |
| 7 | 写发布记录 | `CHANGELOG.md` + `04-运营部署/03-发布记录/` |

> **替换 jar 前必须先停服务**：运行中的 java 独占 `latest/backend/*.jar` 的文件句柄，`Remove-Item` / 覆盖写入会报「正由另一进程使用」。

### 5.4 Windows 服务注册

```powershell
# 用 nssm 托管，不要用 WMI 直接启动
nssm install study-backend "C:\Program Files\Java\jdk-17\bin\java.exe" `
  "-Xms512m -Xmx1024m -Dfile.encoding=UTF-8 -jar D:\DevProject\2-JavaPrj\20261030-jeecg-study\02-代码开发\05-源码\builds\latest\backend\jeecg-system-start.jar"
nssm set study-backend AppDirectory "D:\DevProject\2-JavaPrj\20261030-jeecg-study\02-代码开发\05-源码\builds\latest\backend"
nssm set study-backend AppStdout "...\backend\logs\stdout.log"
nssm set study-backend AppStderr "...\backend\logs\stderr.log"
nssm set study-backend Start SERVICE_AUTO_START
nssm set study-backend AppExit Default Restart
nssm set study-backend AppRestartDelay 5000
nssm start study-backend
```

> **为什么用 Windows 服务而不是 WMI 启动**：既有工程实测，WMI 启动的子进程仍与调用方控制台关联，Agent 任务/终端结束时的 Ctrl+C 会波及后端，表现为 `java exit=-1`（Windows 强杀特征，非应用异常）。由 SCM 托管可避免。

### 6.2 nginx.conf

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;
    gzip_min_length 1024;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://study-backend:8590;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 60s;
    }

    location /study/ {
        alias /var/www/study-upload/;
        expires 7d;
    }
}
```

> **静态资源用 hash 文件名 + 长缓存**（`/assets/xxx.a1b2c3.js`），`index.html` 不缓存。

## 回滚方案

### 8.1 回滚触发条件

| 情况 | 处置 |
|------|------|
| 后端启动失败 | 回滚到上一版本 jar，重启 |
| 冒烟关键路径失败 | 回滚代码 + 回滚数据库 |
| 红线检查失败 | **立即回滚**，不现场修 |
| 性能指标不达标 | 评估后决定 |

### 8.2 代码回滚

```
1. Stop-Service study-backend
2. 从 builds\<上一时间戳>\backend\ 复制 jar 回 latest
3. 从 builds\<上一时间戳>\frontend\ 增量镜像 dist 回 latest
4. Start-Service study-backend
5. 重跑冒烟检查
```

> **保留历史**：每次构建产出独立时间戳目录 `builds/<yyyyMMdd.HHmmss>/`，保留最近 5 个。jar 与前端产物用 **NTFS 硬链接**发布到 `latest`（同卷零额外占用），指纹一致的组件跳过。

### 8.3 数据库回滚

| 变更类型 | 处置 |
|----------|------|
| 新增表/列 | 不回滚（向后兼容，旧代码不读新字段即可） |
| 新增索引 | 不回滚（仅影响性能） |
| 字段含义变更 | **必须写补偿脚本**，在 `02-migrations/` 追加 `V<新版本>__revert-<原版本>.sql` |
| 数据订正 | 写补偿脚本订正，**不修改已执行脚本** |

> **铁律**：已执行的迁移脚本**永不修改**。回滚靠**追加**补偿脚本，不靠改历史。

### 8.4 回滚后验证

重跑第 7 章的冒烟清单 + 红线冒烟 + 关键路径冒烟。
