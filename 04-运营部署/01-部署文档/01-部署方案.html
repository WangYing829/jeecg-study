3.4 单库配置

V1.1 变更：ADR-015 决定平台表与业务表同在 jeecg-study 库，双数据源方案作废（ADR-001 被取代）。 因此只保留默认数据源 master，业务代码不需要任何 @DS 标注。

# 基座 application-prod.yml 的真实形态（口令走环境变量，无缺省）
spring:
  datasource:
    dynamic:
      primary: master
      datasource:
        master:                          # 唯一数据源：jeecg-study（平台表 + 业务表同库）
          url: jdbc:mysql://127.0.0.1:3306/jeecg-study?characterEncoding=UTF-8&useUnicode=true&useSSL=false&tinyInt1isBit=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
          username: ${DB_USERNAME:root}
          password: ${DB_PASSWORD}
          driver-class-name: com.mysql.cj.jdbc.Driver

dev / test profile 写的是 ${DB_PASSWORD:root}（缺省回落上游默认 root）， prod 没有缺省——不注入 DB_PASSWORD 就直接启动失败，这是有意的。 入库前请跑 python -X utf8 .\05-公共资源\2026103023-凭据扫描.py，确保没有明文口令漏进仓库。

全仓不应出现 @DS(。若将来要拆库，只需在 spring.datasource.dynamic.datasource 下新增一个键并给业务 Mapper 加 @DS(...)，加在 Service 实现类的方法上，不是 Mapper 上。

4.2 执行顺序

1. 01-平台库初始化.sql       平台表 133 张 + 种子 7446 条（单库，先建平台表）
2. 02-schema.sql              建 17 张业务表（含 4 张家庭与成员表）
3. 03-init.sql                业务种子（当前只有规格占位）
4. 04-fix.sql                 增量：7 张行为表加 child_id
5. 05-partition.sql           创建当月分表

顺序不能换：平台表必须先建（业务表与 sys_user 有外键语义依赖）。

4.3 幂等要求

要求 做法
建表 CREATE TABLE IF NOT EXISTS
插数据 INSERT ... ON DUPLICATE KEY UPDATE
改结构 ALTER TABLE ... ADD COLUMN IF NOT EXISTS（MySQL 8 不支持 → 用存储过程判存在）
索引 先查 information_schema.statistics 再建
迁移记录 每次执行在 study_schema_migration 表登记（脚本名 + 校验和） 
CREATE TABLE IF NOT EXISTS `study_schema_migration` (
  `id`           varchar(32) NOT NULL COMMENT '主键',
  `script_name`  varchar(128) NOT NULL COMMENT '脚本文件名',
  `checksum`     char(64) NOT NULL COMMENT '脚本内容 SHA-256，防止事后改脚本',
  `applied_at`   datetime NOT NULL COMMENT '执行时间',
  `duration_ms`  int DEFAULT NULL COMMENT '耗时毫秒',
  `del_flag`     tinyint NOT NULL DEFAULT 0 COMMENT '删除标记',
  `create_by`    varchar(50) DEFAULT NULL COMMENT '创建人',
  `create_time`  datetime DEFAULT NULL COMMENT '创建时间',
  `update_by`    varchar(50) DEFAULT NULL COMMENT '更新人',
  `update_time`  datetime DEFAULT NULL COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_script_name` (`script_name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='迁移执行记录';

脚本冻结：script_name 与 checksum 登记后，禁止修改已执行的脚本（哪怕只是改注释）。要改就追加新的迁移脚本。

4.4 执行脚本

# 02-代码开发/05-源码/04-建库迁移/migrate.ps1
param(
  [string]$Env = 'dev',
  [switch]$DryRun
)
$ErrorActionPreference = 'Stop'

$sqlDir = Join-Path $PSScriptRoot '..\..\02-代码开发\02-数据库\sql'
$mysql = 'mysql'
$db = switch ($Env) {
  'dev' { 'jeecg-study' }
  'test' { 'jeecg-study-test' }
  'acc' { 'jeecg-study-acc' }
  'prod' { 'jeecg-study-prod' }
}

# 1) 初始化脚本（按文件名排序）
Get-ChildItem (Join-Path $sqlDir '01-initialization') -Filter *.sql | Sort-Object Name | ForEach-Object {
  Write-Output "执行 $($_.Name)"
  if (-not $DryRun) {
    Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
    if ($LASTEXITCODE -ne 0) { throw "脚本失败：$($_.Name)" }
  }
}

# 2) 增量脚本（按文件名排序，已执行的跳过）
Get-ChildItem (Join-Path $sqlDir '02-migrations') -Filter *.sql | Sort-Object Name | ForEach-Object {
  $name = $_.BaseName
  $applied = & $mysql -u root -p$env:MYSQL_PWD $db -N -B -e "SELECT COUNT(*) FROM study_schema_migration WHERE script_name='$name'"
  if ($applied -eq '0') {
    Write-Output "执行 $name"
    if (-not $DryRun) {
      Get-Content $_.FullName -Raw | & $mysql -u root -p$env:MYSQL_PWD $db
      if ($LASTEXITCODE -ne 0) { throw "迁移失败：$name" }
    }
  } else {
    Write-Output "跳过 $name（已执行）"
  }
}

注意：.ps1 脚本含中文时必须存为 UTF-8 带 BOM，否则 PowerShell 5.1 按 GBK 解码会吞掉换行符，把后续行并进注释，报出与真实原因无关的错误。

5.2 构建流程

脚本已落成真文件：02-代码开发/05-源码/04-建库迁移/build-and-sync.ps1（UTF-8 带 BOM）。 本节只讲怎么用；脚本内容以文件为准，不在这里内联副本。

# 构建后端 + 前端，同步到 05-源码\builds\latest
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1'

# 只构建后端（前端产物已在 latest 里）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipFrontend

# 不同步版本目录（只更新 latest）
& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -SkipVersion
步骤 脚本内部做什么 产物
1 后端 mvn -pl jeecg-module-system/jeecg-system-start -am clean package -DskipTests=true —— -pl 必须指向启动模块（见坑 ④） jeecg-module-study-3.9.2.jar + jeecg-system-start-3.9.2.jar（309 MB 的 fat jar，含 342 个 BOOT-INF/lib）
2 前端 pnpm build dist/
3 镜像 SQL 真源 builds\latest\sql\*.sql
4 同步到 latest（robocopy /MIR 增量镜像，不整拷） builds\latest\{backend,frontend,sql}
5 写版本目录 + manifest.json builds\versions\<stamp>\

四个必须遵守的坑（来自既有工程与本轮实测的教训）： ① 构建输出不要经 | Out-Host 管道转发——1MB+ 资源清单会把管道压垮并让构建静默中断。用 Tee-Object -FilePath $log | Out-Null，失败时打印日志尾部。 ② Start-Process -ArgumentList 传数组不安全，会用空格拼成一条命令行且不加引号。调用原生命令优先用 &。 ③ 替换 jar 前必须先停服务：运行中的 java 独占 jar 的文件句柄，覆盖写入会报「正由另一进程使用」。 ④ -pl 必须指向启动模块 jeecg-system-start：指向业务模块 jeecg-module-study 时， 启动模块根本不会进 reactor（业务模块不依赖它）⇒ 产物里那枚 jar 是上一轮的薄 jar （54 个 entry、无 BOOT-INF/lib、MANIFEST 无 Main-Class）⇒ java -jar 报「jar 中没有主清单属性」。 判据：产物里的 jeecg-system-start-*.jar 必须是 fat jar（含 BOOT-INF/lib/、MANIFEST 带 Main-Class: org.springframework.boot.loader.launch.JarLauncher），且 build-and-sync.ps1 跑完后能真的起起来。

5.3 发布流程

步骤 动作 校验
1 执行数据库迁移 study_schema_migration 全部登记
2 停止后端服务 Stop-Service study-backend
3 替换 jar 与前端 dist 先比对 SHA256，再替换
4 前端运行期配置 不需要改写 —— VITE_GLOB_DOMAIN_URL 已是相对路径 /jeecgboot，环境无关（见下方说明）
5 启动后端服务 Start-Service study-backend，健康检查通过
6 托管前端 dist（nginx） start-nginx.ps1（复制配置 + nginx -t + 启动）；本机 nginx 已有别的站点 ⇒ 用独立端口 8090 + 独立 pid/日志并存

替换 jar 前必须先停服务：运行中的 java 独占 latest/backend/*.jar 的文件句柄，Remove-Item / 覆盖写入会报「正由另一进程使用」。

步骤 4：前端运行期配置（相对路径 ⇒ 这一步已不需要手工改）

dist/_app.config.js 是上游刻意生成的运行期覆盖文件 （基座 build/script/buildConf.ts 注释原文：「生成外部配置文件，用于生产发布后配置，无需重新打包」）。

本项目已把它改成相对路径（2026-11-05，E-53）：

VITE_GLOB_DOMAIN_URL=/jeecgboot

/jeecgboot 是同一个前缀，VITE_GLOB_API_URL（前端所有接口请求的父前缀）也用它， 后端的 context path 是 /jeecg-boot ⇒ 由 nginx 做一次前缀转换即可：

浏览器 ──/jeecgboot/...──▶ nginx ──/jeecg-boot/...──▶ 后端(8590)

为什么必须是相对路径：

绝对地址（原来的 http://127.0.0.1:8080/jeecg-boot） 相对路径（现在的 /jeecgboot）
换端口/域名 要重打包（或每次部署手工改 dist/_app.config.js） 不用改，同一份产物到处能用
忘了改的后果 WebSocket 每页一条 ERR_CONNECTION_REFUSED，通知不可用 不存在这个坑
构建期能否拦住 不能（构建成功、退出码 0，产物带着错误的地址上线） 能：build-and-sync.ps1 断言产物里不许出现绝对地址，出现即 throw 禁止发布

实测（2026-11-05 首次发布演练，E-52）：对着发布候选取证， 95 / 102 个页面带 WebSocket connection ... ERR_CONNECTION_REFUSED 控制台错误； 每页一条，通知功能不可用。对着 dev server 取证永远看不到 —— dev 走 .env.development（http://localhost:8590/jeecg-boot）。

现在的构建命令（不需要再传地址）：

& '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1'

脚本会：同步产物 → 校验文件数与 index.html 引用（E-51）→ 断言 latest/frontend/dist/_app.config.js 里的 VITE_GLOB_DOMAIN_URL 必须是相对路径（以 / 开头）；是绝对地址就 throw「禁止发布」。

需要绝对地址的例外（比如后端与前端不同源、且没有反代）：显式传参，脚本会改写并校验生效。 powershell & '.\02-代码开发\05-源码\04-建库迁移\build-and-sync.ps1' -RuntimeDomainUrl 'https://api.example.com/jeecg-boot'

已经部署完、只想改配置（不用重新构建）：

# 直接改 latest 里的运行期配置
$p = '.\02-代码开发\05-源码\builds\latest\frontend\dist\_app.config.js'
$t = [System.IO.File]::ReadAllText($p)
$t = [regex]::Replace($t, '"VITE_GLOB_DOMAIN_URL":"[^"]*"', '"VITE_GLOB_DOMAIN_URL":"/jeecgboot"')
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($false)))

⚠ 不要把 VITE_GLOB_DOMAIN_URL 写死成某个部署环境的地址后再提交 —— 它是环境相关的， 正确做法是用相对路径，让 nginx 去适配具体环境。

5.4 Windows 服务注册

✅ 本节命令已实跑验证（2026-11-05）：服务注册成功、StartType = Automatic、 端口 8590 起得来、健康检查 HTTP 200、/api/v1/study/ 返回 401（鉴权正常生效）。 下面是实测可复制的版本 —— 原先那版有三处对不上，照抄必然起不来： ① jar 名写的是 jeecg-system-start.jar，实际产物带版本号（jeecg-system-start-3.9.2.jar）； ② Java 路径写死 C:\Program Files\Java\jdk-17\bin\java.exe，本机实际在 D:\DevTools\Java\jdk-17.0.2； ③ 日志路径用 ... 占位，nssm set 会把它当真路径。

为什么用包装脚本，而不是 nssm 直接起 java：nssm 的 AppEnvironmentExtra 会把口令 明文写进注册表（HKLM\SYSTEM\CurrentControlSet\Services\<服务名>\Parameters） ⇒ 违反 ADR-046「口令不落文件、不进命令行、不进注册表」。 start-backend.ps1 改为：启动时点号调用 load-db-credential.ps1，从 DPAPI 加密凭据真源 解密到本进程环境变量（进程退出即消失）；同时它负责按通配找最新 jar、不写死 Java 路径。

$root    = 'D:\DevProject\2-JavaPrj\20261030-jeecg-study'
$nssm    = 'C:\Users\Administrator\AppData\Local\Microsoft\WinGet\Links\nssm.exe'
$svc     = 'study-backend'
$backend = "$root\02-代码开发\05-源码\builds\latest\backend"

# ① 注册（powershell 包装器负责：加载凭据 → 选 jar → 选 java → 前台跑）
& $nssm install $svc powershell.exe "-NoProfile -ExecutionPolicy Bypass -File `"$root\02-代码开发\05-源码\04-建库迁移\start-backend.ps1`""
& $nssm set $svc AppDirectory $backend
& $nssm set $svc AppEnvironmentExtra "JAVA_HOME=D:\DevTools\Java\jdk-17.0.2"   # 仅 JDK 路径，非敏感信息
& $nssm set $svc AppStdout "$backend\logs\stdout.log"
& $nssm set $svc AppStderr "$backend\logs\stderr.log"
& $nssm set $svc Start SERVICE_AUTO_START
& $nssm set $svc AppExit Default Restart
& $nssm set $svc AppRestartDelay 5000
& $nssm set $svc AppRotateFiles 1
& $nssm set $svc AppRotateBytes 10485760
& $nssm start $svc

关键片段（完整版见 02-nginx.conf）

server {
    listen       8090;
    server_name  localhost;

    root  D:/DevProject/2-JavaPrj/20261030-jeecg-study/02-代码开发/05-源码/builds/latest/frontend/dist;
    index index.html;

    # SPA history 模式：刷新子页面必须回落 index.html，缺了直接 404
    location / {
        try_files $uri $uri/ /index.html;
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg)$ {
            expires 7d;
            add_header Cache-Control "public";
        }
    }

    # 敏感路径不得落入 SPA 的 try_files 兜底
    location ~ /\.(env|git|svn|hg|aws|ssh|docker) { return 404; }

    # 安全加固：积木报表未授权 RCE 端点禁用
    location ~* ^/jeecg-?boot/jmreport/(auto/export|executeSelectApi|auto/show) {
        return 403 '{"code":403,"message":"Forbidden: endpoint disabled by security policy","success":false}';
    }

    # ===== 后端反代 =====
    # 前端的 VITE_GLOB_API_URL（所有接口请求的父前缀）与 VITE_GLOB_DOMAIN_URL
    # （上传 / 文件下载 / WebSocket）**都是相对路径 /jeecgboot** ⇒ 浏览器只认这一个前缀。
    # 后端的 context path 是 /jeecg-boot ⇒ 这里做一次前缀转换。
    location /jeecgboot/ {
        proxy_pass http://127.0.0.1:8590/jeecg-boot/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        # ⚠ WebSocket 升级：**没有这两行，顶部消息通知连不上**（E-52）
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_connect_timeout 30s;
        proxy_read_timeout 120s;
    }
}

⚠ 2026-11-05 订正：原配置里的 location /api/ { proxy_pass http://study-backend:8590; } 是错的 —— 它没有补上后端的 context path /jeecg-boot，请求打到后端会 404； 而前端本来也不走 /api/（接口父前缀是 /jeecgboot）⇒ 这段配置删掉，换成上面的 /jeecgboot/。

⚠ Connection 头用 map $http_upgrade $connection_upgrade 生成（http 块里）， 不要直接写死 "upgrade" —— 那样普通 HTTP 请求也会带上 Connection: upgrade。

静态资源用 hash 文件名 + 长缓存（/assets/xxx.a1b2c3.js），index.html 不缓存。
