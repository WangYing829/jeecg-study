
## 3 命名

测试脚本属于**过程产物**：

| 项 | 约定 | 示例 |
|---|---|---|
| 目录 | `NN-<业务名>` | `01-后端` |
| 文件 | `8位日期2位序号-业务名` | `2026103018-ArchUnit判定层隔离测试.java` |
| 序号 | 项目内全局唯一 | 与 `05-公共资源/` 的序号不重复 |

## 4 铁律

| # | 规则 |
|---|---|
| 1 | **断言必须可判定**——不许写「正常显示」「运行正常」这类无法判定的期望 |
| 2 | **数元素个数，不查可见性**——`display:none` 的元素仍在 DOM，R01-3 必须数个数 |
| 3 | **不依赖截图判定**——滤镜、颜色、过渡要用 computed style 断言 |
| 4 | **无头环境不推进 CSS 过渡**——需要时给验证副本注入 `transition:none`，**不要污染交付文件** |
| 5 | **浏览器断言用内置 Browser + iframe 校验台**，不用无头 Edge（本机 msedge 常驻，不可靠） |
| 6 | 失败要输出**可定位信息**（文件、行号、实际值），不是「断言失败」 |

## 5 与文档校验的关系

本目录的脚本是**代码侧**门禁；文档侧的门禁在 `05-公共资源/`：

| 脚本 | 管什么 |
|---|---|
| `2026103013-交付物校验.py` | 10 份 HTML 的结构、编码、锚点、表格 |
| `2026103015-追溯矩阵生成.py` | 需求 → 接口 → 用例 的机读追溯 |
| `2026103016-红线断言检查.py` | 24 条断言的文档齐全性 + 追溯闭合 |
| `2026103017-DDL提取.py` | 从设计源稿生成 SQL 真源脚本 |

> 代码侧断言的门禁脚本**待 V0 落地后补**，届时登记到本目录并接入统一入口。

## 6 什么时候需要动这个目录

| 场景 | 动作 |
|---|---|
| V0 源码落地 | 按 §1 建子目录，搬入断言脚本 |
| 只改断言规格 | 改 `../01-红线断言规格.md`，不动本目录 |
| 断言实现完成 | 回填 `../01-红线断言规格.md` §4 的登记表 |
