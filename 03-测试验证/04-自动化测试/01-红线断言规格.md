## 3 脚本落点

| 类型 | 路径 | 说明 |
|---|---|---|
| Java 单元测试 / ArchUnit | `02-测试脚本/01-后端/` | 随源码模块走 |
| 前端 E2E（DOM / 样式 / 交互） | `02-测试脚本/02-前端/` | Playwright 或等价 |
| 静态扫描（源码文案 / 隐藏式答案） | `02-测试脚本/03-扫描/` | Node 或 Python 均可 |
| 数据库约束检查 | `02-测试脚本/04-数据库/` | 连库执行 |
| 公共测试工具 | `02-测试脚本/00-公共/` | 共享的断言辅助 |

> **命名**：测试脚本属于「过程产物」，用 `8位日期2位序号-业务名称`；但放进 `02-测试脚本/` 子目录后，统一用 `NN-<业务名>` 便于按类型归档。

## 6 与发布的关系

红线断言是**发布否决项**：

| 阶段 | 断言要求 |
|---|---|
| V0 地基 | R01-1、R01-3、R01-5、R02-1、R02-4、R04-1 **必须已实现**（前 6 条优先级） |
| V0 地基（多用户前置） | **R04-5、R04-6 必须已实现**——多家长上线即生效，没有隔离底线不能发 |
| V1–V4 | 每阶段新增的断言必须实现；**24 条全部**实现前不发布 V4 |
| 每个版本 | **24 条全部通过**，一条不过 → 不发布 |
