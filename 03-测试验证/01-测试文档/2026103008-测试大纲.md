## 测试目标与依据

### 1.1 测试目标

本项目是**多家庭、多孩子、多家长、面向未成年人**的家庭工具，测试目标有四个层次，与常规业务系统不同：

| 层次 | 目标 | 判据 |
|------|------|------|
| 功能正确 | 六个模块按 PRD 定义工作，跨模块数据确实打通 | 每条 P0/P1 需求至少 1 条用例且通过 |
| **红线成立** | 四条产品红线在系统层面**不可被绕过**，不是靠人自觉 | 每条红线有**可自动检测**的断言，全部通过 |
| **不伤害孩子** | 用眼可控、反馈不制造挫败、不诱导搜题依赖 | 护眼阻断实测有效；文案扫描无负向表达与排名 |
| **数据隔离成立** | 家长 A 看不到孩子 B 的任何数据；家长之间互不可见 | 10 条越权用例全部返回 **4010**；R04-5、R04-6 通过 |

> 第四层次是**多用户改造后新增的发布否决项**：任一条越权用例没按预期返回 4010（家长 A 看到了孩子 B 的数据），版本不予发布。
> 它与第三层次同级——「泄露别的孩子的错题」对孩子的伤害不亚于「诱导搜题」。

## 测试范围与不做

### 2.1 测试范围

| 范围 | 包含 |
|------|------|
| 功能测试 | 六模块全部功能 + 底座五组件 + 家长端 + 护眼 |
| 接口测试 | 89 个接口（含 4 个护眼心跳接口） |
| 数据库测试 | 12 张表的约束、索引、事务、幂等 |
| 红线专项 | R-01…R-04 的可自动检测断言（**24 条**，含 2 条多家庭强化断言） |
| UI 规范走查 | 设计规范自检清单 42 条（通用 25 + 多端 7 + 学习端 10） |
| 性能测试 | 关键路径（P95） |
| 安全与隐私 | 数据边界、越权、未成年人合规 |
| 兼容性 | 桌面主流浏览器 + 移动视口 |

### 2.2 明确不做

| 不做 | 原因 |
|------|------|
| 压力测试（万级并发） | 家庭级使用，无并发压力可言；只测同家庭多孩子/多家长的并发写 |
| 多租户与通用权限体系 | **N-05**：多家庭多用户，但不做多租户、不做通用权限体系；数据隔离只按 `child_id` 实现 |
| 家庭内比较功能 | **R-04**：多孩子家庭也不做横向比较，只呈现每个孩子自己的客观趋势 |
| 兼容性矩阵穷举 | 只测 Chrome / Edge 最新两个大版本 + Safari（iOS） |
| 大模型效果评测 | AI 只做解释层，不是正确性判定主体；只测「超时能降级」 |
| 教育效果验证 | 超出工程测试范围，属产品运营范畴 |
| 第三方模型供应商横向评测 | 后续若接入多供应商再补 |

## 测试级别与策略

| 级别 | 时机 | 范围 | 执行方式 | 阻塞发布 |
|------|------|------|----------|----------|
| **L0 静态检查** | 每次提交 | 类型、lint、依赖漏洞、**ArchUnit 断言** | CI 自动 | 是 |
| **L1 单元测试** | 每次提交 | Service / Engine / Rule 三个包 | CI 自动 | 是 |
| **L2 组件测试** | 每次提交 | Controller 层（MockMvc）、Mapper 层 | CI 自动 | 是 |
| **L3 接口测试** | 合并前 | 全部 72 个接口的契约与错误码 | CI 自动 + 人工抽查 | 是 |
| **L4 集成测试** | 版本验收 | 跨模块链路（16 个端到端场景） | 人工 + 脚本 | 是 |
| **L5 UI 走查** | 版本验收 | 设计规范 42 条清单 | 人工 + 截图取证 | 是 |
| **L6 性能与兼容** | 版本验收 | 关键路径性能 + 双端兼容 | 人工 | 性能是 |

### 3.1 单元测试重点

| 包 | 必测内容 |
|----|----------|
| `engine.judge` | **每种 `JudgeStrategy` 的边界**：数值容差边界（等于容差/超一点）、空答案、格式错误（`1,000` vs `1000`）、多选题部分正确 |
| `engine.review` | 排期状态机全路径：当天→+1→+3→+7→+14；连续三次做对移出；答错回退 |
| `engine.mastery` | 掌握度四态迁移（含 MASTERED 答错直跌两级） |
| `engine.forgetting` | 四档反馈的 S/λ 更新数值正确 |
| `engine.variant` | 三层变式生成的结构正确性 + 答案可被规则验算 |
| `rule.*` | 各题型规则命中与不命中 |
| `service.error` | **错因缺失必须抛 4001**；错题写入与排期写入的**事务原子性** |

### 3.2 ArchUnit 断言（红线 R-02 的编译期保险）

```
断言 1：org.jeecg.modules.study.engine 与 rule 包不得依赖任何 AI 客户端类
断言 2：org.jeecg.modules.study.rule 包不得依赖 org.jeecg.modules.study.ai 包
断言 3：org.jeecg.modules.study.base.error 之外的包不得直接访问 study_error_pool 表
断言 4：ParentReadController 的方法不得返回类型包含 answer / analysis 字段的 VO
断言 5：任何 Controller 方法名含 "judge" / "grade" 的，返回类型必须含 judgeSource 字段
```

> **断言 3 是 G-01 的数据层保险**：任何绕过 `ErrorPoolService` 直接写错题表的代码都会在编译期失败。

## 测试类型

### 4.1 功能测试

按模块拆，见《测试用例》。

### 4.2 接口测试

| 检查维度 | 方法 |
|----------|------|
| 响应体结构 | `success/code/message/result` 四字段齐全；失败时 `result` 为 null |
| 错误码 | 每个业务错误码至少 1 条用例（4001–4008） |
| 幂等 | 重复提交的返回结果一致，且不产生重复数据（接口设计 10.1 的 5 个接口） |
| 并发 | 同一错题多端同时复习，`correct_streak` 不重复累加 |
| 事务 | 排期写入失败时错题记录不落库（N-04 / A-16） |
| 字段缺失 | `next` 接口**不返回** `answer` 与 `analysis`（R-01 接口层保险） |
| 字段枚举 | `judgeSource` 只出现 `rule` / `rule+model` |

### 4.3 数据库测试

| 项 | 方法 |
|----|------|
| 约束 | `error_cause` NOT NULL；`judge_source` 枚举 CHECK；`uk_word_spelling_line` 唯一 |
| 索引命中 | 关键查询走 `EXPLAIN` 确认命中预期索引（数据库设计 11.1 的 9 条路径） |
| 版本化 | 考纲调整后旧节点 `invalid_at` 有值、`status=0`，且历史错题仍能解析到旧节点 |
| 分表 | 跨月查询正确；月度表自动创建幂等 |
| 事务回滚 | 模拟排期写入失败，确认错题记录不落库 |
| 清理脚本 | 种子数据清理后不影响非种子数据 |

### 4.4 UI 规范走查

按《产品设计规范》第 14 章的 **42 条自检清单**（通用 25 + 多端 7 + 学习端 10）逐条走查，每条留截图取证。

**特别项**：

| 项 | 走查方法 |
|----|----------|
| 桌面横向溢出 | 在 1280 / 1366 / 1920 三个宽度下验证 `documentElement.scrollWidth === clientWidth` |
| 移动端转卡片 | ≤992px 下表格变卡片（不是横向滚动）；阈值对齐上游基座 `AppProvider.vue:28-31` |
| 暗色模式 | 切到 dark，管理端页面无残留硬编码亮色 |
| 学习端主题锁定 | 学习端始终浅色，不出现半深半浅 |

### 4.5 性能测试

| 指标 | 目标 | 方法 |
|------|------|------|
| 列表页首屏 | ≤1.5s | 本地环境，Chrome Performance 面板 |
| 判对错接口 | ≤300ms（不含 AI） | 100 次采样取 P95 |
| AI 解释 | ≤3s，超时降级 | 注入延迟 |
| 坐标树加载 | 缓存命中 <50ms | Redis 命中前后对比 |
| 队列物化 | ≤200ms | 50 条队列 |
| 今日复习队列 | ≤300ms | 5000 条错题池下测 |

### 4.6 安全与隐私测试

| 项 | 方法 |
|----|------|
| 数据出网 | 全流程抓包，确认**零**第三方请求（无统计、无广告、无外部模型） |
| 越权 | 家长角色调用练习接口 → 403；学生角色调用家长端接口 → 403 |
| **child_id 数据隔离** | 家长 A 请求孩子 B 的任意接口（含改 URL 指定他人 childCode）→ **4010**；孩子 A 请求孩子 B → **4010**；家长之间响应零标识泄露 |
| 答案泄露 | 家长端全部响应体扫描 `answer` / `analysis` / `correctAnswer` 字段 → 必须为 0 |
| 排名泄露 | 全库检索「排名」「排行」「百分位」「超过…同学」→ 必须为 0 |
| XSS | 用户输入（作文正文、错因备注、反馈）渲染前转义 |
| 文件上传 | 错题图片仅允许图片类型，限制大小，重命名存储 |
| SQL 注入 | 所有查询走 MyBatis-Plus 参数化，无字符串拼接 |
| 口令 | `application-*.yml` 已 gitignore；生产走环境变量 |

## 红线专项测试

> 这四条是本项目的**否决项**。任一条不通过，整个版本不予发布。
> 断言共 **24 条**：R-01 5 条、R-02 7 条、R-03 6 条、**R-04 6 条**（其中 R04-5、R04-6 为多家庭改造新增）。

### 6.1 R-01 反搜题

| 编号 | 检查 | 方法 | 通过标准 |
|------|------|------|----------|
| R01-1 | 接口层 | 调用 `GET /practice/{type}/next` | 响应体**不含** `answer` / `analysis` / `correctAnswer` 字段 |
| R01-2 | 接口层 | 未作答直接调 `GET /practice/{contentId}/explanation` | 返回 4003 |
| R01-3 | DOM 层 | 练习页初始状态下查询解析容器 | `document.querySelectorAll('[data-role="explanation"]').length === 0`（**不存在**，不是隐藏） |
| R01-4 | 交互层 | 走一遍全部 5 个练习页 | 未作答时看不到任何答案或解析入口 |
| R01-5 | 源码层 | 静态扫描学习端组件 | 不存在 `v-show` / `display:none` 形式的答案隐藏实现 |

### 6.2 R-02 AI 只做解释层

| 编号 | 检查 | 方法 | 通过标准 |
|------|------|------|----------|
| R02-1 | 源码层 | ArchUnit 断言 | `rule` / `engine.judge` 包对 AI 客户端**零依赖** |
| R02-2 | 数据层 | 检查 `study_error_pool.judge_source` 全部取值 | 只出现 `rule` / `rule+model`，**无** `model` |
| R02-3 | 接口层 | 遍历所有返回对错的接口 | 响应必含 `judgeSource`，且取值同上 |
| R02-4 | 数据库层 | 尝试写入 `judge_source='model'` | 被 CHECK 约束拒绝（或应用层校验拒绝） |
| R02-5 | 架构层 | 检视变式生成 | `generatedBy` 只出现 `RULE` / `RULE+MODEL`；答案均可由规则验算 |
| R02-6 | 兜底通道 | 提交一次申诉 | 申诉记录落库，家长端可见 |
| R02-7 | 降级 | 注入 AI 超时 | 练习流程**不中断**，仅解析区降级 |

### 6.3 R-03 护眼硬指标

| 编号 | 检查 | 方法 | 通过标准 |
|------|------|------|----------|
| R03-1 | 阻断 | 把间隔临时设为 1 分钟并等待 | 出现阻断遮罩，**无法**通过切页面/刷新绕过 |
| R03-2 | 不可自动消失 | 触发后静置 60 秒 | 遮罩仍在 |
| R03-3 | 统计准确 | 模拟 10 分钟会话（含 3 分钟后台） | 服务端统计约 7 分钟（后台不计） |
| R03-4 | 蓝光过滤 | 开启后检查滤镜生效 | 容器 `filter` 属性存在且生效 |
| R03-5 | 端上不显示 | 检查孩子端界面 | 不出现用眼时长数字 |
| R03-6 | 家长端可见 | 检查家长端 | 用眼时长与休息次数可见 |

### 6.4 R-04 不做公开比较（6 条）

| 编号 | 检查 | 方法 | 通过标准 |
|------|------|------|----------|
| R04-1 | 数据库 | 全库检索字段名 | 无 `rank` / `percentile` / `compare_rank` 等字段 |
| R04-2 | 接口层 | 遍历家长端全部响应 | 响应体中无排名类字段与数值 |
| R04-3 | 文案 | 全站文案扫描关键词 | 无「排名」「排行」「超过 X% 的同学」「超越」 |
| R04-4 | UI + 学习端 | 遍历全部页面截图 + 背单词/闯关页 | 无横向比较元素；学习端无分数、无等级、无排行榜入口 |
| R04-5 | 多家长隔离 | 用家长 A 的 token 遍历家长端全部响应，检索家长 B 的 userId、用户名、昵称、头像 | 检索命中数 = 0 |
| R04-6 | 家庭内比较 | 全站文案扫描「更 / 比 / 超过」类比较措辞（家长端 + 孩子端全部页面） | 命中数 = 0；不出现「谁的孩子更…」「比上次进步更多」这类家庭内比较措辞 |

## 缺陷分级与流转

| 等级 | 定义 | 本项目示例 | 修复时限 |
|------|------|------------|----------|
| **S1 致命** | 系统不可用 / 数据丢失 / 红线被破 / 伤害孩子的行为 | 孩子能看到未作答的答案；AI 判定直接落库；护眼提醒可绕过 | 立即，阻塞发布 |
| **S2 严重** | 主流程不可用 / 数据错误 | 排期推进错误；错题丢失；跨模块错题不进池 | 24h，阻塞发布 |
| **S3 一般** | 次要功能异常 / 体验缺陷 | 文案错误；间距偏差；动效卡顿 | 3 天 |
| **S4 轻微** | 界面细节 / 优化建议 | 圆角差 1px；阴影略重 | 下个版本 |

**流转**：

```
发现 → 提单（必填：环境、步骤、预期 vs 实际、截图/录屏、对应需求编号）
     → 开发确认（24h 内）
     → 修复 → 自测 → 测试复测
     → 关闭 → 纳入回归集
```

**提单规范**：每条缺陷必须关联**需求编号或用例编号**。无法关联的缺陷先归类为「体验建议」，不占缺陷指标。
