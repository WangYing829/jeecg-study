## 取证结论

取证结论：§11.2「尚未上线的界面」新增的 13 个页面，在**本机真实浏览器**里逐页渲染、逐页截图、逐页量测，**42 张截图全部产出，四项硬指标全为 0**；过程中抓出 **4 个真实缺陷并全部闭环**，其中 **2 个是源码静态扫描无论如何都发现不了的**。

| 硬指标 | 结果 | 口径 |
|---|---|---|
| 横向溢出 | **0 / 42** | `documentElement.scrollWidth - clientWidth`，逐页实测 |
| 控制台错误 | **0 / 42** | `console` 事件 `type === 'error'`，逐页实测 |
| 4xx / 5xx 响应 | **0 / 42** | `response` 事件 `status >= 400`，逐页实测 |
| R-04 公开比较措辞 | **0 / 42** | 正文全文匹配「排名/排行/百分位/名次/排行榜/超过/位次」 |
| 业务错误提示残留 | **0 / 42** | 正文全文匹配「请指定要访问的孩子/无权访问/系统异常/请求失败/加载失败」 |

三条核心结论：

1. **四个缺陷已闭环**。D-2（两个 `:code` 页 404）与 D-3（管理端列表整列空白）都是 **P0 级**——前者页面直接打不开，后者页面打开了但**所有数据列都是空的**；D-4（表格有数据却挂着错误提示）与 D-1（vite 路由 glob 陈旧）同样是实打实的缺陷。修复后重跑 42 个页面态，四项硬指标依然全 0。
2. **两个缺陷是静态扫描抓不到的**。D-2 的根因在**后端菜单树算法 + DB 数据**的组合上（`is_leaf=1` 让整棵子树被静默剪掉，**无 4xx、无 console error**，页面只有一张 404 插画）；D-3 的根因在 **antd 取值约定**上（`record[dataIndex]` 取不到值 → 每格都是 `record[undefined]`）。两者在源码里都「看起来完全正常」，只有真跑浏览器才暴露。这正是本轮取证的价值所在。
3. **修复全部补成可执行断言**。新增 **7 条**断言（4 条静态内核不变量 + 3 条 DB 支撑的菜单树不变量），把「下次不会再犯」从口头约定变成红灯。

> **本报告的口径**：所有数字均来自**本机真实执行**，不是设计预期值。截图是浏览器实际渲染结果，指标由取证脚本在页面稳定后读取 DOM 得出。原始数据见 `03-测试验证/01-测试文档/02-取证数据.json`，逐行明细见 `02-取证数据-实测表.md`。

## 取证方法与环境

取证方法与环境：用 **Playwright 自带的 Chromium** 驱动真实浏览器，绕开底座图形验证码，登录三种角色后逐页渲染取证。

### 2.1 为什么不用无头 Edge

本机 `msedge` 常驻进程会接管 `--headless=new --dump-dom` 与截图，实测 **stdout 0 字节、`$LASTEXITCODE` 为空**，截图与 DOM 全部不可信。Playwright 的 `chromium-1223` 是**独立实例**，完全不受常驻实例影响，且额外提供三项本轮刚需：

| 能力 | 无头 Edge | Playwright Chromium |
|---|---|---|
| 精确视口 | `--window-size` 不是 CSS 视口宽（Windows 最小窗宽，390 ⇒ `innerWidth=492`） | `viewport={'width':390}` 精确生效 |
| 真实滚动 | 无头不滚动 | `window.scrollTo` / `mouse.wheel` 真实滚动 |
| CSS transition | 不推进（`.show` 的 `opacity` 恒为 0） | 正常推进（`opacity` 能读到 1） |

### 2.2 登录怎么过：改写请求体，不 OCR、不改配置

底座登录带图形验证码（`Firewall.enableLoginCaptcha` 默认 `true`）。本轮**不 OCR 图片、不改任何生产配置**，走 Redis：

1. 自造一个 `checkKey`，调 `GET /sys/randomImage/{myKey}` 让后端把验证码写进 Redis；
2. Redis key = `md5(checkKey + signatureSecret) + lowerCase(code)`，**value 就是验证码本身**（注意 value 是 JSON 序列化的，**带引号**，要 `.strip('"')`）；
3. 用 `page.route()` 拦下 `/sys/login` 的请求体，把 `captcha` / `checkKey` 换成自己那一对，再点真实的「登 录」按钮。

这样验证码与「页面上显示哪张图」**彻底解耦**——登录页挂载与失败重试都会刷新验证码图，按「最后一次 randomImage 请求」解码会与显示的图**错配**，那是本轮踩过的第一个坑。

三条登录链路全部实测通过：`admin` / `123456`、`study_parent_demo` / `study@2026`、孩子端家庭码 `STU026` → 小星 → PIN `1234`。

## 取证发现的缺陷

取证发现的缺陷：4 个，**2 个 P0 级**、1 个竞态类、1 个环境类。全部已修复并复验。

### 4.1 D-1 vite 路由 glob 陈旧（环境类）

| 项 | 内容 |
|---|---|
| 现象 | 新增的 8 个 `.vue` 页面打开后显示 JeecgBoot 的「查看组件引用是否正确」空态 |
| 根因 | `src/utils/dynamicPages.ts` 的 `import.meta.glob` 在 **dev server 启动时**静态展开并缓存；此后新增的 `.vue` **不会**进入缓存 → 路由组件解析失败 |
| 影响 | 8 个新页面**全部**打不开（一度误判为代码问题） |
| 处置 | 重启 vite dev server（必须用 Python `subprocess.Popen` 拉起，`Start-Process` + `RedirectStandardOutput` 会卡死且中文路径被打乱） |
| 复验 | 重启后 8 个 component 全部 FOUND，42 个页面态全部正常 |
| 沉淀 | **新增 `.vue` 页面后必须重启 dev server**——这是 vite 的机制，不是本项目的约定 |

### 4.2 D-2 菜单树 `is_leaf` 导致两个 `:code` 页 404（P0）

| 项 | 内容 |
|---|---|
| 现象 | `/study/manage/coordinate/KPT-MA-000001` 与 `.../history` 打开是 404 插画 |
| 根因 | `SysPermissionController#getPermissionJsonArray`（`SysPermissionController.java:735` 与 `:759`）**只有 `!permission.isLeaf()` 才递归进子节点**。父菜单 `is_leaf=1` 时，其子菜单被**静默丢弃**——**无 4xx、无 console error**，页面只有一张 404 插画 |
| 对照 | 家长端「关联管理」正常，因为它挂在 `st_menu_parent`（`is_leaf=0`）**平级**下；第一版种子把两个 `:code` 菜单挂在「坐标树」下，而「坐标树」同时被写成 `is_leaf=1` |
| 处置 ① | 两个 `:code` 菜单的 `parent_id` 从 `st_menu_manage_coordinate` 改到 `st_menu_manage`（与「关联管理」已跑通的写法一致） |
| 处置 ② | `ON DUPLICATE KEY UPDATE` 增补 `parent_id` / `is_leaf` **回写**（原来不写，重跑脚本也救不回来） |
| 处置 ③ | 种子脚本新增 §5 **菜单树形状自愈**：`UPDATE sys_permission p SET p.is_leaf = (SELECT CASE WHEN COUNT(*) = 0 THEN 1 ELSE 0 END ...)`，按实际子节点重算 `st_menu_%` 的 `is_leaf` |
| 处置 ④ | 脚本末尾新增 §6 说明段落，写清 `is_leaf` 规则与两条修法（改父节点 / 改挂载层级）的取舍 |
| 复验 | 脚本连跑两遍 `exit=0`（幂等）；DB 核对 9 个子菜单 `is_leaf` 全部为 0；A03 / A04 正常渲染 |

**为什么这是 P0**：它不是「某个页面坏了」，而是**整棵子树静默消失**。接口返回 200、控制台干净、菜单树 JSON 里 children 齐全——只有真正渲染出来才知道少了一支。

### 4.3 D-3 管理端列表整列空白（P0）

| 项 | 内容 |
|---|---|
| 现象 | A04 / A05 / A06 / A07 / A08 五个列表页**所有数据列渲染为空**，只有操作列的「查看」链接有内容 |
| 根因 | antd 表格按 `record[dataIndex]` 取值；底座 `useColumns` 只处理 `key → dataIndex` 的**显示名**，**不会**把 `key` 当取值字段。薄配置页只写 `{key,title,width}` ⇒ 每格都是 `record[undefined]` |
| 连带 | 操作列**重复两列**：`tableColumns` 手工注入 `{key:'action'}` + BasicTable 的 `actionColumn` 又 push 一列——`handleActionColumn` 只按 `flag === ACTION_COLUMN_FLAG` 去重，手工注入的那列不带 flag，拦不住 |
| 伴生 | A04「考点版本历史」凭空多出一个「展开行」按钮：考点 VO 带 `children`，antd 以为这行可展开，而历史版本是**平铺**的、没有子节点可言 |
| 处置 ① | `ManageContentPage.vue` 的 `tableColumns` 改为 `list.map(item => ({ ...item, dataIndex: item.dataIndex || item.key }))` |
| 处置 ② | 删除原先手工注入的 `{key:'action'}`，操作列**只**由 BasicTable 的 `actionColumn` 提供一处 |
| 处置 ③ | `:show-action-column="true"` → `:show-action-column="hasActionColumn"`，`hasActionColumn = computed(() => Boolean(props.detailBuilder))`——只读页不再留一列空操作 |
| 处置 ④ | `coordinate/history.vue` 的 `loader` 映射 `children: undefined`，去掉「展开行」按钮 |
| 复验 | A04/A05/A06/A07/A08 的**数据格空白数 = 0**（详见 §9）；`expandIcon = 0` |

**复验时的一个判据**：antd 表格有一行**隐藏的测量行**（`ant-table-measure-row`），它按列数贡献等量空单元格。所以「空白数 = 列数」是**正常的**，不是缺陷；真正的判据是**数据行的空白格是否非零**。本轮 A04 的 3 个空格是 DB 里 `question_type` / `score_weight` / `invalid_at` **本来就为 NULL**（已用接口原始响应交叉核对）。

### 4.4 D-4 表格有数据却挂着错误提示（竞态类）

| 项 | 内容 |
|---|---|
| 现象 | 「母题维护」页表格有 4 条数据，**下方挂着一行「请指定要访问的孩子」** |
| 根因 | `ManageContentPage` 的 `onMounted(reload)` **先于**页面自己的 `onMounted`（取孩子下拉）执行 ⇒ 发出一次必然 4010 的请求；该请求的 `catch` **晚于**第二次成功请求落地，而 `errorText` 在成功路径上**没被清** ⇒ 数据与错误提示并存 |
| 处置 ① | `mother/index.vue` 的 `loader` 在 `childId` 未就绪时直接 `return []`，**不发**必然 4010 的请求；等 `childId` 就位后 `refreshKey` 变化会触发内核重载 |
| 处置 ② | `ManageContentPage.reload()` 引入 `reloadSeq` **序号守卫**（过期响应不得写状态），成功路径补 `errorText.value = ''` |
| 复验 | 42 个页面态的 `errHits` **全部为 0** |

## 新增可执行断言

新增可执行断言：7 条，把「下次不会再犯」从口头约定变成**会红的测试**。

### 5.1 管理端列表内核不变量（4 条 · 静态）

落在 `StudyUiSpecAssertionTest`（`ui/` 包），扫 `src/views/study/manage/**`：

| 断言 | 卡住的事 | 判据 |
|---|---|---|
| `manageListKernelMustSupplyDataIndex` | D-3 不复发 | 内核必须含 `dataIndex: item.dataIndex \|\| item.key` |
| `manageListMustNotDuplicateActionColumn` | 双操作列 / 空操作列 | `tableColumns` 计算体内不得出现 `action`；`show-action-column` 必须绑 `hasActionColumn` |
| `manageThinPagesColumnsMustCarryKey` | 薄配置页漏写 `key` | 每个 `{...}` 列定义必须含 `key:` |

### 5.2 菜单树形状不变量（3 条 · DB 支撑）

| 断言 | 卡住的事 | 判据 |

### 11.2 本轮新沉淀的坑

1. **vite `import.meta.glob` 在 dev server 启动时展开并缓存** —— 新增 `.vue` 页面后**必须重启 dev server**，否则路由组件解析失败，页面显示「查看组件引用是否正确」。这不是本项目的约定，是 vite 的机制。
2. **`is_leaf=1` 会让后端静默剪掉整棵子树** —— `getPermissionJsonArray` 只在 `!permission.isLeaf()` 时递归。父菜单 `is_leaf=1` 时子菜单**无 4xx、无 console error** 地消失，页面只剩一张 404 插画。**「有子菜单」必须 `is_leaf=0`；`is_leaf=0` 也用于「只有按钮」的菜单**，所以不能简单按「无子菜单就置 1」重算——只按**子菜单**（`menu_type IN (0,1)`）重算。
3. **antd 表格按 `record[dataIndex]` 取值，底座 `useColumns` 不会把 `key` 映射成 `dataIndex`** —— 只写 `{key,title}` 的列配置会让整列渲染成空。另：`handleActionColumn` 只按 `flag === ACTION_COLUMN_FLAG` 去重，手工注入的 `{key:'action'}` **拦不住**，会出现两列操作列。
4. **antd 表格有一行隐藏测量行** —— 统计「空白单元格」时必须把它的贡献（= 列数）扣掉，否则会把正常页面误判成「整列空白」。
