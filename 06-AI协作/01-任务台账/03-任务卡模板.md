# 任务卡模板

> 复制本模板填写，放进 `01-需求迭代/04-任务拆分/`。
> 任务卡是 **AI 的输入单元**：一张卡 = 一次可交付的 AI 任务。
> 一张卡只做一件事；跨卡的工作要拆开，否则 AI 会顺手做超范围的事。

---

## 任务卡 `T-{阶段}-{序号}` {任务名称}

| 字段 | 值 |
|---|---|
| 任务号 | `T-V0-XX` |
| 所属阶段 | V0 地基 / V1 习惯 / V2 主战场 / V3 拓展 / V4 沉淀 / 运维 |
| 需求编号 | `F-XXX-NN`（可多个）· 红线 `R-0X`（如涉及） |
| 优先级 | P0 / P1 / P2（对应 PRD §4.2） |
| 状态 | ⬜ 未开始 / 🟡 进行中 / 🔵 待验证 / ✅ 完成 / ⛔ 阻塞 |
| 产出物 | 具体到文件或接口路径，不写「实现 XX 功能」 |
| 依赖 | 前置任务号 |
| 预估 | 半天 / 1 天 / 2–3 天 |

### 1 目标

一句话说清**做完之后系统多了什么能力**。不是描述过程，是描述结果。

### 2 范围

| 含 | 不含 |
|---|---|
| 明确列出要做的事 | 明确列出**不做**的事（AI 最爱越界，这里要写死） |

### 3 落点

| 类型 | 位置 |
|---|---|
| 后端 | `org.jeecg.modules.study.{域}.{controller\|service\|entity\|mapper}` |
| 前端 | `src/views/study/{kid\|parent\|shared}/` · `src/components/study/` |
| 数据库 | `02-代码开发/02-数据库/03-脚本/`（DDL 真源） |
| 接口 | `GET /api/v1/study/{资源}` |
| 测试 | `03-测试验证/04-自动化测试/` |

### 4 输入契约

- 依赖的既有接口 / 表 / 组件（给准确名称）
- 参考实现：**照抄对象**（如「参照 `MonitorAlarmModelController.list()`」）

### 5 验收判据

必须是**可判定**的，不能写「正常显示」「运行正常」。

| # | 判据 | 验证方式 |
|---|---|---|
| 1 | | 手工 / 单测 / 脚本 / 浏览器断言 |

> 红线相关任务必须至少有一条断言式判据，且能对应到 `03-测试验证/04-自动化测试/01-红线断言规格.md` 的编号。

### 6 红线检查

| 红线 | 本任务是否触及 | 具体落点 |
|---|---|---|
| R-01 反搜题 | 是 / 否 | |
| R-02 AI 只做解释层 | 是 / 否 | |
| R-03 护眼硬指标 | 是 / 否 | |
| R-04 不做公开比较 | 是 / 否 | |

### 7 自检

交付前跑完 `06-AI协作/05-产出自检/01-产出自检清单.md`，在此勾选：

- [ ] 静态校验 `2026103013-交付物校验.py` 退出码 0
- [ ] 红线门禁 `2026103016-红线断言检查.py` 退出码 0
- [ ] 追溯矩阵已重跑，本任务涉及的接口数与用例数已更新
- [ ] 产出物已写入台账，状态已更新
- [ ] 未触碰范围外目录、未手改已生成的 HTML

### 8 备注

踩坑、偏离、需要人工确认的地方。**偏离设计文档的地方必须写在这里**，不能默默做。
